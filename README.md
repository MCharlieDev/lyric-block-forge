> 一个给歌词创作者用的离线 LRC 编辑器：把歌词当成时间轴上的**块**来拖，而不是表格里的**行**来填。

Lyric Block Forge（工程内名 `lrc-editor`）面向真正要打轴的人：看得见波形、拖得动歌词块、改得了字级切分、退得回任何一步，而且所有数据都留在自己的机器上。

🌐 **在线体验**：<https://mcharliedev.github.io/lyric-block-forge/>

> 构建产物与 `gh-pages` 分支已就绪。首次访问若返回 404，请在仓库 **Settings → Pages → Source** 选择 `gh-pages` 分支。建议使用桌面端 Chrome / Edge，移动端布局仍在开发中。

## 为什么做这个项目

大多数 LRC 编辑器只提供一种改时间的方式：在输入框里敲时间戳。可创作者面对的是一段声音，不是一串数字。

这个项目的初衷只有一句话：**给创作者最大的方便和权限，但不替创作者做表达决定。**

- 想对齐某一句？直接拖那个块，眼睛盯着波形。
- 想微调某个字？放大到字级，拖那个字卡。
- 改错了？日志里每一条都在，可以按条撤销，也可以按类型整批回退。
- 工具发现格式有坑？它自己填平，不拿确认框骚扰你。

它刻意不做"傻瓜编辑器"：不自动猜你想怎么切分，不偷偷改你的时间戳，不在波形上盖满标记。

## 六条准则

**1. 创作者管意图，工具管合法性**
畸形标签、编码残留、重复元数据、错位时间戳——这些是格式的坑，静默归一化。歌词文本、时间值、切分方式、换行与空行——这些是表达，动之前必须问。

**2. 无损的对象是意图，不是字节**
重复标签、元数据原始顺序、空行位置、双语分隔符、原始换行符与 BOM，只要承载了创作者的选择就保留；纯机器产物和缺陷不为其保存特性。

**3. 日志是唯一真源**
每一次时间修改都写入带类型的操作日志。当前时间 = 基线按顺序回放所有生效记录。撤销不删记录，只翻转状态；因此历史永远可见、可恢复。

**4. 重大改变必须确认**
多选整组位移、清空行级时间、改正文导致字级作废——默认弹窗，说清后果。确认形态可配置为「仅 toast」，也可以直接在弹窗里勾掉「以后用 toast 提示」。

**5. 离线优先**
没有账号、没有服务端、没有同步、没有遥测。设置存本地，文件进文件，音频不出浏览器。

**6. 连续输入跟手，离散输入平滑**
拖动、按住、擦洗不补动画，指针在哪就是哪；滚轮、翻页这类离散输入才做平滑。这是手感问题，不是性能妥协。

## 它和别的 LRC 编辑器不一样在哪

### 歌词块是一等公民

放大态下，一行歌词会被拆成按时间锚定的**字卡（chip）**：每个字有自己的横向位置、自己的可拖动区域、自己的时间。重叠的字卡不会糊成一团，而是按阶梯错开、组内倒序绘制，保证最早那张永远可点。整行的宽度由内容宽与到下一行的时间间隙共同决定，压缩时自动提示重叠。

这意味着你不只是在"填时间"，而是在一条共享毫秒坐标系的轨道上**摆放声音的切片**。

### 类型化操作日志，而不是普通 undo 栈

`manual-timestamp`、`selection-offset`、`global-offset`、`word-timestamp`、`word-segments`、`remove-line`、`clear-timestamps`…… 每种操作都有自己的类型、范围与变化量。

于是可以做到普通编辑器做不到的事：**只撤销"所有整体偏移"，保留手动打轴成果**；也可以展开某条已撤销记录，把它单独恢复。日志面板就是这份文档的工作日志，随文档存在。

### 行首拖动是"推土机"

拖动一行开头的 4px 热区，行首时间会推到新位置，**被新行首越过的字卡会被一起推平**（时间塌缩到新行首），一条日志整笔撤销。这不是"只改行级、字级不管"的半吊子实现，而是承认行级与字级本来就有从属关系。

### 切分是显式动作，可以预览、可以作废

字级切分不靠猜：打开切分弹窗，在字符缝隙上点出切缝，得到草案；草案里每块时间可单独编辑；正文一改，草案自动标记作废并灰显留痕，保存时不会悄悄写进去。切分本身是一条 `word-segments` 日志，撤销即整笔回滚。

### 确认粒度可配置

同一个"重大改变"，有人希望每次都拦一下，有人希望只留一条提示。两个确认项都能在设置面板切换，也能在弹窗底部直接勾掉；两种入口读写同一字段，不存在两套状态。

### 有自动化验收的编辑器

仓库自带一套基于 Chrome DevTools Protocol 的 headless harness：假时钟、真实静音 WAV、按组断言真实 DOM 与 store 状态，跑完自动回收进程。当前 **510 条断言全绿**，另有 **207 条 vitest** 覆盖核心纯函数。

## 功能一览

### 导入

- 标准 LRC、增强型 LRC（字级标签）、纯文本（每行一条未打轴歌词）
- 文件、剪贴板、手动输入三条入口，共用同一条解析管道
- 双语歌词自动识别，分隔符可配置（换行、斜杠、竖线、自定义符号）
- 元数据前缀识别：`作词：` / `作曲：` / `演唱：` 等，规则表可增删改，三种模式（关闭 / 转元数据 / 转元数据并保留歌词行）
- 重复标签、未知标签、元数据顺序、空行、换行符、BOM 尽量原样保留
- 字级时间早于行级的错位自动单向拉齐，静默修复

### 打轴与编辑

- 空格打轴、方向键 ±10ms 微调、行级时间数值输入（`125` = 125 秒）
- 行文本、翻译、罗马音、行注释编辑
- 字级时间逐项输入；字级切分弹窗（码元偏移切缝、每块时间可改）
- 清空行级时间（保留切分槽位，显示为未打轴）
- 删除行、上移 / 下移（交换文本，时间留在原位）
- 多选：`Ctrl/Cmd+Enter` 开关选中、`Shift+↑/↓` 范围选、`Esc` 清空选区

### 时间轴与波形

- 波形 / 刻度尺 / 分析轨 / 歌词轨四层共享同一毫秒坐标系，播放头是独立贯穿层
- `Ctrl/Cmd + 滚轮` 以指针为锚点缩放，普通滚轮横向平移
- 播放中视口跟随；手动平移后可选择「自动拉回」或「暂停跟随 + 归位按钮」
- 屏外播放头箭头提示，拖到视口边缘自动滚
- 吸附到播放头、其他行时间、网格线，命中时显示对齐辅助线
- 音频时钟是播放的唯一基准，播放头拖动中每帧写 store，松手才 seek

### 拖动

- 单块拖动、多选整组等量位移
- 字级字卡拖动（只动那个字）
- 行首 4px 热区拖动（推土机推平被越过的字卡）
- 拖动过程零 store 写入、松手落一条日志
- 重大改变提交前弹窗确认（可关闭）

### 日志与回退

- 工作日志面板：总 / 修改 / 报错 / 已归档 / 忽略（报错与忽略为后续校验层预留）
- 按条撤销、按条恢复、勾选多条批量撤销、按类型整批撤销
- 已撤销记录灰显留痕，生命周期（创建 / 撤销 / 恢复）完整可查
- 每条记录带范围、变化量、描述与来源版本

### 导出

- 导出为 LRC / 增强型 LRC，只写当前可见行
- 精度统一在导出层：两位（`mm:ss.xx`）或三位（`mm:ss.xxx`），默认三位
- 删除的行不写、拖动与偏移反映为最终时间、未知标签原样写回

### 设置与快捷键

- 可搜索的设置面板，修改即时持久化到本地
- 时间戳精度、吸附四项、跟随恢复方式、平移 / 移动播放头时是否暂停音频、确认形态、元数据前缀规则、遮罩点击关闭等

**默认快捷键**

| 键 | 行为 |
| --- | --- |
| `Space` | 给当前行打轴 |
| `E` | 播放 / 暂停 |
| `↑` / `↓` | 移动光标到相邻可见行（重置为单选） |
| `Ctrl/Cmd + ↑ / ↓` | 移动光标，保留选区 |
| `Shift + ↑ / ↓` | 从锚点范围选到新行 |
| `Ctrl/Cmd + Enter` | 光标行加入 / 移出选区 |
| `Esc` | 清空选区，光标不动 |
| `←` / `→` | 当前行时间 ∓10ms |
| `Delete` / `Backspace` | 删除选中行 |

## 技术架构

```
core        纯 TypeScript 领域层：文档模型、解析 / 序列化、操作日志与回放、时间与切分纯函数
adapters    平台端口与 Web 实现：File / Audio / Storage / Clipboard / Share / Notification / Haptics / Waveform
ui          React 表现层：时间轴、歌词块、日志面板、弹窗、设置
shells      Web / 桌面 / 移动外壳（当前仅 Web 壳可用）
```

- 文档状态、播放状态、编辑器状态三者分离
- **所有时间统一为毫秒整数**，只在展示层格式化
- 任何文档修改都经由操作日志，不直接改写字段
- 解析 / 序列化尽量无损；无法识别的内容原样保留
- 音频时钟是播放唯一基准；暂停时读 store，播放时读端口
- 视口宽度以画布测量为唯一真源，缩放与滚动共享一个内核

详细设计见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)；每轮实现细节见 [docs/rounds/](docs/rounds/)，交接断点见 [docs/交接文档.md](docs/交接文档.md)。

## 快速开始

环境：Node.js 18+，npm。浏览器建议 Chrome / Edge（依赖 Web Audio、Canvas 与 Pointer Events）。

```bash
npm install
npm run dev        # http://localhost:5177
```

常用命令：

```bash
npm run build      # tsc -b && vite build
npm run typecheck  # tsc -b --noEmit
npm test           # vitest run
npm run harness    # 启动 vite + headless Chrome，跑完整 UI 断言（需要本机安装 Chrome）
npm run deploy     # 构建并发布到 gh-pages 分支（GitHub Pages）
```

GitHub Pages 部署：`npm run deploy` 会把 `dist/` 推到 `gh-pages` 分支；随后在仓库 **Settings → Pages** 把 Source 设为 **Deploy from a branch → `gh-pages` / `root`** 即可。生产构建自动使用子路径 `/lyric-block-forge/`，开发与 harness 仍走站点根路径。

`npm run harness -- AX` 只跑指定断言组；`npm run harness:keep` 保留进程，便于手工连 CDP 调试。端口可用 `LRC_DEV_PORT` / `LRC_CDP_PORT` 覆盖。
