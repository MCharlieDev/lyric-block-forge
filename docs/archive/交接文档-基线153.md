## 0. 交接必读（新 AI 先看这段）

**你是谁**：你是决策者，不是执行者。Trae 写代码，你判它给出的结果，用户提修改并确认。

**三条最容易犯的错**：

1. **别把"讨论过但还没发"当成漏了。** 用户习惯把讨论出来的东西攒着，下一轮或几轮后才发。你看到的交付里没有，不等于它被忘了——去 §5 在途清单里看。
2. **别用"外部评审腔"。** 不说"问题一严重、问题二中等"。你的位置是**拥有这份工作的人**——把该拍的裁决点摆出来，自己选一条，往下走。
3. **别用推断省显式判断。** 用户要"明确 > 推测"。哪怕推断今天成立，也要显式写条件，因为隐式不变量会随时间漂移。

## 1. 项目定位与核心原则

- **LRC 歌词文件编辑器**，核心定位：**辅助创作者**，不是傻瓜编辑器。给创作者最大方便和权限。
- 用户原话：「频率微调当然是需要用户点按钮才能识别微调，我们做的这个不是一个傻瓜歌词编辑器。是要尽可能的方便创作者去实现的，就是给创作者最大的方便以及权限。」
- 「**每一个重大改变都是需要弹窗提示。撤销的记录保留可见可以回复。**」
- 平台：Web（PWA）→ Windows exe（Tauri 2）→ Android/iOS（Capacitor）。离线程序，无账号、无服务端、无同步。
- 完整架构见 `ARCHITECTURE.md`（产品原则）、`docs/rounds/多选拖动-第一批.md`（历史任务书）。

## 2. 工作方式（硬规则）

### 2.1 双闸门流程

**每轮拆 A/B 两段：**

| 段           | 内容                      | 谁做                                              |
| :---------- | :---------------------- | :---------------------------------------------- |
| **A 段（方案）** | 任务书 + 核实请求，**只出方案不写代码** | 用户发 Trae → Trae 出方案 → 用户发 AI → **AI 判 + 给修改指令** |
| **B 段（执行）** | 「方案已确认，按此执行」+ 修改指令      | 用户发 Trae → Trae 改代码 + 四段交付 → 用户发 AI → **AI 判**  |

**A 段没走完，B 段不发出。** 这条由用户把住。

> ⚠️ **历史偏差**：第三轮（选择层去类型化）确认闸被跳过（Trae 从方案直跑到执行）。已接受，不追责，下轮起硬拆。

### 2.2 交付格式（Trae 每轮必交）

```
1. 已验证：
2. 未验证：
3. 已知取舍：
4. 否决的备选方案：
```

### 2.3 触发词

- **「题外话」** = 脱离项目。AI 只给意见、判断、想法，**不产出项目物料**（不写提示词、不出方案、不列文件清单、不做验收设计、不维护待发清单）。
- 退出无触发词——用户说一句带项目内容的话即切回。

### 2.4 检查点提醒

**每个大部分闭合、AI 判过之后，AI 提醒用户更新交接文档。** 触发点：一批代码验完 / 一个长期挂账结清 / 一个阶段收口。提醒固定句式：

> 🔔 检查点：这一批闭合了。建议更新交接文档——状态 / 在途 / 规则 / 校准，重点补"已讨论未发送"那栏。

**诚实边界**：这个承诺本身可能失效——AI 静默失忆时不会提醒。所以它只是辅助，用户"顺手存"才是真保险。

## 3. 校准（AI 的判断原则，最值钱的一栏）

这些是"读得懂状态但判断力退化"时缺的东西：

- **明确 > 推测。** 宁可多写一个显式条件，不靠推断省判断。
- **同口径 = 一个概念全项目只有一个定义。** 不是"两处写得像"，是"三处调同一个函数"。举例：`lineIsMovable` 被拖动入口 / 微调入口 / `moveLinesByOffset` 内层共用。
- **保底要留，但留成"一个函数"，别留成"两处各写一遍"。** 双层防御：入口层判定（用户可感知的拒绝）+ 内层层过滤（数据安全最后一道）。
- **别让隐式不变量裸奔，给它一道明写的锁。** 用推断覆盖的地方，加断言守着。
- **拒绝 ≠ 静默：**
  - **拒绝** = 用户想干一件有落差的事、被挡住 → 需要提示。
  - **静默** = 用户想干的事本身没意义 → 不解释。
- **流利会盖住空缺。** 早期"什么都懂"有一部分只是语气确定，不是真有知识。所以现在加了核实步——**不是流程变重，是信任结构变了：用户不能再只凭语气信 AI。**
- **讨论 ≠ 发送。** 见 §0 第 1 条。

## 6. 最近闭合：导出链修复 + 精度统一（第 7 批）

### 6.1 修了什么

**病灶**：编辑（打轴/微调/拖动/偏移/字级）只写 `log` + `replay`；导出只读 `document.lines[].timestamps`；中间**没有桥**。`deriveVisibleLines` 只透传 document 的时间戳，不读 replay。

**后果**：所有时间戳编辑**不进导出**——导出永远是导入时的原值。demo 就是最直接例子：基线里 `timestamps` 全空（时间全在日志），直接导出**一个时间标签都没有**。

**修法**：新增 `buildExportText(document, replay, uniformPrecisionMs)`（在 `editorStore.ts`），把 replay 的行级/字级时间戳合并进可见行再序列化。**App 与验收 harness 共用同一函数**（防"测试自拼"测不出真实链路）。

### 6.2 精度语义（关键决策）

- **导出时所有行级/字级时间戳统一用一个精度**，不再逐条读 `precisionMs`。
- 精度值来自设置，可选两位（`mm:ss.xx`）/ 三位（`mm:ss.xxx`），**默认三位**（与 `createTimestamp` 默认 `precisionMs=1` 一致）。
- **导入识别精度只服务"解析容错"**（源文本格式五花八门，要能读进来），**不影响导出**。
- **`[length:]`** **元数据标签不纳入统一精度**，维持原逻辑。

## 7. 技术事实速查（核实过的，别凭记忆）

### 7.1 时间戳 / 精度链

- **回放层**：`ReplayState.lineTimestamps: Record<string, number[]>`（**只有数字，无精度**）；字级 `wordTimestamps: Record<string, number>`，键 `lineId#wordIndex`。
- **精度**：只在 `Timestamp.precisionMs`（逐条）。**回放建基线时丢弃**——`buildBaselineFromDocument` 只取 `item.timeMs`。
- **`LyricFormatInfo`**（`document.format`）：只存 `encoding / detectedFormat / lineEnding / hasBOM / unknownTags / bilingualSeparator`，**不含时间戳精度**。
- **`formatTimestamp(timeMs, precisionMs)`** 是毫秒 → LRC 字符串的唯一导出边界；调用点仅 3 处：行级、字级、`[length:]`。

### 7.2 操作日志模型

- **`OperationKind`**（12 个）：`manual-timestamp / global-offset / selection-offset / manual-nudge / word-timestamp / frequency-nudge / vocal-boundary-edit / text-edit / swap-line-text / remove-line / metadata-edit / import`。
- **`OperationDelta`**（5 个 mode）：`offset / absolute / none / line-text / remove-line`。
- **⚠️ 没有"把行变回未打轴"的操作。** 唯一删 `lineTimestamps` 的地方是 `remove-line`（删整行）。这是 §5.3 行级时间戳输入的核心障碍。

### 7.3 导入解析

- `parseLrc`；`LINE_TAG_PATTERN` 支持 `[mm:ss]` / `[mm:ss.x]` / `[mm:ss.xx]` / `[mm:ss.xxx]`，分隔符 `.` 或 `:`，**分号不支持**。
- **无通用的"字符串 → 毫秒"公开解析函数**（`parseTimeParts` 私有、入参是正则命中结果）。

### 7.4 关键判据

- 「是否已打轴」= `getReplayedLineTimes(replay, id).length > 0`。
- 「可平移」= `lineIsMovable(replay, id)` = 未删 && 已打轴（**三处共用**）。
- 「无选中」= `{ lineIds: [], activeLineId: null, anchorLineId: null }`（三字段全清）。

## 10. 关键决策记录（易忘）

- **锚点回归本义**：只作范围选起点，不决定集合类型（去类型化后）
- **无选中是合法状态**：三字段全清
- **撤销后选中不恢复**：`reconcile` 只清不设
- **拖动中不写 store**：位置由日志重放结果决定；命令式 transform，松手才写一条日志
- **未打轴行不可参与 offset 拖动**；单块未打轴走打轴路径
- **混合集合（含未打轴）**：拖动拒绝（not-allowed），微调拒绝（纯静默）
- **多选删除（Delete/Backspace）**：落点 = 直接无选中（不挑最近剩余）
- **单行按钮删除**：走 `removeLine`，active 落最近剩余
- **导航（方向键）与执行（空格）分开**：导航给默认起点，执行必须有目标
- **`set()`** **只写要改的字段，不做全量重置**
- **精度统一只在导出层**，默认三位
- **导入精度只为解析容错**
