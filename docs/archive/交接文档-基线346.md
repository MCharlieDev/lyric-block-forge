## 0. 交接必读

**你的位置**：你是决策者，不是执行者。Trae 写代码，你判它的结果，用户提修改并确认。

**三条最容易犯的错**：

1. **别把"讨论过但还没发"当成漏了。** 用户习惯把讨论结果攒着、几轮后才发。交付里没有 ≠ 被忘了。去 §5 在途清单看。
2. **别用外部评审腔。** 不说"问题一严重、问题二中等"。你的位置是**拥有这份工作的人**——摆出裁决点、自己选一条、往下走。
3. **别用推断省显式判断。** 用户要"明确 > 推测"。哪怕推断今天成立，也要显式写条件——隐式不变量会漂移。

## 1. 工作方式（硬规则）

### 1.1 双闸门

| 段           | 内容                      | 谁做                                              |
| :---------- | :---------------------- | :---------------------------------------------- |
| **A 段（方案）** | 任务书 + 核实请求，**只出方案不写代码** | 用户发 Trae → Trae 出方案 → 用户发 AI → **AI 判 + 给修改指令** |
| **B 段（执行）** | 「方案已确认，按此执行」+ 修改指令      | 用户发 Trae → Trae 改代码 + 四段交付 → 用户发 AI → **AI 判**  |

**A 段没走完，B 段不发出。**

### 1.2 交付格式（逐字，不得改写、不得省略）

```
1. 已验证：
2. 未验证：
3. 已知取舍：
4. 否决的备选方案：
```

### 1.3 其他规则

- **「题外话」= 脱离项目**。AI 只给意见，**不产出物料**（不写提示词/方案/清单）。说一句带项目内容的话即切回。
- **检查点提醒**：每个大部分闭合、AI 判过之后，提醒用户更新本文档（状态/在途/规则/校准，重点补"已讨论未发送"）。
- **弹窗 / toast 一律自研**，禁 `window.confirm` / `alert` / `<dialog>`。
- **讨论 ≠ 发送**。见 §0 第 1 条。
- **核实报告贴全**（判断依据），**执行报告可截**（省钱）。

## 2. 校准（判断原则，最值钱的一栏）

- **明确 > 推测。** 宁可多写显式条件，不靠推断省判断。
- **同口径 = 一个概念全项目只有一个定义。** 不是"两处写得像"，是"三处调同一个函数"。
- **保底留成"一个函数"，不留成"两处各写一遍"。** 双层防御：入口层判定 + 内层层过滤。
- **别让隐式不变量裸奔，给它一道明写的锁。**
- **拒绝 ≠ 静默**：拒绝 = 用户想干的事有落差、被挡住 → 需要提示；静默 = 想干的事本身没意义 → 不解释。
- **流利会盖住空缺。** 语气确定 ≠ 真有知识。所以有核实步——不是流程变重，是信任结构变了。

## 7. 技术事实速查（已核实，别凭记忆）

**回放 / 时间戳**

- `ReplayState.lineTimestamps: Record<string, number[]>`（只有数字，无精度）
- `OperationDelta` 5 个 mode：`offset / absolute / none / line-text / remove-line / clear-timestamps`（后两个是历轮新增）
- 「是否已打轴」= `getReplayedLineTimes(replay, id).length > 0`
- 「可平移」= `lineIsMovable(replay, id)` = 未删 && 已打轴（**三处共用**：拖动入口 / 微调入口 / `moveLinesByOffset` 内层）
- 「无选中」= `{ lineIds: [], activeLineId: null, anchorLineId: null }`（三字段全清）

**清空语义（两种，含义相反）**

- 改文本 → 切分失效 → 连切分一起抹（`editLineText` 现有行为）
- 清空时间戳 → 文本没变 → **只清时间、保留切分**（`clear-timestamps` **不进** `clearedWordLines`）
- 文本变更优先

**导出**

- 唯一导出组装函数 = `buildExportText(document, replay, precisionMs)`，App 与 harness **共用**
- 命中 `clearedLineLines` → 输出纯文本（防复活）
- 精度统一只在导出层，默认三位

**跟随（本轮新增）**

- `FOLLOW_TRIGGER_RATIO = 0.8`、`FOLLOW_TARGET_RATIO = 0.2`、`FOLLOW_ANIMATION_MS = 160`
- 两状态：`followSuspended`（拖块用，无条件挂起）/ `followPaused`（B 模式用）
- `followPaused` 为真 → `followPlayhead` 直接 return（含"屏外直接跳"也不执行）
- 三项设置：`followResumeMode`(snap/pause, 默认 snap) / `pauseAudioOnPan`(默认 true) / `pauseAudioOnSeek`(默认 true)
- `setFollowPaused(true)` 只在**两个用户手势入口**（滚轮平移 / 滚动条拖拽），**不在** `panByPixels`/`applyView`

## 10. 关键决策记录（易忘）

- **锚点回归本义**：只作范围选起点，不决定集合类型
- **撤销后选中不恢复**：`reconcile` 只清不设
- **拖动中不写 store**：命令式 transform，松手才写一条日志
- **混合集合（含未打轴）**：拖动拒绝（not-allowed），微调拒绝（纯静默 → toast）
- **多选删除**：落点 = 直接无选中（不挑最近剩余）；单行按钮删除 = 挑最近剩余
- **精度统一只在导出层**，默认三位；导入精度只为解析容错
- **跟随的启停绑定"音频是否播放"**，不另设规则；唯一例外是拖块（挂起跟随但不停音频）
- **A/B 恢复模式**：A = 松手自动拉回；B = 不拉回（`followPaused`），归位按钮是唯一显式恢复
- **`set()`** **只写要改的字段**，不做全量重置
