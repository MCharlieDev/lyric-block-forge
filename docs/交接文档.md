## 0. 交接必读

你是决策者，不是执行者。Trae 写代码，你判结果，用户提修改并确认。
三条易错：① 「讨论过没发」不等于漏，去 §5 看；② 别用评审腔，摆裁决点自己选；③ 明确 > 推测。

## 1. 工作方式

- **双闸门**：A 段只出方案/核实不写码 → AI 判 → B 段执行 → AI 判。A 没走完 B 不发。
- **交付格式**（逐字）：1.已验证 / 2.未验证 / 3.已知取舍 / 4.否决的备选方案
- **拆轮线**：改 >4 文件 / 新增 >2 组测试 / 1 次压缩 → 拆；**重构+新增并存 → 必拆**。

## 2. 校准

明确 > 推测；同口径 = 一个概念全项目一个定义；别让隐式不变量裸奔；拒绝≠静默；
**离散输入（滚轮/翻页）才补平滑；连续输入（拖动/按住）不补，跟手即可**；
「改了没效果」先硬刷新（Ctrl+Shift+R）再下结论。
无损的对象是创作者意图，不是字节；缺陷/机器产物归一化掉，不为其保存特性。

- 红字原则适用设定（真红字 vs 测试缺陷的分界）见《LRC 编辑器项目 · 协作规程》§六。

## 3. 项目定位

LRC 歌词编辑器，辅助创作者（非傻瓜编辑器）；重大改变要弹窗；离线无服务端。
分层 core / adapters / ui / shells；时间统一毫秒整数；音频时钟是播放唯一基准。

## 6. 技术事实（速查）

**播放头**
- 收口两函数（editorCommands.ts）：resolvePlayheadMs（拖动中→会话值；有音频→端口；否则→store）/ seekPlayhead（setPlayhead + 有音频才 seek）。
- resolvePlayheadMs 门控：scrubMs 优先 → 「有音频 且 isPlaying」走端口 → 否则走 store。即「播放走端口（精确）、暂停走 store（可停在尾巴区）」。
- MIN_DURATION_MS = 5_000（原 30_000）。无音频启动实测 durationMs = 30920（demo 内容 25920 + 尾 5000）——不是 10000，也不是旧的 35000；10000 只在真正空文档（0 行 0 音频）成立。
- 拖动会话 = 模块级单例 scrubMs（非 store、非 React）。
- 留白已删；播放头屏幕位夹 [0, W]（可达时间 0 与末尾）。
- 统一拖拽：尺子任意处 = 抓播放头；TimeRuler 已无手势（canvas 退化纯渲染，保留 cursor-col-resize class 仅供 harness 定位）。
- PlayheadLayer 结构：不动外壳 + 全宽尺子带（top 0..RULER_HEIGHT_PX）+ 9px 竖条（RULER_HEIGHT_PX..LYRIC_TRACK_HEIGHT_PX）。
- 边缘自动滚 = 复用内核 startAutoPan/stopAutoPan（Scrollbar 同款）；触发带 EDGE_ZONE_PX=48，速度 ∝ 越界深度，上限 EDGE_PAN_MAX_SPEED_PX_PER_S=1500。
- 拖动中每帧写 store（handleFrame，门控 pointerIdRef，≤刷新率）；audio.seek 仅松手一次。
- useAudioPlayback 的 isScrubbing() 守卫保留。

**当前行（光标 / 选区）**
- **两个概念**：`activeLineId` = 光标（唯一真源）；`lineIds` = 选区（多选范围）；`anchorLineId` = 范围选锚点。三者同属 `selection`。
- **DOM 焦点跟随光标**：`LyricBlockPanel` 内一个 effect，`activeLineId` 变则把焦点移到对应行（`preventScroll: true`）；目标已是 `activeElement` 则早退（防自激）。
- **`setCursorOnly(lineId)`**（editorStore）：Tab 导航专用——`lineIds` 清空、`activeLineId` / `anchorLineId` 设为该行。与 `selectLine` 的区别：后者把选区替换为「新行单选」。
- **行 `onFocus` 双守卫**：① 光标已在本行则早退（挡焦点跟随 effect 的程序化聚焦）；② 仅 `:focus-visible` 为真（键盘来源）才走 `setCursorOnly`，鼠标点击聚焦交给 `onClick`（实测：鼠标 → `false`，Tab → `true`）。
- **行热区去掉默认 outline**，焦点视觉由 `isActive` / `inSelection` 承担，不再有第二个描边。
- **语义矩阵**：Tab → 挪光标 + 清空选中；↑↓ → 挪光标 + 单选重置；`Ctrl+↑/↓` → 挪光标 + 保选中；空格打轴 → 永远打光标行。完整键位见下「键盘多选（第二轮）」。

## 9. 关键决策（易忘）

- 撤销后选中不恢复；拖动中每帧写 store（读数实时）；audio.seek 仅松手（避免播放态每帧重建 source 节点）；多选删除落点=直接无选中。
- 精度统一只在导出层，默认三位。
- 播放头拖动：按住即接管；松手用 pointerup 坐标重算；顺序 seekPlayhead → endScrub。
- 音频「拖动播放头是否暂停」：维持现状，不再折腾（原待办的开关状态 / B或C 已取消）。
- viewportWidthPx 单一真源：canvas 宽度只认内核快照；测量归 effect（useLayoutEffect 里 attachViewport），不放 ref 回调——否则 React 18 StrictMode 双调用 effect 会 destroy 掉 RO 而 ref 不重挂，宽度永久冻结。
- durationMs 仍一个值担多角色（内容下限 / fit 分母 / 量程上限 / 播放头上限）；本轮只去掉 30s 下限，四角色合一未拆（contentMs/timelineMs 拆分方案已评估、未采纳）。
- 尾部保留 5s（DURATION_TAIL_MS），用途 = 末尾歌词块显示余量；时间轴范围允许大于内容。
- 光标（`activeLineId`）与选区（`lineIds`）**分离**；焦点跟随光标，光标是「当前行」的唯一真源。
- 键盘键位矩阵（第二轮闭合）：↑↓ = 挪光标 + 单选重置；`Ctrl+↑/↓` = 挪光标 + 保选区（anchor 跟新行）；`Ctrl+Enter` = 光标行加入/移出选区（可减到空、光标不动）；`Esc` = 清空选区（光标不动）；`Shift+↑/↓` = 从 anchor 范围选到新行（anchor 不动）；Tab = 挪光标 + 清空选中。
- 唯一不变量是**单向**的：`lineIds 非空 ⇒ activeLineId 非空`；反向不成立（Tab 后可出现 `lineIds = []` 且 `activeLineId ≠ null`）。
- 零尾巴断言（AO / AQ.B×2）改「落定后取样（250ms）+ 最终收敛硬断言」；容差维持 ±3。
- harness 已迁入仓库 `harness/`（B 段-1 入库、B 段-2 加 launch 壳）；冷启动靠「Chrome 启动即带 APP + prewarm 等整页静默」，不再依赖人工先开服务。
