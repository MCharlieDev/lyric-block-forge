### 行容器首边拖动（推土机逻辑）

**状态**：📌 已排期（见 交接文档 §11.1），待开始
**前置依赖**：放大态（word 模式）绝对定位排版已就绪（R3 已闭合）
**涉及范围**：`LyricTrack.tsx`、`LyricBlock.tsx`、`editorStore.ts`

#### 1. 痛点与目标
* **痛点**：放大态下，目前整块拖动会带着所有字卡一起平移。当用户只想调整“行首”的绝对时间，且希望字卡在屏幕上的绝对位置保持不动时（即拉伸/压缩行首空白），现有操作无法实现。
* **目标**：提供一种仅改变行首时间的交互，且字卡绝对位置固定。

#### 2. 适用范围
* **仅限放大态（word 模式）**。缩小态（行级模式）不需要此功能。

#### 3. 交互设计
* **热区**：在放大态行容器的左侧最边缘，增加一个宽度约 `6px` 的透明拖拽热区（Handle）。
* **光标**：悬停热区时，光标变为 `col-resize`（左右箭头）。
* **拖拽状态**：触发新的拖拽模式 `DragMode = 'line-start'`。
* **视觉**：拖拽中，行容器的左边缘跟随移动；因为字卡的时间戳没变，它们在屏幕上的绝对位置不动（利用现有的 `overflow-visible`，向左拖时字卡会溢出到容器左侧）。

#### 4. 底层逻辑（推土机算法）
* **向左拖动**：无限制，拉长行首空白。
* **向右拖动**：无限制。如果行首越过了任何字卡的时间戳，在松手落盘时，**将所有被越过（时间 < 新行首时间）的字卡时间强制拉齐到新的行首时间**（推平）。
* **落盘与撤销**：行级时间的改变与被推平字卡时间的改变，需打包成**一条** `absolute` 类型的 Operation 记录写入操作日志，确保撤销时一步还原。

#### 5. 备注
* 右下角 45° 三角形图示为无光图像，与本需求无关，忽略。

### 歌词列表换行优化（双重模式）

#### 1. 痛点与目标

- 打轴或文本录入时容易插错行（如本想插在 L2 前，手滑点成"在 L2 之后新增"），导致歌词物理顺序与预期不符。
- 希望直接在歌词列表上调整"谁是谁的下一句"的物理顺序。
- 用户明确：行 1 的时间晚于行 2 是合法状态，后续打轴依赖列表的物理顺序，不依赖时间单调。

#### 2. 两种模式（需可切换）

- **模式 A · 仅换文本（现状）**：`swapLineText` 只交换 `text / translation / romanization / comment`，行级时间留在原槽位，字级被 `clearWordTimestamps: true` 清空。适用于"两行都有时间戳，只想换唱词"。
- **模式 B · 整行物理互换（新）**：文本、行级时间戳、字级时间戳作为完整包裹一起换位。适用于新建行、打轴顺序错乱等场景。

#### 3. A 段核实的关键事实

- 日志模型没有"顺序"这一维：`delta` 只能表达值/位移/删除，`scope` 只有 lineIds/wordRefs/timeRange；回放按 `lineId` 覆盖字段，行顺序永远取 `document.lines`。
- 因此"整行重排"无法通过现有 Operation 表达，改 core 才能做成可撤销。
- 但存在既有先例：`appendBlankLine` 直接重建并替换 `document.lines` 基线数组，不进日志、不可撤销（交接文档口径：结构性变更进基线）。
- 因回放按 ID 覆盖，替换基线数组顺序不会使任何历史日志失效。

#### 4. 两个候选架构

- **B1 · 基线重排（零 core 改动）**：在 `editorStore` 新增 action，交换 `document.lines` 中两行的位置，整行对象（含字级）天然一起走。代价：不可撤销、日志面板无记录（与新建空行同规格）。预计 2 文件（无设置项）或 4 文件（含设置项）。
- **B3 · core 新增 Reorder 操作**：可撤销、进日志、语义最干净，但必须修改 `src/core` 的类型与回放，预计 4-6 文件。

#### 5. 切换入口候选

- A：全局设置开关（离操作现场远，且新增设置项可能撞 harness 依赖的 15 项断言）。
- B：行操作菜单（⋮）里给两组按钮（显式，但底排按钮 4→6，需扩图标枚举与类型）。
- C：默认按设置走 + `Alt` 点击反转（外显箭头不膨胀，可发现性差）。
- D：自动判定（任一行未打轴→整行，两行都有时间→仅文本）。与"可切换"的需求有冲突。

#### 6. 待拍板项

- 架构选 B1 还是 B3。
- 切换入口选 A / B / C / D 哪一个（或组合）。

#### 7. 风险与注意

- 新增设置项可能撞 harness「严格等于 15 项」断言，需先确认或改为嵌入已有设置项。
- 整行互换后 `activeLineId` 不变，列表滚动 effect 不会触发，需补"移动后保证可见"逻辑。
- React 在 key 不变、仅换位置时焦点是否稳定保留，需实测。
- 整行互换后列表可能时间倒序，`inferInitialTimeMs` 在"间隔 ≤ 0"时退化为与锚点同时间，不报错但新建行默认时间会变保守。
- 多时间戳行在 `absolute` 下逐条寻址能力未验证（与 B2 方案相关，B1 不受影响）。

- **抽屉绝对不能加 `role="dialog"` / `aria-modal="true"`**。`useEditorHotkeys` 的 `hasOpenDialog()` 判定为 `document.querySelector('[role="dialog"], [aria-modal="true"]') !== null`，命中即**整体 return**，10 个快捷键全部失效（Space 打轴、E 播放、↑↓、Ctrl+Enter、Esc、←→、Delete、Backspace）。

- 现有日志面板本就不带该属性，行为一致即零回归。

#### 4. 宽度代价（1280 视口实测推算）

| 形态 | 主区宽度 | 时间轴可视毫秒（ppms=0.02） |
|---|---|---|
| 现状展开日志 | 924 | 46.1s |
| 新方案·抽屉开（gap-2） | 880 | 43.9s |
| 新方案·抽屉关 | 1208 | 60.3s |

- `ppms` 不随宽度重算，变窄只是可视毫秒变少（−5%），不会自动 fit。
- 时间轴无最小宽度兜底、无原生横向滚动；880px 远大于歌词面板窄屏阈值 440px，四按钮组不会收起。

# R4b 前置决议（切割轮 · 弹窗接线）

> 状态：待 R4a 闭合后启动。本文只记已拍板决议与挂账，不含实现细节。
> 依赖：R4a 提供 `commitWordSegments` + `wordTimes.ts` 纯函数集；本文所有交互都建在它们之上。

## 一、入口

- 位置：行编辑弹窗（`LineActionSheet` + `LineEditForm`）内，字级列表区域。
- 准入：不要求行级非空。锚点三层回退（行级 → 首字 → 占位）由 `commitWordSegments` 内部完成。
- 行级为空且首字有值时，**打开弹窗即预填行级输入框**为首字时间，用户可见可改，保存才落。不静默写。

## 二、二级弹窗（切割）

- 独立 portal，`z-[45]`（避开 `z-40` 现有 dialog 与 `z-50` toast）。
- 文本**只读**，读一级弹窗当前文本；弹窗内不可改字。
- 粒度：按 UTF-16 码点逐字符给缝；空格与标点都是字符元素。
- 视觉：字间距自适应（`clamp((可用宽 - 字符总宽)/(n-1), MIN_GAP, MAX_GAP)`），触底则文字区 `overflow-x: auto` 横向滚；具体数值以人工目测为准。
- 缝隙交互：暗淡竖缝 ↔ 点击变亮 ↔ 再点取消。
- Esc：必须用 capture 阶段监听或模块级弹窗栈，否则会连外层一起关（外层 Esc 是 window 冒泡 + `stopPropagation`，拦不住同 target 其它监听器）。
- 焦点：需自建 focus trap 与归还，现有弹窗无先例可抄。

## 三、文本与切分的关系

- 弹窗打开期间文本固定（模态 + 文本只能在弹窗改 + 保存才生效），**不存在“文本悄悄变、切分莫名失效”的中间态**。
- 一级弹窗文本一改（`textDirty` 为真）：切分草稿**立即作废**。
  - 旧块**保留并整体灰显**（不做空白、不做实时重算）。
  - 灰显区上方一行**常驻内联提示**：「文本已修改，字级划分已作废，保存后请重新切分」。
- 文本改回原样**不恢复**切分。作废即作废，重新切。
- 改文本会清空字级是既有行为（`editLineText` + `clearWordTimestamps`），本轮不改。

## 四、提示（两处，同款机制）

| 触发 | 内容 | 形态 |
| :--- | :--- | :--- |
| 点击**文本输入框**（该行已有切分格子，`wordTimestamps.length > 0`） | 修改文本会清空现有字级分段 | 默认阻塞确认弹窗；带勾选项「以后用 toast 提示」；勾选后降级为不阻挡编辑的 toast |
| **清空行级时间框**并保存（该行已有字级时间） | 清空行级会同时清空字级时间，字级失去参照 | 同款：确认弹窗 + 可降级 toast |

- 本次弹窗编辑内每处**只提示一次**。
- 勾选项是正式设置项（进 `settingsStore`），设置面板里可主动改；弹窗内勾选写同一字段，两边永远一致。
- 设置项语义是「确认弹窗 / 仅 toast」二态，**不是开关**——提示永不消失，只降级。
- 两处**各自独立设置项**（用户可只关一个）。
- 新增设置项沿用元数据前缀轮的「折叠进同一 `data-settings-item`」手法绕过 harness 的 15 项硬断言，不动 harness。

## 五、落盘与撤销

- 弹窗内 cuts 只是临时态；点保存转成 segments，由 `commitWordSegments` 一次写入。
- 一次切割 = **一条日志**，携带（可选）补行级 + segments + 200ms 字级时间；撤销一次全退。
- 初始时间：首块 = 锚点，后续 +200ms；**越界下一行不封顶、允许越界**，交给用户微调。
- 二次切割：旧切分与旧字级时间整体覆盖；需二次确认「重新切割会覆盖现有字级时间」。
- 新 action 直接写绝对值，不走 `setLineTime` 平移，避免字级被二次平移。

## 六、清空行级的保存顺序（待 R4a/R4b 核实后定）

现有顺序「先 `clearLineTime`（删行级 + 删全部字级时间）→ 后 `setWordTimestamps`（写回字级）」会在同一次保存里重新制造「行级空 + 字级有值」的脏状态。

倾向方案：确认弹窗文案说清「本次对字级时间的修改也不生效」，清空时**跳过** `setWordTimestamps`。需先核实 `LineEditForm` 保存逻辑能否干净地加这个分支；不能则退回「只弹确认、不改顺序」，脏状态靠切割入口三层锚点自愈。

## 七、挂账（R4b 不做）

- 脏状态产生源（`setWordTimestamps` 缺行级校验）不在本轮治理，若第六节退回则仍可产生。
- 导出对脏状态无兜底（`clearedLineLines` 命中即丢字标签）。
- 校验层「导出前检测脏行并提示用首字补齐」未做。
- 切分后行从「未打轴」变「已打轴」，可能触发 `needsFit → maybeFit` 重铺满，接受，写进人工目测。
- cuts 不支持多级（L1/L2），值退化为布尔。
- 日志面板对切割 entry 的详细展示（范围、块数）未做，仅保证不显示「未知操作」。

## 八、待核实（R4b 动手前）

1. 时间轴对未打轴行的占位算法是否纯函数、连续多行是否累加——决定第三层锚点由谁算。
2. `ToastHost` 是否支持 action slot（「以后用 toast 提示」勾选项的承载）。
3. `LineEditForm` 保存顺序能否干净拦截（第六节）。

## 九、R4a 闭合后 R4b 的输入

- `commitWordSegments(lineId, segments, { placementStartMs? })` → `{ ok, reason?: 'no-anchor' | 'line-not-found' }`
- `wordTimes.ts`：`charsFromText` / `cutsToSegments` / `segmentsToCuts` / `deriveInitialWordTimes` / `resolveCutAnchor` / `WORD_CUT_DEFAULT_GAP_MS`
- `segmentsToCuts` 用于「已有切分的行再次打开切割弹窗」时回显旧缝。
