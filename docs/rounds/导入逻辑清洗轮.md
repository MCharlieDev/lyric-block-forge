# 导入逻辑清洗轮（A 错位拉齐）· 交接文档

> **用途**：记录本轮的背景、做法、验收与边界。配合主交接文档阅读。
> **状态**：✅ 已闭合。
> **基线**：harness 467/467；core vitest 165/165；tsc 退出码 0。
> **上游/依赖**：字级视图 R3 的 chip 绝对定位（`blockLayout` 允许负 `leftPx`）；本轮无前序轮次代码依赖。

## 一、本轮范围

在 core 解析层加一个模块私有纯函数，把导入数据里的「字级时间早于行级时间」（A 错位）单向拉齐到本行行起点；B 错位（行内字级乱序）与 C 错位（跨行重叠）不处理。

## 二、核心接口与契约变更（极其重要）

- **新增接口**：无（不导出）。`clampWordsToLineStart(words, anchor)` 为模块私有纯函数，仅 `parseLrc` 内部调用。
- **修改接口**：无。`parseLrc` / `buildLine` / `ParseOptions` / `OperationKind` 签名与字段均未变。
- **数据模型/类型变更**：无。
- **DOM 契约（供 harness 依赖）**：无变化。
- **行为契约变更（重要）**：导入含 A 错位的增强型 LRC 时，`LyricLine.wordTimestamps` 的 `timeMs` 不再等于文件原值，而是 `max(原值, 行首 timeMs)`；被改写项同时取 `precisionMs = min(字级, 行级)`。

## 三、关键设计与做法

1. **位置**：`src/core/lyrics/parse.ts`，`splitEnhancedText` 之后新增私有纯函数；调用点放在主循环「行级时间解析完成之后、`buildLine` 之前」。原因：`buildLine` 的参数只是 `{ timeMs, precisionMs }` 轻量对，拿不到完整 `Timestamp`，无法在 `buildLine` 内部满足 `anchor: Timestamp` 的类型约束（任务书的兜底分支）。
2. **锚点**：`timestamps[0]`（首个行级标签）。多时间戳行 `[00:15.00][00:18.00]` 锚 15000；落在后续时间戳区间内的字级时间（如 16000）不修。
3. **只单向钳制**：`if (word.timeMs >= lineStartMs) return word`，不排序、不动 `range` / `text` / 数组顺序 → B 错位原样保留；不做任何跨行比较 → C 错位不处理。
4. **精度归一化**：越界项 `precisionMs = Math.min(word.precisionMs, anchor.precisionMs)`，避免「存储 15500 + 精度 1000 → 导出四舍五入成 16000」。
5. **静默且不进撤销栈**：纠错发生在 `createOperationLog` 之前，导入仍只写一条 `kind:'import'`、`delta.mode:'none'` 日志；不加开关、不生成 issue。
6. **纯文本 no-op**：无字级标签的行 `words = []`，函数直接返回浅拷贝；纯文本行导出仍走 raw，行为零变化。

## 六、已知取舍与未验证

- **取舍**：含 A 错位的文件不再逐字节往返（有意牺牲，换取渲染正确）；静默修正、不生成 issue、用户不可见；B 错位原样保留，行内乱序会继续存在于文档与导出中；C 错位（跨行重叠）不处理；拉齐时改写字级 `precisionMs`（取两者更细者），属元数据归一化；`raw` 仍保留原始行文本，但有字级标签的行导出走结构化重建（`renderWords`），因此修正不可逆；多时间戳行锚 `timestamps[0]`，字级时间落在后续时间戳区间内不修。
- **未验证**：未在真机人工目测「字卡不再飞出块左缘」（本轮只跑机器验收）；未统计真实脏 LRC 样本中 A 错位的分布；未验证「`wordTimestamps` 非空但 `timestamps` 为空」的异常构造（读码判断不会出现，函数已按 `anchor === undefined` 跳过兜底）。

## 七、否决的备选方案

- **在 store `importDocument` 入口清洗**：修改发生在 UI 层，core 测试覆盖不到；与「导入只写一条 import 日志」的语义割裂；`TextImportDialog` 预览走 `parseLrc`，口径会分叉。
- **在渲染层钳制 `leftPx >= 0`**：只治显示不治数据，导出仍是脏数据，换工具再导入必然复发。
- **保留 raw 优先导出以维持逐字节无损**：会导致修正永不落盘，违背本轮目的。
- **顺手修 B 错位（排序）**：会改变创作者原始标注顺序，且 B 可能是刻意的（连读、和声叠字）。
- **在 `splitEnhancedText` 内部拉齐**：该函数拿不到行级时间，需改签名并把「解析」与「纠错」耦合，不如独立纯函数可测。
