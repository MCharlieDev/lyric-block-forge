## 一、本轮解决了什么

在这之前，时间戳只有**位置输入**——拖块、在播放头按空格。知道确切数值（从别处抄来的、资料上写着的）的人，**没有任何地方能把它敲进去**，只能反过来用鼠标逼近。

本轮补上**数值输入**这条腿。两条路各管各的场景。

***

## 二、改了哪些

### 1. 行级时间戳输入框（弹窗最顶端）

- 格式 `mm:ss`（可选小数）；**不带方括号**
- **空串 = 清空语义**（合法，不是非法）
- 非法输入：红框 + `aria-invalid` + 行内红字 + **禁用「保存」**
- 只走「保存」按钮提交，不即时生效
- **不弹确认框**（行级改动不算重大改变）

### 2. 解析规则变更（行级 + 字级共用）

- **纯数字 = 秒**（原来是错的——直接当毫秒：输入 `20` 成了 20 毫秒）
- `mm:ss` / `mm:ss.mmm` 保持；秒 ≥ 60 判非法
- **归一化推迟到保存时**：编辑期间输入框保持用户原文，失焦/回车都不再改写
- 大数自动进位：`125` → 保存后 `02:05.000`
- 抽出共享解析：[timeInput.ts](file:///d:/CodeProjects/LRC-Editor/src/ui/utils/timeInput.ts)

### 3. 改行级 → 字级跟随平移

- 用现有 `offset` 表达（**无需新 core**）：`offsetMs = 新值 − 当前回放值`，`scope.wordRefs` 带该行全部字级
- 行未打轴 → 走 `absolute`（纯打轴）
- 目的：避免「行级跑到字级后面」的非法态

### 4. 清空 = 未打轴（新 core 能力）

新增 delta mode **`clear-timestamps`**：

- 删该行行级时间戳键 + 清该行字级 `timeMs` + `clearedLineLines.add(lineId)`
- **绝不**进 `clearedWordLines` ← **这是保留切分的关键**

**一条日志，撤销一步还原整行（行级 + 字级）。**

### 5. 保留切分

清空后 `deriveVisibleLines` 不动 `wordTimestamps` 数组 → `range`/`text` 保留 → 弹窗槽位仍在，显示「未打轴」。

「切分」和「时间」本来就是分离的字段，所以只清时间、留切分**结构上天然可行**。

### 6. 导出防复活

清空后导出若走原路径，会从文档基线把旧标签「复活」（demo 的字级就存在基线里）。
修法：命中 `clearedLineLines` → 输出 `timestamps:[]`、`wordTimestamps:[]`、`raw:undefined` → **纯文本**。

### 7. 日志

- 条目 `description`：**`清空时间戳「{行文本}」`**（整行概念，不写"行级"）
- `LogPanel.describeDelta` 补分支 → 展开显示「清空时间戳」，不再误报「无时间变化」
- 未新增 `OperationKind`（保持 `manual-timestamp`，"按类型撤销"语义不变）

## 四、已知取舍

- **行级 offset 连带平移该行全部行级时间戳与全部字级**：这是「用 offset 表达行级改动」的必然结果。demo 每行仅 1 个行级时间戳，多时间戳行连动路径**未被数据覆盖**。
- **导出丢切分与翻译**：清空后按纯文本导出——**防复活优先于保留结构**。
- **字级框非法态未单独断言**：非法路径由行级条覆盖同一 `parseInput`，但字级框自身的红框/禁用未单测。
