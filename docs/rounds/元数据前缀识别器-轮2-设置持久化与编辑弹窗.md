## 一、本轮范围

把可配置前缀表接入设置持久化，并新增独立的「前缀规则」编辑弹窗：用户在设置面板点击「配置前缀规则…」后，可在弹窗内即时增删改规则；规则表随设置写入 localStorage，刷新后保持。

## 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `MetadataPrefixDialog`：Props `{ rules: MetadataPrefixRule[]; onChange: (rules: MetadataPrefixRule[]) => void; closeOnBackdropClick: boolean; onClose: () => void }`。用途：前缀规则内联编辑弹窗；遮罩关闭由 `closeOnBackdropClick` 控制。
  - `normalizeMetadataPrefixRules(value: unknown): MetadataPrefixRule[]`（模块内纯函数，未导出）：把持久化读回的未知值规范化为合法规则表。
  - `ControlCtx.openPrefixDialog: () => void`（`SettingsMenu` 内部）：设置项控件打开弹窗的入口。
- **修改接口**：
  - `AppSettings`：新增 `metadataPrefixRules: MetadataPrefixRule[]` 字段；新增 `closeMetadataPrefixDialogOnBackdropClick: boolean`（默认 `false`，与 `closeDialogOnBackdropClick` 相互独立）。
  - `toMetadataPrefixOptions(settings)`：返回值新增 `rules: settings.metadataPrefixRules`（三个模式分支均透传）。
  - `SettingsMenu` 的 `metadataPrefixMode` 控件：外层 `<label>` → `<div>`，内部保留 `<label>` 包文字与 `<select>`；下方新增按钮。
  - `SettingsMenu` 的 `closeDialogOnBackdropClick` 控件：由单个 `<label>` 改为 `<div>` 承载两个独立复选框（行操作弹窗 / 前缀规则弹窗），原开关行为与项 ID 不变。
- **数据模型/类型变更**：
  - `AppSettings` 新增 `metadataPrefixRules`（`MetadataPrefixRule[]`；空数组语义 = 不识别任何前缀，不回退默认表）与 `closeMetadataPrefixDialogOnBackdropClick`（`boolean`，非 boolean 回退默认 `false`）。
- **DOM 契约（供 harness 依赖）**：
  - 新增 `data-prefix-rules-trigger`：设置面板中「配置前缀规则…」按钮。
  - 新增 `data-metadata-prefix-rules`：弹窗内规则滚动区。
  - 新增 `aria-labelledby="metadata-prefix-dialog-title"` 指向弹窗标题；弹窗根 `role="dialog"` + `aria-modal="true"`。
  - 保留 `data-settings-item="metadataPrefixMode"` 与原 `<select>` 三个 option 的值与顺序（`off` / `meta` / `meta+line`）。

## 三、关键设计与做法

1. **即时保存、无草稿**：弹窗每次 `input` / `select` / 增删 / 恢复默认都直接 `onChange(nextRules)` → `settingsStore.update({ metadataPrefixRules })` → `App.tsx` 的变更即写 effect 落 localStorage。关闭弹窗不会提交任何额外变更。
2. **默认表 clone 三处**：`DEFAULT_SETTINGS.metadataPrefixRules`、`createDefaultSettings()`、`reset()` 都走 `cloneDefaultMetadataPrefixRules()`；弹窗内「恢复默认规则」也独立 clone。避免任何一处修改污染内核默认表或其他实例。
3. **白名单校验与内核同口径**：`normalizeMetadataPrefixRules` 对数组逐条校验——`prefix` / `tag` 必须为字符串且 trim 后非空；`tag` 必须匹配 `^[a-zA-Z]+$`；`prefix` trim 后不得含 `：: \t`；`action` 仅 `'line'` 保留，其余一律降级 `'meta'`。非法条目静默丢弃。非数组回退默认表 clone；**空数组保持 `[]`**。
4. **输入即过滤**：prefix 输入时过滤 `：: \t`（含空格），`onBlur` 再 trim；tag 输入时只保留 `[a-zA-Z]`。因此弹窗内很难产出必然非法的条目，红框只用于「用户清空」这类瞬时状态。
5. **行内反馈分级**：空前缀 / 空标签 → 红框 + `text-red-400` 错误文案；与上方规则重复 prefix → `text-amber-400` 警告，不阻断、不在 normalize 去重（与内核「先到先得」一致）。
6. **关闭与焦点**：遮罩点击仅在开关开启且 `event.target === event.currentTarget` 时关闭；Esc 走 `window` keydown 并 `stopPropagation()`，避免触发编辑器全局快捷键；打开时记录 `document.activeElement`，初始焦点给首条规则 prefix 输入（空表给「+ 添加规则」），卸载时还原。
7. **Focus trap**：弹窗根 `onKeyDown` 捕获 `Tab`，查询 `button / input / select / [tabindex]` 中可见元素，Shift+Tab 在首元素回环到末尾、Tab 在末元素回环到开头；焦点意外落在弹窗外时也拉回。
8. **遮罩关闭独立开关**：本弹窗读取 `closeMetadataPrefixDialogOnBackdropClick`（默认 `false`），不复用 `closeDialogOnBackdropClick`，两者互不影响；开关与行操作弹窗开关并列在「界面」段同一设置项内，因此不改变 harness 依赖的设置项 ID 集合。Esc 关闭始终可用。

## 六、已知取舍与未验证

- **取舍：即时保存**——编辑中途无法整体撤销，只能逐条改回或「恢复默认规则」。
- **取舍：遮罩关闭默认开启与否**——`closeMetadataPrefixDialogOnBackdropClick` 默认 `false`，与行操作弹窗默认值保持一致；开启后误触遮罩会丢失正在输入但未 blur 的字段（已落盘规则不受影响）。
- **取舍：新开关不独立成设置项**——为不破坏 harness 依赖的 15 项设置集合，新开关与行操作弹窗开关并列在同一 `data-settings-item` 内；搜索命中该项时两者同时出现。
- **取舍：prefix 禁止空格**——因此「Produced by」这类多词前缀无法配置；换来与内核分隔符口径一致、避免前后缀歧义。
- **取舍：空数组不回退默认**——无法区分「用户主动删光」与「存储被写成 `[]` 的脏数据」，统一按用户意图处理。
- **取舍：重复 prefix 只警告不阻断**——normalize 不去重，与内核「顺序匹配、先到先得」一致；用户可保留重复项观察实际生效规则。
- **未验证**：真实浏览器手工目测（弹窗视觉、Tab 回环、Esc 后焦点还原、遮罩关闭、刷新后空表保持）尚未由用户确认；Firefox / Safari 的 focus trap 与焦点还原未测。
- **未验证**：`Ctrl+Shift+R` 硬刷新后的 localStorage 迁移路径仅通过 hydrate 单测与 harness 的 settings 探针间接覆盖。

## 七、否决的备选方案

- **草稿 + 保存 / 取消按钮**：需要额外的临时状态与「未保存变更」提示，且与设置面板「修改自动保存」的既有口径冲突；否决。
- **在设置面板内联展开规则列表**：设置面板固定 420px 高、中间区域已承载全部设置项，内联列表会挤压搜索与底部操作栏；独立弹窗可提供足够宽度与滚动区；否决。
- **normalize 时按 prefix 去重**：会让「先到先得」的可见规则与持久化结果不一致（用户看到两条、刷新后只剩一条）；改为只警告；否决。
- **prefix 允许空格、匹配时再区分分隔符**：多词前缀会与「前缀 + 空格 + 值」的既有分隔符规则产生歧义，且内核已按无空格前缀设计；否决。
- **复用 `closeDialogOnBackdropClick`**：行操作弹窗与前缀规则弹窗的误触代价、使用频率不同，共用开关会让用户无法单独控制；改为独立字段；否决。
