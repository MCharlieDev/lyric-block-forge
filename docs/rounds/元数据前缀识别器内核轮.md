## 一、本轮做了什么

`parseLrc` 导入时识别歌词前的介绍行（如「作词：张三」），转为文档元数据。开关由 `ParseOptions` 新字段控制，**默认关**。

本轮**只做内核 + 单测，不接线 UI**：功能默认关、无入口，因此仅内核可测（已在 A 段裁决接受）。

## 二、关键设计

- `ParseOptions.metadataPrefix?: { enabled?: boolean }`，默认 `false`。既有调用方不传 ⇒ **零行为变化**。
- **生效条件**：`applyRecognizers !== false && metadataPrefix.enabled === true`（`applyRecognizers` 是总闸门）。
- **默认前缀表**（写死常量 `METADATA_PREFIX_TABLE`，`tag` 用「标签名」不是字段名）：

  | 前缀 | tag | 前缀 | tag |
  | :--- | :--- | :--- | :--- |
  | 作词 | lyricist | 制作人 | producer |
  | 作曲 | composer | 混音 | mixer |
  | 演唱 | **ar** | 母带 | mastering |
  | 编曲 | arranger | 出品 | presented |
  |  |  | 发行 | publisher |

  非标准 tag 走 `default` 分支 → `meta.custom[tag] = value` 且去重 push `unknownTags`。
- **触发四条件（同时满足才摘）**：① 位置在前 `METADATA_PREFIX_MAX_LINES = 10` 条**内容行**内 ② 该行无行级时间戳 ③ 出现在**第一条带时间戳的行之前**（全文无时间戳则恒满足）④ 前缀命中 + 分隔符合法 + 值非空。
- 分隔符 `METADATA_PREFIX_SEPARATORS = '：: \t'`（中文冒号 / 英文冒号 / 半角空格 / Tab）；**前缀锚定行首**（避免「作词人：X」误命中「作词」）；值两端 `trim`。不满足 → 保留为歌词行（原行为不变）。
- **命中即就地转元数据**：该行**不进 `lines`**；按元数据行既有方式处理空行游标（共用 `flushBlanksForMetaRow`）。
- **关键裁决 · 合成记录**：命中时**同时** `metadataTags.push([{ name: tag, value }])`（源顺序位置）。否则 pristine 判据 (b)「无有值却未被 `metadataTags` 覆盖的名」失败 ⇒ 导出退回单行标准序、多行元数据布局塌陷。
- **共用映射**：标签→字段写入抽为 `parseLrc` 内局部函数 `applyMetaTag`，元数据标签路径（`[tag:value]`）与前缀识别路径**共用同一份 switch**，不复制。
- **识别即移除原文（有损）**：导出为 ASCII 标签名（如 `[lyricist:张三]`），中文前缀不回写。

## 四、已知取舍

- **有损转换**：识别行原文不保留，仅以标准标签名回写。
- **非标准前缀落 `custom`**：中文前缀不往返，导出为 ASCII 标签名（`[producer:李四]`）。
- **前缀表写死**：不持久化、不可配置（增删 UI 留给后续轮）。
- **窗口 10 条为硬编码常量**。
- **界面不可达**：默认关 + 无入口，仅内核可测。

## 五、未验证

- **UI 可达性未验**：按裁决本轮不接线，界面无入口（预期）。
- **仓外 CDP harness 未跑**：本轮在 core 层，harness 基线（414/414）不受影响；core 回归以既有 33 条为基线。
- **元数据块内部空行交互未覆盖**：识别行与「两条元数据行之间的空行」的交互未断言（该缺口既有、非本轮引入）。
- **`offset` / `length` 前缀路径未覆盖**：默认表中无对应中文前缀，前缀路径无法触发这两个 case。
