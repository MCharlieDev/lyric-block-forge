【产品决定】

═══ 零、核心语义：没有选中是合法状态 ═══

1. 「有选中」和「无选中」都是合法状态。「无选中」不是需要自动填上的空状态。
2. 空格打轴：无选中 → 静默返回（不打任何行）。
3. 方向键切行：无选中 → 选中第一可见行（导航和执意分开，方向键是导航意图）。
4. 「无选中」在三种情况下产生：
   - 用户主动点时间轴背景
   - Ctrl+点击减空最后一个成员
   - 操作副作用（删行/撤销后没有剩余成员）
5. 导入时的默认选中第一行保留 —— 那是「从无到有」的唯一合法来源，不是「没选中就自动填上」。这是覆盖旧逻辑，不是叠加。
6. 撤销删除后，选中不自动恢复。reconcile 只清不设，是刻意的。

═══ 一、多选选择 ═══

1. Ctrl（macOS 下 Cmd）+ 点击：切换该行选中态
2. Shift + 点击：从锚点到该行做范围选（含两端，按可见行顺序）
3. 普通点击：清空其他选中，只选中当前行
4. 时间轴上的块与列表里的行共用同一份 selection.lineIds，两边点击都生效
5. 点击时间轴背景（非块区域）：清空全部选中
   lineIds = \[]、activeLineId = null、anchorLineId = null

═══ 二、锚点 ═══

1. 新增 anchorLineId 字段（string | null）
2. 锚点 = 上一次非 Shift 点击的行；Ctrl+点击也重设锚点
3. Shift+点击不改锚点；锚点缺失或不在可见行里时退化为普通点击
4. Ctrl+点击减掉当前 active 行时，activeLineId 落到 lineIds 剩余成员的最后一项；
   剩余为空则 null

═══ 三、对账（本批必做） ═══

1. 抽一个只处理行字段的纯函数：
   reconcileLineFields(selection, existingIds: Set<string>): SelectionState
   - 过滤 lineIds、activeLineId、anchorLineId
   - 不动 entryIds
2. 存在性判据从 document.lines 改为 deriveVisibleLines(document, replay) 的 id 集合
   —— 这是修病根，不是多加一层清理
3. 把 reconcileSelectionAfterUndo 改成 (document, replay, selection) =
   reconcileLineFields(...) + entryIds: \[]
4. 四个调用点（undoLastAction / undoByKindAction / undoSelectedEntries /
   restoreSelectedEntries）改传操作后的新 replay
   （现在传的是旧 document，本身就是错的口径）
5. removeLine 末尾接入 reconcileLineFields，并补三条路径：
   - 删 active（单选）：移到相邻可见行（现有行为，保留）
   - 删 active（多选）：剔掉它，光标落到最近的剩余成员
   - 删非 active（多选）：剔掉它，其他成员保留（现在完全没处理）
6. 对账时机 = 所有可能改变可见行集合的操作结束后
   即 removeLine + 4 条 undo/restore。
   offset / text-edit / word-timestamp / swap 不改可见集合，不接对账。

═══ 四、选中态视觉 ═══

1. 区分两种视觉：
   - isActive（line.id === activeLineId）：强高亮，现有样式不变
   - inSelection（lineIds 成员但不是 active）：次高亮
2. 时间轴块与列表行都要用这一套区分
3. 订阅 selection.lineIds 时注意引用稳定性，不要在 selector 里创建新数组

【已核实的技术事实】（不需要再验）

1. kind 是 selection-offset，label 是多选移动，demo 在 demoSession.ts:166
2. isMajorChange('selection-offset') 返回 true，但代码库里没有任何弹窗分支，
   isMajor 只被 LogPanel 渲染成徽标
3. selection.lineIds 目前只写不读，改它语义不破坏现有消费方
4. 现有对账函数 reconcileSelectionAfterUndo 已覆盖 lineIds / activeLineId /
   entryIds，但存在性判据用 document.lines，永不缩减，对已删行完全无效；
   且 removeLine 完全没走它
5. 删除行只往 replay.removedLineIds 加，document.lines 永不缩减
6. stampActiveLine 现在有「无选中 → 打第一可见行并选中它」分支，需要删掉
7. moveSelection 现在也有「无选中 → 选第一可见行」分支，需要保留
8. clearLineSelection / toggleLineSelection / selectLineRange 在 src 中零命中，
   无重名冲突
9. anchorLineId 已作为 inferInitialTimeMs 的形参名存在，与 SelectionState 字段
   不同作用域，类型层面不冲突

【我的判断与依据】（依据不成立先反驳，不要执行）

1. 对账修在源头，改判据不改架构。
   依据：病根是「视角用错」，不是「漏做清理」。判据从「文档里有」改成
   「能被渲染出来」，之前所有幽灵自然不符合条件，自动过滤。
2. 空格删分支，方向键保留分支 —— 两个函数的不同处理不是不一致，是分职。
   依据：空格是执行（对当前行做点什么），无目标不该做；
   方向键是导航（移动光标），无目标时给默认起点是合理服务。
3. 四个 undo/restore 调用点：先把 computeReplay 结果存进 const，
   再同一份穿过 replay 与 reconcile，避免重复计算。
4. removeLine 是唯一「reconcile + 显式设值」的地方。
   依据：按零.6，reconcile 只清不设；回退/重定位是本函数自己的职责。
5. 第一批不做提交侧过滤 —— 那是第二批拖动提交时的事。
   本批只做源头对账，不加消费侧过滤。
6. 第一批和第二批的边界：
   - 第一批：对账 + 选择 API + 视觉 + 空格/背景语义改动。
     做完后可以手动验：Ctrl 点击选中、Shift 范围选、点背景清空、
     删行后剩余选中是否干净、无选中时空格是否真的不打轴。
   - 第二批：拖动状态机（track 层 ref + 命令式 transform + 吸附 + 提交）。
     理由：第一批错了（高亮不对）能立刻看见；第二批错了要在拖动中才察觉，
     容易被误当成卡顿。分开做，出问题时知道该 blame 谁。
