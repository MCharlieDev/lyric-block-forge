## 二、产品决定（已裁决，最终态）

### 2.1 确认框

| 项           | 决定                                               |
| :---------- | :----------------------------------------------- |
| **触发面**     | 只挂「**拖动提交** `selection-offset`」一个点；方向键多选微调**不弹** |
| **形态**      | **挡操作**——点确认才落盘；取消则完全不落盘、不改状态、不改设置               |
| **设置**      | 一个**总开关** `confirmMajorChange`，默认开启              |
| **弹窗内勾选**   | 「以后不再显示」为本地 state；**仅点确认时才写设置**（取消/Esc/× 都不写）    |
| **不弹的场景**   | 单行打轴、单行微调（架构文档 5.2 已定）                           |
| **行级时间戳输入** | **不算**重大改变，不弹（创作者习惯直接输数字微调，弹框会打断高频操作）            |

**为什么方向键不弹**：方向键是「小步长、可连按」的精细工具，弹窗会摧毁它；且拖动的「一次挪大段、多行同动」才符合"重大改变"的心理预期。技术上干净——确认框挂在**拖动入口**，不挂在 kind 上，方向键入口不挂即可。

### 2.2 拒绝提示 toast

| 项               | 决定                                |
| :-------------- | :-------------------------------- |
| **载体**          | **自研 toast**（禁止原生）                |
| **位置**          | 顶部居中，工具栏下方（`top-[3.25rem]`）；不压歌词块 |
| **时长**          | 3500ms 自动消失                       |
| **手动关闭**        | 有 × 按钮                            |
| **去重**          | 同文案 3000ms 窗口内再到达 → **丢弃且不刷新计时**  |
| **堆叠**          | 单槽（后到替换），不做堆叠                     |
| **触发**          | 拖动 blocked + 方向键微调拒绝，两处           |
| **单行 nudge 拒绝** | **保持静默**，不弹                       |

### 2.3 通用原则（记入校准栏）

**所有弹窗 / toast 必须自研，禁止** **`window.confirm`** **/** **`alert`** **/ 原生** **`<dialog>`。**

## 三、关键设计点

### 3.1 确认框的插入点（最容易做错的一处）

**现状（改前）**：`handlePointerUp` 里 `clearSessionStyles` 是**无条件先执行**——撤掉 transform、块弹回原位，然后才按 mode 提交。

**改后**：把 `clearSessionStyles` 从「无条件先撤」改为「**确认 / 取消 / 无弹窗时才撤**」。

判断链（`session.mode === 'multi'` 且 `|deltaMs| >= DRAG_MIN_DELTA_MS` 且设置开启）：

- **命中** → 不撤样式、不落盘；暂存会话（含 nodes 映射）到 ref + `setState` 打开弹窗后 return
- **未命中** → 走原路径（撤样式 → 提交）

**为什么挂** **`mode === 'multi'`** **而不是** **`kind === 'selection-offset'`**：方向键微调与拖动共用同一 kind，挂 kind 会误伤方向键。挂入口（`mode === 'multi'`）才不误伤。

### 3.2 「松手 → 确认」的视觉状态

**块保留临时 transform，停在吸附后落点**（`zIndex=10`、`grabbing` 光标仍在），弹窗以 z-40 盖在其上——**所见即所确认**。

- 确认 → `clearSessionStyles` + `moveLinesByOffset`（与现状合批一致）
- 取消 → 仅 `clearSessionStyles`，块弹回原位

### 3.3 取消能完全回滚（论证）

`multi` 模式**蕴含**"被按块已在多选中"——因为 pointerdown 只对"未选中块"做归位单选，一旦归位 `selected.length` 变 1，mode 就不可能是 `multi`。

**所以 pointerdown 根本没动选区，取消时**：transform=清、选区=未变、日志=未写、设置=未写。**完全回滚，零副作用。**

### 3.4 弹窗属性（硬要求）

必须带 `role="dialog"` + `aria-modal="true"` + `aria-label`——因为 `useEditorHotkeys.hasOpenDialog()` 依赖它来**停用全局快捷键**。缺了它，弹窗打开时按空格/方向键还会作用到背后。

### 3.5 关闭路径

Esc = 取消、右上角 × = 取消、**遮罩点击 = 不关闭**（破坏性确认不给"随手点掉"的路径）。`autoFocus` 落在「取消」按钮。

**不做完整 focus trap**（与既有 `LineActionSheet` / `TextImportDialog` 现状一致）。

## 六、已知取舍

- **不抽通用 modal 基座**：`LineActionSheet` / `TextImportDialog` 属已定稿、且不在允许清单，抽象会牵连既有 Esc/遮罩行为；新弹窗**复制其模式自实现**。
- **不做完整 focus trap / 焦点还原**：与项目两弹窗现状一致；`hasOpenDialog` 已停用全局快捷键，Tab 逃逸风险低。列为已知缺口。
- **toast 单槽不堆叠**：当前唯一多触发场景是两处拒绝文案，单槽 + 去重足够。
- **遮罩点击 = 不关闭**：破坏性确认不提供"随手点掉"路径；未接 `closeDialogOnBackdropClick` 设置。
- **确认框内 checkbox 为本地 state**：取消后不保留勾选状态（下次打开重置为未勾）。

## 八、否决的备选方案

- **挂** **`kind==='selection-offset'`** **而非挂拖动入口**：方向键微调与拖动同为该 kind，会误弹——违背产品决定。
- **松手即撤 transform、弹窗用"幽灵块"预览落点**：需额外渲染影子层、状态更多；"块停在落点、弹窗盖其上"更直观且改动最小。
- **取消时额外做** **`selectLine`** **回滚选区**：`multi` 根本未动选区，多余写入反而污染。
- **用原生** **`window.confirm`**：产品明令禁止，且无法承载"勾选同步设置"。
- **给两处批量撤销入口（App.tsx / LogPanel）也加确认框**：超出本轮硬边界，仅报备。
- **单行 nudge 拒绝也弹 toast**：属"单行微调"，产品决定不弹。
- **toast 堆叠/队列**：按指令单槽（后到替换）。
- **确认框内 checkbox 直接实时写设置**：改为本地 state，仅点确认且勾选时才写。

## 九、这轮踩到的坑（供后轮参考）

**harness 的 BOOTSTRAP 是模板字符串**：`majorDialogDelta` 的正则原为 `/[+-]?\d+ ms/`，`\d` 被模板字符串转义吞成 `d` 导致恒 null。修法：写成 `\\d`（原样注入 `\d`）。

**教训**：harness 里内嵌的正则（在模板字符串内）**必须双反斜杠**，否则 `\d` / `\s` / `\w` 全被吞。这是 harness 侧 bug，非产品代码问题。
