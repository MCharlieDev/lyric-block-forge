## 轮次 1：几何内核（真实内容宽 + 阶梯宽度纯函数）

### 一、本轮范围

只做几何内核：为每张 word chip 提供「纯内容宽」，并新增一个把同时间连续多字改写为阶梯宽度的纯函数。零接线、零视觉变化。

### 二、核心接口与契约变更

- **新增接口**：
  - `stackWordChipWidths(fullWidthsPx: readonly number[], contentWidthsPx: readonly number[], timesMs: readonly (number | null)[]): number[]`：纯函数，入参三等长，返回等长宽度数组。用途：把相邻且时间严格相等的连续多字改写为阶梯宽度（只改宽度，不改左缘）。
- **修改接口**：
  - `LineWidths`：新增必填字段 `wordChipContentWidthsPx: number[] | null`。修改原因：`wordChipWidthsPx` 含 +8 padding 与 22 下限，拉丁字符反推内容宽会偏 7px/字，必须由测量层直接给出纯内容宽。
  - `CHIP_PADDING_X_PX`：模块私有 → `export`。修改原因：`blockLayout` 需要 `CHIP_PADDING_X_PX / 2` 作为单侧 padding，导出常量以避免 `4` 双写漂移。
- **数据模型/类型变更**：
  - `WordChipBox`：**无变化**（仍只有 `leftPx` / `widthPx`）。加字段会让 `blockLayout.test` 的 q1–q4 `toEqual` 全红。
- **DOM 契约（供 harness 依赖）**：
  - 无变化。本轮不触渲染层。

### 三、关键设计与做法

1. **内容宽的上游来源**：`computeLineWidths` 在传入 `wordTexts` 时，逐项 `measure(wordTexts[i], 'chip')` 得到纯文本宽——不含 `CHIP_PADDING_X_PX`、不含时间戳徽标宽、不受 `WORD_CHIP_MIN_WIDTH_PX` 约束，与 `wordChipWidthsPx` 同长度同下标。未传 `wordTexts` 时为 `null`。
2. **既有算法一律不动**：`wordChipWidthsPx` 与 `wordRowWidthPx` 的计算保持原样，因此 q1–q4 等既有断言不受影响。
3. **阶梯宽度公式**（组内序 0..N-1，`c` 为内容宽）：
   - `W_0 = CHIP_PADDING_X_PX / 2 + c[0]`
   - `W_i = W_{i-1} + CHIP_GAP_PX + c[i]`（1 ≤ i ≤ N-2）
   - `W_{N-1} = W_{N-2} + CHIP_GAP_PX + c[N-1] + CHIP_PADDING_X_PX / 2`
   - 组总宽 = `8 + Σc + 2(N-1)`，即「一张卡的内容 + N-1 个间隔」，与合并卡同量级。
4. **分组规则**：`timesMs[i] === null` 的卡不参与阶梯、原样输出；相邻且 `timeMs` 严格相等的连续段为一组；单元素组原样输出（保留徽标宽与 22 下限）；多元素组内不套 22 下限（组整体才是可点目标），结果恒 ≥ 上一级。
5. **只改宽度不改左缘**：左缘仍由 `layoutWordChips` 按 `(timeMs − startMs) × ppms` 决定；`layoutWordChips` / `layoutBlock` 的签名与实现均未改动。
6. **常量不双写**：`CHIP_PADDING_SIDE_PX = CHIP_PADDING_X_PX / 2` 由导出常量派生，避免 4 与 8 漂移。

## 轮次 2：取消合并 + 阶梯渲染 + 组内反序

> **状态**：✅ 已闭合（含 4 条预期红字，轮 3 清账）。
> **基线**：harness 444/444；core vitest 152 通过 / 4 失败 / 156 总数；tsc 退出码 0。
> **上游/依赖**：轮 1 的 `wordChipContentWidthsPx` 与 `stackWordChipWidths`（本轮首次接线）。

### 一、本轮范围

把轮 1 的几何内核接到 UI：`deriveDisplayChips` 取消同时间合并、逐字成卡；`LyricTrack` 用阶梯宽度排版；`LyricBlock` 组内左偏移 + 倒序绘制 + 仅组首时间戳溢出。

### 二、核心接口与契约变更

- **新增接口**：无（`stackWordChipWidths` 为轮 1 既有）。
- **修改接口**：
  - `deriveDisplayChips`：签名不变，**语义变更**——同时间不再合并，每条 chip 恒为单字，`indices` 恒为单元素数组。修改原因：阶梯需要「每个字一张卡」才能逐级外露，合并卡会让阶梯退化成一张卡。
- **数据模型/类型变更**：`DisplayChip` 字段形状不变（`indices` 仍为数组，便于消费端不改）。`WordChipBox` 不变。
- **DOM 契约（供 harness 依赖）**：
  - `data-word-chip` / `data-chip-indices`（现恒为单值）/ `data-chip-time-ms` 均保留。
  - **DOM 顺序变化**：多元素组内改为倒序渲染（组首最后绘制）。按 DOM 顺序取 chip 的假设不再成立，必须用 `renderOrder` 映射回原下标。
  - 组首卡片由 `overflow-hidden` 改为 `overflow-visible`；组内非首卡时间戳位置为等高占位（`&nbsp;`）。

### 三、关键设计与做法

1. **取消合并但保留排序**：排序（时间升序 / null 最后 / 同时间按原 index 稳定 tiebreak）是阶梯分组的前提——渲染层靠「同时间相邻」识别组，排序不动。
2. **宽度上线**：`laidOut` 里先算 `wordChipWidthsPx = stackWordChipWidths(full, content, times)`，再喂给 `layoutWordChips`；左缘仍由时间算。两者缺一（null）时退回原 `full`。
3. **组内左偏移**：非组首卡的 `paddingLeft = 前一张 widthPx + CHIP_GAP_PX`，`paddingRight = 组尾 ? 4 : 0`；组首走既有 `px-1`（左 4）不写 inline padding。宽度一律取 `wordChips[i].widthPx`，前端不重算。
4. **绘制顺序**：`renderOrder` 遍历 chips，遇到多元素组整组倒序推入；渲染时仍用原下标取 `chips[i]` / `wordChips[i]`，几何与数据不错位。
5. **为什么不用 z-index**：chip 自身原本无 z-index、块根普通态 `z-index:auto` 不构成堆叠上下文；给 chip 写正 z-index 会让它逃逸到平面层压住相邻块。因此层级只能靠 DOM 顺序——「组内第一张最后绘制 = 画在最上层」，正好匹配 `closest('[data-word-chip]')` 的命中规则。
6. **时间戳**：仅组首渲染 `formatMiniTime`；非组首用等高空占位保住字行基线。组首卡 `overflow-visible` + 时间戳 `whitespace-nowrap`，让时间向右溢出到阶梯上方可读。
7. **未打轴（null）永不参与**：`inMultiGroup` 先判 `timeMs !== null`，避免两张 null 卡被误认成一组。

- **取舍**：
  - 组内只有首卡渲染时间戳，其余为等高占位；首卡时间戳溢出到阶梯上方，视觉上会盖住后两张卡的上排。

- **未验证**：真实字体下 CJK / 拉丁的阶梯像素观感；同时间多字在真实 ppms 下的命中顺序与溢出遮挡；组内拖动单字后脱离组、组重算的实机表现；缩小态与降级块无回归（本次未做真机目测）。

### 七、否决的备选方案

- **给组内 chip 写正 z-index 做层级**：会让 chip 逃逸到平面层、压住相邻块（块根普通态不构成堆叠上下文），比 DOM 顺序更危险。
- **在 LyricBlock 里重算阶梯宽度**：会把轮 1 的几何内核复制一份，且前端拿不到内容宽（`WordChipBox` 只有 `leftPx/widthPx`），只能反推，拉丁字符会偏。
- **保留合并再在组内切分**：即用户已驳回的方案②路线，多一层「先合再拆」的伪合并态。
- **非组首卡也渲染时间（灰色小字）**：会与阶梯叠加，视觉噪声大；改用等高占位。

**§8 新增挂账条目原文**
