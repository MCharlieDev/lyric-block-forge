### 二、红字原则口径澄清

- 清账轮那 6 条旧断言并非全是红字：l / o / j 三条是引用已删常量（`WORD_CARD_HANDLE_*`）导致 NaN 的**测试缺陷**；m / n / k 三条才是「断言仍有意义、只是几何口径被 R3 取代」的**真红字**。
- 分界固化进协作规程 §六：断言本身已失效（`NaN` / `undefined` / 引用不存在的导出 / 无法求值）属测试缺陷，必须当场修，不得攒成红字；只有「所描述的规则被新行为取代」才可保留为红字。
- 本切面「轮次 6 / 清账轮」原文写「6 条红字」是当时的从宽口径，**不回改切面**；以本节澄清为准，历史表述与现行口径保留一处已知不一致。

### 三、协作规程五处更新清单

- **§一.5**：新增第 5 条——归档是执行 Agent 的默认动作，决策 AI 不得就「是否允许归档 / 是否新建轮次文档 / 是否写 memory」「用极简、只写要点压缩七节模板」「以改动小、纯文档轮为由跳过归档」请示或设限；只规定正文与归档的先后顺序、以及归档不得覆盖哪些正文结果。
- **§二 · B 段模板【硬边界】**：新增一行——`docs/` 归档按 project_rules.md 归档豁免条款默认执行、不计入文件数；本轮若暂缓需显式写「本轮暂缓归档」并给理由。
- **§三【发货前自检】**：新增第 4 条——任务书里出现「暂缓归档 / 极简 / 只写要点 / 请裁决是否归档」字样即删掉再发；归档只许在【硬边界】写默认条款，不许写成待裁决项。
- **§五**：新增「对称义务」——执行侧的强制动作（归档、跑测试、报四段），决策侧必须有对应的「不得削弱」条款；只写「必须做」不写「不得免」，规则会在第一次「情况特殊」时失效。
- **§六**：新增「红字原则的适用设定」——真红字与测试缺陷的分界，以及判交付时的归属（真红字进「已知取舍」，测试缺陷进「已验证」的修复说明）。
