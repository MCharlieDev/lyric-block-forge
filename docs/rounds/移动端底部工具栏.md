# 移动端底部工具栏 · 交接文档

> **用途**：记录轮 2d-1a 的背景、做法、验收与边界。配合主交接文档阅读。
> **状态**：✅ 已闭合。
> **基线**：harness 593/593（BN 16/16）；core vitest 208/208；tsc 退出码 0。
> **上游/依赖**：2c-1（窄屏隐藏 `ActivityBar`，手机端失去日志入口）、3a（顶栏移动端折叠）、3d（窄屏间距统一 4px）、4a（`env(safe-area-inset-bottom)` 避让）。

## 一、本轮范围

在 `ThreeColumnLayout` 根 flex 列内新增窄屏专用底部工具栏骨架：`日志` / `操作` 两个入口，点击各弹一条占位 Toast；不接面板、不做手势、不做 fixed 悬浮。属于「轮 2d（移动端底部工具栏 + 半屏面板）」的第一个子轮。

## 二、核心接口与契约变更（极其重要）

- **新增组件**：
  - `MobileToolbar`（`src/ui/layout/MobileToolbar.tsx`）：无 props，无入参、无出参；内部直接调用 `showToast`。用途：窄屏底部常驻两个入口的骨架。
- **数据模型/类型变更**：无。
- **DOM 契约（供 harness 依赖）**：
  - 新增 `<nav data-mobile-toolbar>`（仅 `isNarrow` 为真时进 DOM）。
  - 内部两个 `<button title="日志">` / `<button title="操作">`。
  - **禁止**给「日志」按钮写 `title="工作日志"`——`BN.b` 以该 title 判定「窄屏不渲染活动栏」。
- **既有文件接口变更**：无。`ThreeColumnLayout` 仅新增 import 与一行条件渲染，`isNarrow` / `PlaybackBar` / `LeftColumn` 全部未动。

## 三、关键设计与做法

1. **流内 flex 子项而非 fixed 悬浮**：`<nav>` 以 `h-12 shrink-0` 插在「第一行 flex-1 主内容」与「桌面 footer」之间。根节点是 `flex h-full flex-col overflow-hidden`，因此主内容行被**压缩**，不会产生溢出滚动，也不需要给歌词列表补 `padding-bottom`。
2. **安全区不叠加**：`index.css` 的 `#root > div > main > div { padding-bottom: calc(0.25rem + env(safe-area-inset-bottom)) }` 已作用在 `ThreeColumnLayout` 根节点上，底栏作为流内最后一项天然被托起。本轮**没有**在本组件再加 `env()` padding，避免双份留白；也**未改** `index.css`。
3. **等分扩展性**：`<nav>` 根不写 `justify-around` / `justify-between`；每个按钮自身 `flex h-full flex-1 items-center justify-center`。未来加第三个入口只需追加同样结构的按钮，无需改任何 CSS。
4. **条件渲染而非 CSS 显隐**：沿用 2c-1 的 `isNarrow` JS 闸门，桌面端**不产生**不可见 DOM（而非 `md:hidden` 常驻隐藏节点）。
5. **图标**：复用 `ActivityBar` 的内联 SVG 风格（`viewBox 0 0 24 24` + `fill="none"` + `stroke="currentColor"` + `strokeWidth 1.75` + `h-5 w-5`）；「操作」为临时手绘四向准星（circle + 四条刻度），不引图标库。
6. **占位反馈**：`showToast('日志功能开发中')` / `showToast('操作功能开发中')`。Toast 宿主在 App 顶层、位置为屏幕顶部居中，因此反馈出现在上方而非底栏附近——本轮接受这一错位。

## 六、已知取舍与未验证

- **取舍**：
  - 流内布局，非 fixed 悬浮（主内容被压缩，而非覆盖）。

## 七、否决的备选方案

- **挂载到 `App.tsx`**：可绕开 `main > div` 的 safe-area padding，但要改第三个业务文件、且拿不到 `isNarrow`，只能退化为 CSS 显隐（产生不可见 DOM），违反本轮边界。
- **`fixed bottom-0` + `z-30`**：视觉更像原生 App，但需同时改 `index.css` 的根 padding 公式（`calc(0.25rem + 底栏高 + env)`），且要处理 `env` 双份；本轮克制为流内。
- **纯 CSS `md:hidden` 显隐**：`ThreeColumnLayout` 零新增状态，但桌面 DOM 常驻隐藏节点，且 harness 只能改用 `getClientRects()` 软断言。
- **复用 `title="工作日志"`**：会让 `BN.b` 假红，已明确禁止。
- **按钮 `disabled` 占位**：语义「即将上线」最诚实，但 disabled 不可聚焦、与「常驻入口」观感相悖，且 harness 无法证明点击链路。

## 轮次 2d-1b：日志面板头部（全选 / 计数 / 撤销 + Ctrl+Z 接线）

> **用途**：记录日志面板头部重排与撤销快捷键接线。
> **状态**：✅ 已闭合。
> **基线**：harness 601/601（新增 BO 8/8）；core vitest 208/208；tsc 退出码 0。
> **上游/依赖**：轮 2d-1a 移动端底部工具栏骨架；A 段已核实「撤销最后一条」按钮既有、KeyZ 未占用、checkbox 在 blocksHotkeys 名单内。

### 一、本轮范围

把「撤销最后一条」从 `PanelFrame.actions` 移到页签下方新头部，新增「全选」与「已选 N 条 / 撤销所选 / 清空」，并把 `Ctrl/Cmd+Z` 接到「撤销最后一条」。

### 二、核心接口与契约变更

- **新增接口**：
  - `editorStore.selectEntries(ids: string[]): void`：整体写入 `selection.entryIds`（去重、保持传入顺序），不动 activeLineId / anchorLineId / logView。
- **修改接口**：
  - `editorStore.undoLastAction()`：`() => void` → `() => boolean`。无「生效中且可撤销」目标时返回 `false` 且不写 state，供 UI 决定是否 toast。
- **数据模型/类型变更**：无。
- **DOM 契约（供 harness 依赖）**：
  - 新增 `[data-log-header]`、`[data-select-all]`、`[data-selection-count]`、`[data-undo-last]`、`[data-undo-selected]`、`[data-clear-selection]`、`[data-restore-selected]`。
  - 移除底部批量操作栏（原「已选 N 条 / 批量撤销|恢复所选 / 清空选择」）。
  - `[data-select-all]` 部分选中时置 `aria-checked="mixed"` + `indeterminate`。

### 三、关键设计与做法

- 全选口径 = 当前页签 + 当前筛选下**可见但有勾选框**的条目；细行判定抽成组件内 `isThinEntry`，与传给行组件的 `thin` 同源，不在 store 复刻。
- 头部右侧互斥：无选中显示「撤销」；有选中显示计数 + 「撤销所选」（已归档页签为「恢复所选」）+「清空」。
- `undoLastAction` 的存在性判断与 core `undoLast` 同口径（`status === 'active' && isRevertable(kind)`），避免「先写 state 再发现没目标」。
- 快捷键：`KeyZ` 仅在 `Ctrl/Cmd` 下生效；`blocksHotkeys` 对 `checkbox` / `radio` 只对这一个组合豁免（Space 仍被拦，保住勾选框原生切换）；行编辑文本框内 `Ctrl+Z` 仍走原生撤销。
- 无目标反馈：`撤销` 按钮与快捷键共用「返回 false → `showToast('没有可撤销的记录')`」。

### 六、已知取舍与未验证

- 「撤销所选」的目标判定仍在 `undoSelectedEntries` 内部（无目标时给 store notice「所选记录中无可撤销项」），未改成返回 boolean —— 硬边界要求不改该 action，故与「撤销」的 toast 文案不完全统一。
- BO.f 的行编辑弹窗带 `role="dialog"`，`hasOpenDialog()` 也会拦截快捷键；该断言证明「不碰日志」，但未单独隔离「输入框豁免」这一条路径。
- 撤销语义 = 全量最近一条，与全选口径（当前可见）不同维，有意不一致。
- 头部与三组平铺筛选 chip 共存，垂直空间比 2d-1c 折叠后的最终形态高。

### 七、否决的备选方案

- 让 `undoSelectedEntries` 也返回 boolean：文案可统一，但违反「不改 undoSelectedEntries」硬边界。
- 点全选时在 store 内复刻 thin 判定：会让「细行」定义出现两处来源，后续改显示模式必漏一处。
- 把筛选弹层/头部加 `role="dialog"`：会触发 `hasOpenDialog()` 停掉全部快捷键（含 Space 打轴），故头部保持普通容器。

## 轮次 2d-1c：筛选折叠弹层 + 顶栏冗余入口清理

> **状态**：✅ 已闭合。

### 一、本轮范围

日志面板三组平铺筛选 chip 折叠为「筛选 ▾」按钮 + 弹层（Portal 挂 body，桌面下拉 / 窄屏贴底），非默认筛选时按钮 accent + 圆点；同时删除顶栏「分级回退」下拉、「撤销该类型全部记录」按钮与「共 N 条日志」计数。

### 二、核心接口与契约变更

- **新增组件**：`LogFilterPopover`，props `anchorRect: DOMRect`（触发按钮视口矩形，桌面定位）、`onClose: () => void`（Esc 关闭；遮罩点击由父级处理）。
- **store 复用**：读 `log` / `logView`，写 `patchLogFilter` / `setArchivedDisplay`；无新增 action。
- **DOM 契约（供 harness 依赖）**：
  - 新增 `[data-log-filter-toggle]`（筛选按钮）、`[data-filter-dot]`（非默认圆点）、`[data-log-filter-popover]`（弹层根）、`[data-filter-section="status|archived|kind"]`、`[data-filter-status="all|active|undone"]`、`[data-filter-archived="thin|hidden|normal"]`、`[data-filter-kind-all]`、`[data-filter-kind="<kind>"]`。
  - 遮罩沿用 `[aria-label="关闭筛选"]`（`fixed inset-0 z-10`，窄屏 `bg-black/40`）。
  - `[data-topbar-right]` 保留但清空；顶栏不再有 `select` 与「分级回退 / 撤销该类型全部记录 / 共 N 条日志」。

### 三、关键设计与做法

- **Portal 挂载**：`createPortal(..., document.body)`，摆脱 `LogPanel` 及未来 `BottomSheet` 的 `overflow-hidden` / `relative` 裁切。
- **响应式**：桌面用 CSS 变量 `--filter-top` / `--filter-left` 做 `md:top-[…]` / `md:left-[…]` 锚定在按钮下方，`left` 由 `Math.max(8, Math.min(anchorRect.left, innerWidth - 288 - 8))` 夹取防越界，`w-72` / `max-h-[70vh]`；窄屏 `<768px` 走 `max-md:inset-x-4 max-md:bottom-4 max-md:top-auto max-md:w-auto max-md:max-h-[60vh] max-md:z-50` 贴底。
- **触控热区**：chip 常量 `CHIP = 'rounded px-2 py-1 text-[11px] max-md:px-3 max-md:py-2 max-md:text-sm'`；分段间距 `space-y-1 max-md:space-y-2`，弹层整体 `space-y-2 max-md:space-y-4`。
- **非默认判定（圆点口径）**：`Boolean(filter.kinds) || (tab === 'all' && (Boolean(filter.statuses) || archivedDisplay !== 'thin'))`，只反映「当前页签真正生效」的筛选。
- **分段可见性**：状态段 / 已撤销段仅 `tab === 'all'` 渲染；类型段所有页签渲染。
- **快捷键安全**：弹层不带 `role="dialog"` / `aria-modal`，`hasOpenDialog()` 不会停掉编辑器快捷键。

### 一、本轮范围

给 `FilePort` 增加读取原生 `File` 对象的能力：新增 `readDroppedFile(file)`，内部复用 `openTextFile` 的 BOM / UTF-8 / GBK / docx 解析管道，不弹文件选择器、不返回 `null`；顺手把三处重复的解析分支收拢为模块私有 `decodeTextFile(file)`。本轮**只落底层能力，零 UI 接入**。

### 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `FilePort.readDroppedFile: (file: File) => Promise<TextFileContent>`：入参原生 `File`，返回已登记引用的 `TextFileContent`。用途：全局拖拽导入时把拖入的文件交给同一条解码 / docx 管道，免去 UI 层重复处理编码。
- **新增内部函数（不导出）**：
  - `decodeTextFile(file: File): Promise<{ text: string; encoding: string | null }>`：`isDocxFile ? { text: await readDocxText(file), encoding: null } : decodeBuffer(await file.arrayBuffer())`。
- **行为变更**：无。`openTextFile` 与 `readText` 的解析分支改为调用 `decodeTextFile`，逻辑逐字等价（同一三元表达式 + 同一组函数）。
- **数据模型/类型变更**：无新增字段，`TextFileContent` / `FileRef` 原样复用。
- **DOM 契约（供 harness 依赖）**：无变化（本轮零 UI 改动）。
- **破坏性变更**：`readDroppedFile` 为**必填**方法，接口层面不向后兼容；全仓仅 `createWebFilePort` 一个实现（`src/shells/desktop|mobile` 均为 throw 占位），故无其他调用点被打红。

### 三、关键设计与做法

- **闭包内落地**：实现写在 `createWebFilePort` 返回对象里，才能复用闭包内的 `register(file)` 注册表；`ref.uri = register(file)`，因此 `readDroppedFile` 拿到的 `ref` 可直接交回 `port.readText(ref)` 重读（与 `openTextFile` 的 ref 契约一致）。
- **消除三处重复**：`readText` / `openTextFile` / `readDroppedFile` 原本各自写一遍 `isDocxFile ? … : decodeBuffer(…)`，抽成 `decodeTextFile` 后只保留一份；`openTextFile` 的「用户取消返回 null」语义由外层 `pickFile` 判断，未受影响。
- **无对话框语义**：`readDroppedFile` 不存在「用户取消」，故返回类型是 `Promise<TextFileContent>` 而非 `Promise<TextFileContent | null>`；文件权限 / 读取失败仍以 reject 抛出，由调用方（3b 的拖拽层）决定 toast 文案。
- **ref 构造**：`name` / `sizeBytes` / `mimeType`（空串归一为 `null`）与 `openTextFile` 完全同口径，未引入第二套元数据映射。
- **单测环境适配**：`createWebFilePort()` 在构造时会读 `window.showSaveFilePicker` 计算 `supportsNativeSave`，vitest 为 node 环境无 `window`；在测试文件内 `vi.stubGlobal('window', {})` / `vi.unstubAllGlobals()` 兜底，**未为测试改生产代码**。

### 三、关键设计与做法

- **Portal 挂 body**：抽屉要脱离主内容行的 `overflow` 裁剪与 flex 高度约束，`createPortal(…, document.body)` 是最短路径；代价是抽屉不在 `App` 的 DOM 子树内（harness 只能用 `document.querySelector` 全局找）。
- **手势只绑把手**：`onPointerDown` 记 `startYRef = e.clientY`、`setDragging(true)`、`setPointerCapture(e.pointerId)`；`onPointerMove` 只取 `offsetY > 0` 的向下位移写入 `dragY`（向上拖不跟手、也不产生负位移）；`onPointerUp` 若 `offsetY > 150` → `onClose()`，否则 `setDragY(0)` 回弹；`onPointerCancel` 复位。
- **过渡切换**：拖动中 `style.transition = 'none'`（跟手无延迟），松手 `transform 200ms ease-out`（回弹有阻尼感）；用内联 `style` 而非 Tailwind 类，避免为两个状态新增 `data-*` / 条件类名。
- **`open` 复位**：`useEffect(() => { if (open) setDragY(0) }, [open])`，保证每次重新打开都从 0 开始，不会继承上次的拖拽残值。
- **层级**：遮罩 `z-40`（低于 Toast 的 `z-50`、确认框 `z-[45]`），面板 `z-50` 与 Toast 同档但区域不重叠；弹层类组件（如 `LogFilterPopover` 的 `z-20` 卡内下拉）将来放进抽屉时仍在面板内部。
- **`touch-none`**：把手加 `touch-none` 阻止移动端浏览器把下拉手势劫持成页面滚动，否则 `pointermove` 会被 `pointercancel` 打断。
- **不改全局 CSS**：所有尺寸 / 颜色走 Tailwind 内置类 + 主题变量（`bg-panel` / `border-divider`），未新增 `@keyframes` / 全局 `transform` 规则。
- **harness 稳定性**：`BN.n` 断言后主动点遮罩关闭，避免抽屉残留遮挡后续 `BN.o` 的「操作」按钮点击；BS 组用 `setDeviceMetricsOverride(375×667, mobile)` 进入窄屏、`finally` 恢复桌面视口。

### 三、关键设计与做法

- **缩放的跨组件桥接**：内核是 `TimelineStrip` 的 `useState` 私有实例，`OperationPanel` 与它是兄弟，拿不到引用；新建 Context 会多碰第 5 个文件。故在 `useTimelineViewport.ts` 内加模块级 `activeKernel`，由 `useTimelineViewportKernel` 的 effect 登记 / 注销（注销时判 `activeKernel === kernel`，避免并发挂载互相抹掉），并导出 `zoomActiveTimeline`。
- **锚点口径（对任务书公式的显式偏离）**：任务书给的公式用 `snapshot.windowStartMs`，但该字段是 `RenderWindow` 起点 —— `OVERSCAN_RATIO = 1`，窗口在视口左右各外扩**一整屏**，照抄会让 `rawXPx` 恒 ≥ 一屏宽、被夹到右边缘（缩放永远绕右边缘跳）。实现改用 `getFrame().view.startMs`（视口左边缘，正是各图层当前绘制所用值），再按任务书要求夹紧 `[0, viewportWidthPx]`。
- **速率菜单内联展开**：`BottomSheet` 内容区是 `flex-1 overflow-y-auto`，绝对定位 popover 会被裁切；抽屉只有 85vh、下方还有方向键与播放键，向上弹也不稳。故速率做成「点按钮 → 面板内多出一行 6 个 chip → 点档位写入并收起」，代价是约 40px 布局跳动。
- **方向键复用命令层的两套语义**：← / → 走 `nudgeSelection(∓10)`（有字级游标动单字、否则动整行、含未打轴行会 toast 拒绝）；↑ / ↓ 走 `moveSelection(∓1)`（移动选中行，字级游标跟着落点行）。不另写一套「纯 UI 游标」逻辑，避免与快捷键行为分叉。
- **播放 / 打轴与桌面同源**：`togglePlayback(adapters)`（无音频静默 return）与 `stampActiveLine(adapters)`（无选中 / 不可见静默 return，成功后选中推进到下一可见行），不在面板里重复判定业务边界。
- **热键不会双触发**：抽屉面板带 `role="dialog"` / `aria-modal`，`useEditorHotkeys` 的 `hasOpenDialog()` 会停用全部全局快捷键；面板按钮只绑 `onClick`，因此空格 / 箭头不会与按钮重复执行。
- **触屏细节**：所有按钮 `type="button"` + `select-none touch-manipulation`（防长按选中文字与双击缩放），方向键区 `h-40` 保证单键高度 ≈ 76px；音量图标为内联 SVG（全仓无图标库）。
- **harness 稳定性**：BT 组沿用 BS 的 `375×667 mobile` + `try/finally` 恢复桌面视口；BT.b 断言后把 `playback.rate` 还原为 1，避免污染后续用例；BT.c 点遮罩时必须同时验「面板移除 + 遮罩移除」，否则残留遮罩会挡住后续点击。

### 七、否决的备选方案

- **新建 Context / 全局单例 bridge 文件暴露内核**：会多碰第 5 个文件（并可能动 `TimelineStrip`），超出硬边界；且内核本就该由时间轴独占，加 Context 会扩散耦合。改在 `useTimelineViewport.ts` 内做最小桥接。
- **照抄任务书的 `snapshot.windowStartMs` 锚点公式**：`OVERSCAN_RATIO = 1` 使该值是「视口左边缘再向左一屏」，锚点会被夹到右边缘、缩放明显跑偏，故改用 `getFrame().view.startMs`。
- **速率用绝对定位 popover / 原生 `<select>`**：popover 会被 `BottomSheet` 的内容区 `overflow-y-auto` 裁切；原生 `<select>` 在移动端弹系统选择器、样式不可控且难断言，故用内联 chip 行。
- **在 `OperationPanel` 里读设置 / 复刻 `PlaybackBar` 的滚轮音量**：本轮 UI 无任何设置项依赖（故未引入 `useSettingsStore`，否则成未使用变量触发 tsc 报错），滚轮调音量在触屏上也无意义，故只保留滑块。
- **面板自建 `setPlayhead` / 打轴逻辑**：会与 `editorCommands` 的唯一实现分叉，且绕过「音频时钟是唯一基准」的架构约定，故一律走命令层。

### 三、关键设计与做法

1. **去遮罩即事件穿透**：删除 `fixed inset-0 z-40` 遮罩节点后，面板只覆盖自身矩形（`z-50`），上方区域没有任何 DOM 拦截点击，背后时间轴与波形天然可交互。`touch-none` 只留在把手上，不限制内容区滚动。
2. **三档偏移的计算口径**（全部以「面板未位移时的基准顶 `baseTop`」为参照）：
   - 档位一 `0` —— 80vh 全展开；
   - 档位二 `cardBottom - baseTop` —— ~~波形下边缘~~ **时间轴卡片底边（补充修正 1 改写）**，读不到 `[data-timeline-strip]` 时回退 `innerHeight * 0.45 - baseTop`；
   - 档位三 `innerHeight * 0.7 - baseTop` —— 面板高度固定 30vh。
   - 三者 `Math.max(0, …)` 后**强制升序排序**，且**绝不做间距合并**（补充修正明确要求保留三个独立吸附点）。实测 667 屏上排序结果为 `[0, 214.67, 333.49]`（补充修正 1 换锚点后）。
3. **`baseTop` 必须抵消 transform**：面板用 `transform: translateY(dragY)` 下移后 `rect.top` 会跟着变，故 `measureSheet` 用 `rect.top - dragY` 还原基准顶；`dragY` 从 state 读会滞后，故维护 `dragYRef` 镜像。
4. **从吸附位继续拖不跳回顶部**：新增 `startOffsetRef` 记录按下瞬间已有位移，`pointermove` / `pointerup` 一律算 `Math.max(0, startOffsetRef.current + clientY - startY)`（**补充修正 1 修正了 `Math.max` 的位置**，详见文末）。
5. **重测时机**：`open` 变 true 时与 `pointerdown` 时各测一次（分析轨 / 歌词块高度会改变波形底边）。未接 `ResizeObserver`，视口旋转不会自动重测（已入挂账）。
6. **关闭判定**：`visibleHeight = panelHeight - offsetY`，若 `< innerHeight * 0.1` 则先 `applyDrag(0)` 复位再 `onClose()`，避免下次打开带着旧位移；否则吸附到 `nearestStop`。
7. **收起按钮不冒泡**：按钮与 `[data-sheet-handle]` 是兄弟节点（外层 `div.relative` 包裹），且不在把手内部，因此点击不会触发 `pointerdown` 的拖拽链路。
8. **harness 必须走 CDP 真实鼠标**：合成 `PointerEvent` 触发 `setPointerCapture` 会抛 `InvalidPointerId`，故新增 `dragSheetDown(cdp, dy, steps = 6)`：读把手中心 → `pressAt` → 循环 `moveTo`（每步 `sleep(25)`）→ `releaseAt` → `sleep(300)` 等吸附动画。

## 补充修正 1：修复上拖 Bug + 档位锚点改为整个时间轴卡片

修复「从非 0 档位向上拖拽失效」的手势 Bug，并把吸附档位二的锚点从「波形层底边」纠正为「整个时间轴卡片（`TimelineStrip`）底边」。

### 二、核心接口与契约变更

### 三、关键设计与做法

1. **Bug 根因**：原写法 `startOffsetRef.current + Math.max(0, clientY - startY)` 把「向上拖的负增量」直接夹成 0，导致从任一非 0 档位向上拖时位移恒定不变（视觉卡死）。
2. **修法**：只对**总位移**夹 0 —— `Math.max(0, startOffsetRef.current + clientY - startY)`，允许增量为负，同时保证面板不被顶出屏幕。
3. **`pointerup` 必须同步**：若只在 `move` 修、`up` 仍用旧式，向上拖后松手会按「忽略向上位移」的旧值吸附，产生一次跳回。故 `handlePointerUp` 的 `offsetY` 也改为同一公式。
4. **锚点语义纠正**：需求里的「波形图底下」指整个时间轴卡片底边（含波形 + 歌词拖动轨），露出内容比只看波形层更多；`TimelineStrip` 是卡片根节点，`getBoundingClientRect().bottom` 即其下边缘。

## 轮次 2d-6：移动端高度分割线（拖拽调整上下高度占比）

> **用途**：记录本轮的背景、做法、验收与边界。配合主交接文档阅读。
> **状态**：✅ 已闭合。
> **基线**：harness 625/625；core vitest 211/211；tsc 退出码 0。
> **上游/依赖**：承接 2d-5（多档吸附 + 手势四件套）；复用 `showPlaybackBar` 这一「窄屏」闸门，不新增布局层。

### 一、本轮范围

窄屏下在「波形 + 播放条」与「歌词列表」之间加一条可拖拽分割线，实时调整两者高度占比，双向各保留 20%，松手停在当前位置。

### 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `LeftColumn` 内部无新 props；`showPlaybackBar`（已有）语义**扩展**为「是否渲染高度分割线」。
  - `DragSnapshot`（组件内 interface）：`{ startY: number, startTopPx: number, sectionH: number, extras: number }`。用途：按下瞬间的快照，避免拖动过程中反复测量。
- **修改接口**：
  - `LeftColumn` 根节点 `<section>` 增加 `ref`（供 `clientHeight` 与 `rowGap` 读取），并新增上下两区的显式高度分配（此前完全由子组件自身 flex 决定）。
- **数据模型/类型变更**：无（比例只存组件内 `useState`，不进 `AppSettings`）。
- **DOM 契约（供 harness 依赖）**：
  - 新增 `[data-column-top]`：上区容器（`TimelineStrip` + 窄屏 `PlaybackBar`），`height = ratio × section.clientHeight`。
  - 新增 `[data-column-splitter]`：分割线热区，属性 `role="separator"` / `aria-orientation="horizontal"` / `aria-label="调整歌词列表高度"`；下拉 `py-2` + 内部 `h-0.5` 线，实测 **18px**。
  - 窄屏渲染顺序：`[data-column-top]` → `[data-column-splitter]` → 歌词面板；桌面端无分割线，`[data-column-top]` 内只有 `TimelineStrip`。
  - `[data-timeline-strip]`（2d-5 引入）保持不变，仍只由 `TimelineStrip` 根节点提供。

### 三、关键设计与做法

1. **不用 grid，用内联 `flex-basis` 百分比**：`[data-column-top]` 写 `style={{ flex: '0 0 ' + ratio*100 + '%' }}`，下区 `LyricBlockPanel` 的 `PanelFrame` 自带 `flex-1` 吃剩余。百分比基准是 `<section>` 的内容盒高度，旋转 / 地址栏收起 / 软键盘弹起后占比不变，无需 `ResizeObserver`。
2. **存 ratio 而非 px**：拖动中按 px 计算（`startTopPx + dy`），松手后的 state 已经是比值，渲染即用，天然自适应。
3. **`extras` 不写死**：按下时实测分割线 `getBoundingClientRect().height` + `getComputedStyle(section).rowGap * 2`。窄屏 `gap-1`（4px）与宽屏 `gap-3` 都不必写死，分割线后续改高度也不会失准。
4. **夹紧公式**：`top ∈ [0.2·H, 0.8·H − extras]`。上限减 `extras` 是因为分割线 + 两段 gap 不参与两区高度分配——不减就会让下区实际只剩 `0.2H − 26px`。
5. **触摸拦截**：分割线与时间轴 / 列表是**兄弟**节点，事件只向祖先冒泡，天然不存在「冒泡进时间轴」的路径；真正要防的是「手指拖出分割线后落到别处」→ `setPointerCapture` 把后续 move/up 锁在分割线上。`touch-none` 让浏览器不把纵向拖动当页面滚动，`select-none` + `preventDefault` 防选中文字。
6. **未引入 `useEffect`**：任务清单写的是「引入 useState、useRef、useEffect」，但本轮没有任何副作用需求（无 resize 监听），`tsconfig` 开着 `noUnusedLocals`，多引一个未使用的 `useEffect` 会直接编译失败，故只引 `useRef` / `useState`。
