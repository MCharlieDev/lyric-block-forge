## 轮次 1：行首拖动（推土机逻辑）

### 一、本轮做了什么

放大态下，单时间戳歌词块左缘 4px 热区可拖动改行首时间：拖动中块左缘跟随鼠标、字卡在屏幕上保持不动，松手把新行首以一条 `absolute` 操作落盘（复用 `stampLine`），不动任何字级时间戳。

### 二、核心接口与契约变更

- **新增接口**：
  - `dragBlockEdge(cdp, id, dx, mid?)`（harness）：起拖点 = `__lrc.point(id, -8)`（块左缘 + 2px，落在 4px 热区内），依次 press → move(dx/2) → move(dx) →（可选 `mid` 回调取样）→ release。用途：给 BE 组提供能命中热区的拖动原语。
  - `chipLeftExpr(id)` / `wordInnerTransformExpr(id)`（harness 表达式）：读取块内 `[data-word-chip]` 的 `getBoundingClientRect().left`、`[data-word-inner]` 的 inline `transform`。用途：断言「字卡屏上不动」与「反向 transform 已清零」。
  - `tests/stores/editorStore.dragStart.test.ts`：2 条落盘契约断言（`stampLine` 的 `absolute` / 仅行级；undo 复原行首）。
- **修改接口**：
  - `DragMode`：新增 `'line-start'`。
  - `DragSession`：新增 `pressedWidthPx?: number`（按下时块宽，拖动中算 `width` 用）、`lineStartOrigin?: { left: string; width: string }`（按下时 inline 原值，用于还原声明式样式）、`lineStartInner?: HTMLElement | null`（内层定位容器，用于反向 transform）。
- **数据模型/类型变更**：无（未碰 `src/core/`）。
- **DOM 契约（供 harness 依赖）**：
  - 新增 `[data-line-start-handle]`：块根末尾的 `span`，`absolute inset-y-0 left-0 w-1 cursor-ew-resize`，仅 `mode === 'word' && !isDegraded && times.length === 1` 时渲染。
  - 新增 `[data-word-inner]`：word 模式内层相对定位容器（原 `relative h-full w-full overflow-visible pt-1` div），承载 `translate3d(-dx,0,0)`。
  - 无已删除 selector。

### 三、关键设计与做法

1. **命中优先级**：`handlePointerDown` 里先判 `closest('[data-line-start-handle]')`，命中且该行 `times.length === 1` 则建立 `mode:'line-start'` 会话并 `return`，位于字卡分支之前——保证 4px 热区优先于 chip 命中，且不会误入字卡拖动。
2. **框动字不动（命令式）**：拖动中零 store 写入。块根 `style.left = startMs×ppms + dx`、`style.width = 按下宽 − dx`（`Math.max(0, …)` 防负宽）；内层 `[data-word-inner]` 施加 `translate3d(-dx,0,0)`，抵消块左移，使 chip 屏幕位置不变。`left`/`width` 是声明式 prop，React 不会在无重渲染时改写 inline，故必须自行记录并还原。
3. **会话样式清理**：`clearSessionStyles` 新增还原分支——有 `lineStartOrigin` 则把 `left`/`width` 写回按下时的原值，有 `lineStartInner` 则清 `transform`，并 `hideGuide()`。点击、阈值内拖动、越界都走这条路径，保证块不停歪。
4. **提交口径**：松手 `deltaMs = Math.round(dx / ppms)`；`|deltaMs| < DRAG_MIN_DELTA_MS(10)` 视为点击（只选中、不落日志）；否则 `stampLine(lineId, startMs + deltaMs)` —— 落到 `kind: 'manual-timestamp'`、`delta.mode: 'absolute'`、`values` 仅一条行级项（`wordIndex: null`），字级完全不动，一步撤销。
5. **负时间防护**：move/up 均先 `dx = Math.max(rawDx, -startMs × ppms)`，行首下限 0ms；up 另以 `targetMs < 0` toast 兜底。
6. **辅助线**：拖动中 `showGuide(startMs + dx / ppms)` 跟随新行首；`clearSessionStyles` / 松手统一 `hideGuide()`。
7. **harness 取样口径**：`setView(11500, 2200)` 后 `ppms ≈ 0.419`，此时仅 l0 在渲染窗口内，`__lrc.ppms()`（依赖 l0/l3 同时可见）不可用 → 改用 `viewInfo().pixelsPerMs`。起拖点用 `point(id, -8)`，并前置断言 `elementAt === id` 与 `elementFromPoint(...).closest('[data-line-start-handle]')`，防止热区没挂上却测成字卡拖动。

- **扩大热区到 6px**：否决——6px 会进一步侵占首字卡抓取区，且与任务书拍板的 4px 不一致。

## 轮次 2：推土机推平（补齐字级）

### 一、本轮范围

轮 1 松手复用 `stampLine`，只写行级项，被新行首越过的字卡仍停在旧时间（绝对定位下落到块左缘之外）。本轮新增 `setLineStartWithPush`，把「行级新起点」与「被越过的字级」打包进同一条 `absolute`，实现真正的推土机推平，且松手后一步撤销。

### 二、核心接口与契约变更

- **新增接口**：
  - `setLineStartWithPush(lineId: string, newStartMs: number): void`（`src/ui/stores/editorStore.ts`）：把行首移到 `newStartMs`；凡回放时间 `< newStartMs` 的字级一并写成 `newStartMs`。落一条 `kind: 'manual-timestamp'`、`delta.mode: 'absolute'`；`values[0]` 为行级项（`wordIndex: null`），其后为每个被推平的字级项。无被越过的字卡时转发 `stampLine`，语义与轮 1 完全一致。
- **修改接口**：
  - `LyricTrack` 的 `line-start` 提交路径：`stampLine(lineId, targetMs)` → `setLineStartWithPush(lineId, targetMs)`；`stampLine` 本身未改，仍服务未打轴单块拖动。
- **数据模型/类型变更**：无（未碰 `src/core/`）。
- **DOM 契约（供 harness 依赖）**：无新增/删除；BE 组改为读取既有的 `wordTimes` 与 `delta.values`。

### 三、关键设计与做法

1. **越界判定用回放值**：从 `get().replay` 用 `getReplayedWordTime(replay, lineId, i)` 读每个字级的当前时间，与 `Math.round(newStartMs)` 比较。不用文档基线，保证多次拖动叠加后仍以「当前生效时间」为准。
2. **一条操作打包行级 + 字级**：`values` 首项固定行级，后续每个被越过的字级都写 `timeMs = landedMs`。`absolute` 语义下，未被越过的字级不出现在 `values` 里，保持原值（不会被 offset 连带）。
3. **退化分支**：`pushedWordIndexes.length === 0` 直接 `get().stampLine(...)`，不复制粘贴一套日志构造；此时日志文案仍是「手动打轴」，行为与轮 1 逐字段一致。
4. **撤销链路零新增**：不新增 OperationKind、不改回放引擎；`undoLast` 失活该条后整体重放基线，行级与字级同时复原。
5. **拖动中口径不变**：仍然零 store 写入、块根 left/width 命令式 + 内层反向 transform；只有松手才落一条操作。
6. **harness 口径反转**：BE.b 原断言「字级全程未变」改为「被越过的字级 = 新行首」；同时把 `values 只含一条行级项` 改为「行级 + 被推平的每个字级」，并把「字卡屏上仍在原位」改为「首张字卡在块内偏移跟随推平后的时间」。fixture 无需加大 dx：`setView(11500, 2200)` 下 `ppms ≈ 0.419`、拖 50px ≈ 119ms，首字 12008 远早于新行首 12239，必然越过。

### 七、否决的备选方案

- **否决轮 1 的决定「推土机只动行首、字级完全不动」**：该决定让被越过的字卡留在块左缘之外，与「推土机」语义相悖；本轮以 `setLineStartWithPush` 取代 `line-start` 分支的 `stampLine` 调用。轮 1 记录保留为历史，其「只改行级」的描述在提交路径上已失效。
- **在 `LyricTrack` 里连发两条操作（先 stampLine 再逐字 setWordTimestamps）**：否决——会产生多条日志，撤销需多步，且中途状态可被观察到。
- **用 `offset` 平移被越过的字级**：否决——`offset` 会把所有字级（含未越界的）一起移动，须改用 `absolute` 精确列出越界项。
- **给 `stampLine` 加参数复用**：否决——会改变既有未打轴拖动路径的签名与语义；新增并列 action 更可控，也不破坏现有测试。

## 轮次 3：行首拖动接吸附（复用 `calculateSnapAndOffset` + 吸本行字级）

> **状态**：✅ 已闭合。
> **基线**：harness 575/575（新增 BL 14/14）；core vitest 207/207；tsc 退出码 0。
> **上游/依赖**：轮 1/2 的 `line-start` 拖动与 `setLineStartWithPush` 推土机；吸附内核（`snapOffsetPx` / `collectTargetsMs` / `calculateSnapAndOffset`）来自整块拖动，本轮直接复用。触发原因：§8 挂账「行首拖动未接吸附」；用户补充要求行首可吸附到**本行自己的字级时间**（如首字），以便精确对齐且不触发推平。

### 一、本轮范围

`line-start` 会话的 move / up 两个分支接入吸附内核；吸附候选额外加入被拖行自己的字级时间（行级自身排除），实现「行首吸到首字 = 对齐但不推平」。

### 二、核心接口与契约变更（极其重要）

- **新增接口**：无对外接口。
- **修改接口**：
  - `collectTargetsMs`：原入参 `(excludeTimesMs: number[])` → 现入参 `(excludeTimesMs: number[], lineStartLineId: string | null = null)`。修改原因：仅行首拖动会话需要把本行字级时间纳入候选，其他拖动口径不变。
- **数据模型/类型变更**：`DragSession` / `SnapResult` / `RowModel` 均未改（复用既有 `mode` / `pressedLineId` / `wordTimes`）。
- **DOM 契约（供 harness 依赖）**：无新增 / 删除 `data-*`；`[data-snap-guide]` 在行首拖动时也会写 `dataset.snapMs`（此前只有整块拖动会写），BL 组据此断言。

### 三、关键设计与做法

- **候选集扩展**：`calculateSnapAndOffset(rawPx, session)` 在 `session.mode === 'line-start'` 时把 `session.pressedLineId` 传给 `collectTargetsMs`；后者从 `rowsRef.current` 找到该行，把 `wordTimes` 的非空值推入候选，并用 `excludeTimesMs`（= 被拖行 `times`）排除与行级时间重合的值——否则行首会「吸到自己」导致恒命中、永远拖不动。
- **move 分支**：保留 `minDx = -pressedStartMs × ppms` 的负值下限，先夹出 `rawPx`，再 `calculateSnapAndOffset` 得 `{ offsetPx, snappedMs }`；块根 `left` / `width` 与内层反向 `transform` 三处几何全部改用 `offsetPx`，辅助线写 `snappedMs ?? pressedStartMs + offsetPx/ppms`（未命中时即裸落点，行为与旧版一致）。
- **up 分支**：同样先夹 `rawDx` 再算吸附，`targetMs = snappedMs ?? pressedStartMs + Math.round(offsetPx/ppms)`；点击阈值判定由「像素位移」改为「落点时间差 < `DRAG_MIN_DELTA_MS`」，避免「吸附把 3px 拖成 100ms 后仍判点击」的错位；负值 toast 守卫与 `setLineStartWithPush` 调用顺序不变。
- **为何吸到首字不推平**：`setLineStartWithPush` 只推平 `字级 < 新行首` 的字卡；新行首恰好等于首字时判定为 false，字级原样保留，天然实现「对齐但不推平」。越过首字（关吸附或继续右拖）才进入推平分支。
- **harness 口径**：BE 组写死 `expectedDeltaMs = round(50/ppms)`，接入吸附后裸落点可能被吸走 → BE 组首关吸附、组尾恢复，**既有断言与期望值一字未改**；吸附行为由新 BL 组覆盖（全部候选只留本行字级，避免其他候选干扰）。

### 四、改动文件清单

### 六、已知取舍与未验证

- **取舍**：行首吸附复用整块拖动的 8px 阈值与候选集，额外加入「本行字级时间」作为吸附目标；候选随设置开关（播放头 / 其他行 / 网格）叠加，本行字级不受 `snapToLineTimes` 控制（属行首拖动专属候选）。
- **取舍**：吸到首字后行首与首字重合，推土机判定 `< 行首` 为 False，因此不推平——这正是「对齐且不推平」的实现方式，但也意味着想推平必须越过首字。
- **取舍**：BE 组改为「关吸附」保持纯推土机断言；吸附行为由 BL 组覆盖，不改 BE 期望值。
- **未验证**：真机触控 / 触控板下的磁吸手感；一次拖动连续掠过多个字级时间时的辅助线跳变节奏；行首拖到播放头与其他行行首同时竞争时的吸附优先级（沿用最近距离，无优先级权重）。

### 七、否决的备选方案

- **（推翻 A 段设想）候选集只含播放头 / 其他行行首 / 网格线**：用户补充明确要求行首可吸本行字级（精确对齐首字），只靠外部候选无法完成；改为额外追加本行字级，并保留行级自身排除。
- **把本行字级候选挂在 `snapToLineTimes` 开关下**：否决——该开关语义是「其他行行首」，把行内字级混进去会让用户关掉行首吸附时连字级磁吸一起丢失；行首专属候选不受其控制。
- **up 分支继续用像素位移判点击阈值**：吸附会把 3px 的裸位移放大成上百毫秒时间差，仍按像素判会把「想吸到首字」误判为点击，否决。
- **不改 BE、直接更新 BE 期望值**：违反「严禁为全绿改断言」，且会把「吸附是否命中」与「推土机是否正确」两个变量耦合进同一组，否决。
