## 轮次 1：行首拖动（推土机逻辑）

### 一、本轮做了什么

放大态下，单时间戳歌词块左缘 4px 热区可拖动改行首时间：拖动中块左缘跟随鼠标、字卡在屏幕上保持不动，松手把新行首以一条 `absolute` 操作落盘（复用 `stampLine`），不动任何字级时间戳。

### 二、核心接口与契约变更

- **新增接口**：
  - `dragBlockEdge(cdp, id, dx, mid?)`（harness）：起拖点 = `__lrc.point(id, -8)`（块左缘 + 2px，落在 4px 热区内），依次 press → move(dx/2) → move(dx) →（可选 `mid` 回调取样）→ release。用途：给 BE 组提供能命中热区的拖动原语。
  - `chipLeftExpr(id)` / `wordInnerTransformExpr(id)`（harness 表达式）：读取块内 `[data-word-chip]` 的 `getBoundingClientRect().left`、`[data-word-inner]` 的 inline `transform`。用途：断言「字卡屏上不动」与「反向 transform 已清零」。
  - `tests/stores/editorStore.dragStart.test.ts`：2 条落盘契约断言（`stampLine` 的 `absolute` / 仅行级；undo 复原行首）。
- **修改接口**：
  - `DragMode`：新增 `'line-start'`。
  - `DragSession`：新增 `pressedWidthPx?: number`（按下时块宽，拖动中算 `width` 用）、`lineStartOrigin?: { left: string; width: string }`（按下时 inline 原值，用于还原声明式样式）、`lineStartInner?: HTMLElement | null`（内层定位容器，用于反向 transform）。
- **数据模型/类型变更**：无（未碰 `src/core/`）。
- **DOM 契约（供 harness 依赖）**：
  - 新增 `[data-line-start-handle]`：块根末尾的 `span`，`absolute inset-y-0 left-0 w-1 cursor-ew-resize`，仅 `mode === 'word' && !isDegraded && times.length === 1` 时渲染。
  - 新增 `[data-word-inner]`：word 模式内层相对定位容器（原 `relative h-full w-full overflow-visible pt-1` div），承载 `translate3d(-dx,0,0)`。
  - 无已删除 selector。

### 三、关键设计与做法

1. **命中优先级**：`handlePointerDown` 里先判 `closest('[data-line-start-handle]')`，命中且该行 `times.length === 1` 则建立 `mode:'line-start'` 会话并 `return`，位于字卡分支之前——保证 4px 热区优先于 chip 命中，且不会误入字卡拖动。
2. **框动字不动（命令式）**：拖动中零 store 写入。块根 `style.left = startMs×ppms + dx`、`style.width = 按下宽 − dx`（`Math.max(0, …)` 防负宽）；内层 `[data-word-inner]` 施加 `translate3d(-dx,0,0)`，抵消块左移，使 chip 屏幕位置不变。`left`/`width` 是声明式 prop，React 不会在无重渲染时改写 inline，故必须自行记录并还原。
3. **会话样式清理**：`clearSessionStyles` 新增还原分支——有 `lineStartOrigin` 则把 `left`/`width` 写回按下时的原值，有 `lineStartInner` 则清 `transform`，并 `hideGuide()`。点击、阈值内拖动、越界都走这条路径，保证块不停歪。
4. **提交口径**：松手 `deltaMs = Math.round(dx / ppms)`；`|deltaMs| < DRAG_MIN_DELTA_MS(10)` 视为点击（只选中、不落日志）；否则 `stampLine(lineId, startMs + deltaMs)` —— 落到 `kind: 'manual-timestamp'`、`delta.mode: 'absolute'`、`values` 仅一条行级项（`wordIndex: null`），字级完全不动，一步撤销。
5. **负时间防护**：move/up 均先 `dx = Math.max(rawDx, -startMs × ppms)`，行首下限 0ms；up 另以 `targetMs < 0` toast 兜底。
6. **辅助线**：拖动中 `showGuide(startMs + dx / ppms)` 跟随新行首；`clearSessionStyles` / 松手统一 `hideGuide()`。
7. **harness 取样口径**：`setView(11500, 2200)` 后 `ppms ≈ 0.419`，此时仅 l0 在渲染窗口内，`__lrc.ppms()`（依赖 l0/l3 同时可见）不可用 → 改用 `viewInfo().pixelsPerMs`。起拖点用 `point(id, -8)`，并前置断言 `elementAt === id` 与 `elementFromPoint(...).closest('[data-line-start-handle]')`，防止热区没挂上却测成字卡拖动。

### 六、已知取舍与未验证

- **取舍**：
  - line 模式（非放大态）不加 wrapper，低缩放下字随框微动（可接受）。
  - 4px 热区吃掉最左字卡左侧 4px 的抓取空间。
  - 行首跨过相邻行起点提交后，块可能跳泳道（两行分配算法的自然结果）。
  - 复用 `stampLine`，操作日志文案仍是「手动打轴」，不区分行首拖动。
  - 行首下限 0ms；仅 `times.length === 1` 的已打轴行渲染热区（多时间戳行与未打轴行无入口）。
- **未验证**：
  - 吸附未接入（A 段前置提到复用 `snapToPlayhead` / `snapToLineTimes` / `snapToGrid`，B 段清单公式未含，本轮按清单实现）。
  - 低缩放下「字随框微动」的视觉幅度未量化。
  - 真机高刷屏手感、触控（pen/touch）下的 4px 热区可点性未测。

### 七、否决的备选方案

- **给 line 模式也加 wrapper 承载反向 transform**：否决——会改变所有 line 模式块的 DOM 结构，为视觉边缘场景付架构代价；改为仅在 word 模式做「框动字不动」。
- **拖动中每帧写 store 再回滚**：否决——违反「拖动中零 store 写入」，会污染操作日志与撤销栈。
- **用 `nudgeLine`（offset）改行首**：否决——offset 会连带平移全部字级时间戳，与「推土机只动行首」冲突；必须走 `stampLine` 的 `absolute` 单值。
- **扩大热区到 6px**：否决——6px 会进一步侵占首字卡抓取区，且与任务书拍板的 4px 不一致。
