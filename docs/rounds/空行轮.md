## 一、本轮做了什么

让空行在「解析 → 序列化」之间无损往返（V3）。核心选择：**空行不进 `document.lines`**，另记在 `format.blankLines` 上。

## 二、关键设计

- `format.blankLines?: { leading?: string[]; beforeLine?: Record<lineId, string[]>; trailing?: string[] }`
- **行 ID 锚定**（不是下标）：导出走 `deriveVisibleLines` 子集、`remove-line` 属 replay 层，下标会位移。
- **存原文**：通常为 `''`，仅含空白字符的行也按空行处理并原样存回 → 字节无损。
- **三个写回点**：元数据块前（leading）/ 该歌词行前（beforeLine）/ 末尾（trailing）；终止换行仍由 `serializeLrc` 统一补。
- **终止符产物**：`split` 末尾那个 `''` 必须剔除（它是「以换行结尾」的产物，终止换行由 serialize 补），否则多写一个空行。
- **降级**：锚点行不存在（被删除 / 被双语合并吸收）→ 该批空行**丢弃**，不顺延、不累积。

## 四、已知取舍（两处有损）

- **元数据块内部空行不承载**：两条元数据行之间的空行有损（parse 处已留 `TODO(空行·未来扩展)`）。
- **双语合并吞噬锚点行 → 空行丢弃**：`mergePair` 保留主行 id、丢弃被动行；锚在其上的空行按「锚点消失」丢弃。
