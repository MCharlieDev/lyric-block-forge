# 字卡交互补全 · 交接文档

> **用途**：记录本轮的背景、做法、验收与边界。配合主交接文档阅读。
> **状态**：✅ 已闭合（轮 1：时间三位 / 字卡条横滚 / 3 字截断；轮 2：点行落游标 / 左右键字级微调 / 死区跟随滚动；轮 3：全局时间精度收敛）。
> **基线**：harness 561/561；core vitest 207/207；tsc 退出码 0。
> **上游/依赖**：字级空格打轴轮（`wordCursor` / `stampWordAt` / 字卡蓝光）。本轮只动展示层与格式化，不碰游标与微调内核。

## 一、本轮范围

行级时间标签与放大态字卡时间统一到三位毫秒；缩小态字卡条改为横向滚动容器并做 3 字截断（**缩小态字卡内不渲染时间**）。

## 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `formatTimecode3(ms: number): string`：出参 `mm:ss.mmm`（三位毫秒）；用途：行级卡片时间标签渲染 + 行宽测量入参。与 `formatTimecode`（两位）并存。
- **修改接口**：
  - `formatMiniTime(ms: number | null): string`：签名不变，输出由 `ss.xx` 改为 `ss.mmm`（三位毫秒）。
- **数据模型/类型变更**：无。
- **DOM 契约（供 harness 依赖）**：
  - 缩小态字卡条新增 `data-word-strip-scroll=""`（滚动容器），其子项仍为 `data-word-strip=""`、游标项仍带 `data-word-cursor`。
  - 行级时间标签文本由 `mm:ss.xx` 变 `mm:ss.mmm`；占位由 `--:--.--` 变 `--:--.---`。

## 三、关键设计与做法

- **不能改 `formatTimecode` 本体**：它还被 TimeRuler、日志描述、LogPanel、LyricBlockPanel 共 10 处调用，改本体会把尺子与日志一起变成三位。故新增 `formatTimecode3`，只作用于行级卡片渲染与 `measureLineWidths` 入参。
- **测量与渲染同步**：`LyricTrack` 传给 `measureLineWidths` 的 `timecode` 与 `LyricBlock` 实际渲染的标签同源（都用 `formatTimecode3`），避免块宽按两位估算、却渲染三位而溢出约 1 字符。
- **缩小态字卡条**：容器从 `overflow-hidden` 改为 `overflow-x-auto` + `[scrollbar-width:none] [&::-webkit-scrollbar]:hidden`，并打 `data-word-strip-scroll`；chip 由 `flexShrink:1` 改 `flexShrink:0`、`flexBasis:'auto'`，`flexGrow` 仍取 `chipSpans[index]` 作为剩余空间的分配权重；去掉单行截断 class（`truncate` / `whitespace-nowrap` 只留 `whitespace-nowrap` 于 chip）。
- **缩小态字卡文字**：`word.text.length > 3 ? word.text.slice(0, 3) + '...' : word.text`，并**彻底删除**该分支内的时间 span（用户补充修正：缩小态字卡绝不渲染时间，含 `formatMiniTime` 调用）。
- **放大态字卡**：chip 时间仍调 `formatMiniTime`，随函数改造自动变三位，无需另改渲染点。
- **未加手势横滑**：不加 `touch-pan-x`、不拦 wheel；触摸与滚轮走原生行为（纵滚为主），横滚位置仅由代码控制（轮 2 的游标居中滚动）。

## 六、已知取舍与未验证

## 七、否决的备选方案

- **改 `formatTimecode` 本体统一三位**：会连带 TimeRuler 刻度、日志描述、LogPanel、LyricBlockPanel 共 10 处变三位，超出本轮范围，否决。
- **缩小态字卡沿用等比压缩 + `overflow-hidden`**：窄缩放下单卡被压到不可读，且超出内容被裁掉无从查看，否决。
- **在缩小态字卡内叠一行时间**：A 段曾设想，用户补充修正明确否决——缩小态字卡内绝不渲染时间。

## 轮次 2：点行落游标 + 左右键微调 + 死区跟随滚动

> **状态**：✅ 已闭合。**基线**：harness 560/560（新增 BK 10/10）；vitest 207/207；tsc 退出码 0。

### 本轮范围

把字级游标下沉到缩小态：点行体落首字；有游标时左右键只微调该字；字卡条按死区平滑跟随游标，时间轴视口绝不跟随。

### 核心接口与契约变更

- **新增接口**：无（全部为既有动作 / 事件的接线）。
- **修改行为**：
  - `LyricTrack.handlePointerUp`：非拖动点击的行体 → `setWordCursor(lineId, 0)`（该行有切分时）；无切分则 `setWordCursor(null)`。
  - `LyricTrack.handlePointerDown`：**行体按下不再清空游标**（仅放大态字卡按下时落游标），否则整行拖动必然清掉游标，与 BK.b 冲突。
  - `editorCommands.nudgeSelection`：开头新增字级优先分支。
- **DOM 契约**：无新增属性；复用轮 1 的 `data-word-strip-scroll` / `data-word-strip` / `data-word-cursor`。

### 关键设计与做法

- **点击 vs 拖拽**：游标只在 `pointerup` 且 `!session.dragging` 时落下；指针捕获会把 `event.target` 重定向到平面容器，故用 `window.document.elementFromPoint(clientX, clientY)` 反查真实命中元素，排除 `[data-word-chip], [data-word-strip]`。
- **修饰键**：Ctrl / Meta / Shift / Alt 任一按下时不动游标。
- **字级微调优先**：`selection.lineIds.length <= 1` 且 `cursor.lineId === activeLineId` 且 `getReplayedWordTime(...) !== null` → `nudgeWordsByOffset(lineId, [wordIndex], deltaMs)` 后直接 return；否则保持原行级口径（多选仍整行移）。
- **死区跟随**：新增 `useEffect([wordCursor])`，按 `data-line-id` 找到当前行块与 `[data-word-strip-scroll]`、`[data-word-cursor]`；`scrollWidth <= clientWidth` 直接返回；否则用 `chip.offsetLeft - strip.offsetLeft` 换算内容坐标，左缘 < `scrollLeft + 25%` 或右缘 > `scrollLeft + 75%` 时 `scrollTo({ behavior: 'smooth' })`。只操作该 DOM 容器，不碰 kernel。
- **视口不跟随**：打轴是把播放头时间赋给字卡，字卡飞出屏幕属合理预期，明确禁止平推视口。

## 轮次 3：全局时间精度统一（`formatTimecode` 收敛三位 + 删除 `formatTimecode3`）

> **上游/依赖**：轮 1 为隔离风险，保留两位 `formatTimecode` 并另开 `formatTimecode3`。用户确认刻度尺空间足够后，本轮正式收敛。

### 本轮范围

把 `formatTimecode` 本体改成三位毫秒（`mm:ss.mmm`），删除轮 1 的临时函数 `formatTimecode3`，三处调用点回归；导出层不受影响。

### 核心接口与契约变更

- **删除接口**：
  - `formatTimecode3(ms: number): string`：整个函数与导出删除；其职责并回 `formatTimecode`。
- **修改接口**：
  - `formatTimecode(ms: number): string`：出参由 `mm:ss.xx`（百分秒）改为 `mm:ss.mmm`（三位毫秒）。修改原因：全局统一时间精度。
- **数据模型/类型变更**：无。
- **DOM 契约（供 harness 依赖）**：无新增 / 删除 `data-*`；行级时间标签文本变为 `mm:ss.mmm`（占位仍 `--:--.---`）。

### 关键设计与做法

- **单一出口**：`formatTimecode` 是全 UI 唯一的时间码出口（刻度尺 / 侧边列表 / 日志描述 / 行级卡片 / 行宽测量共 11 处调用点），改本体即全局收敛；`formatDuration`、`formatMiniTime` 本就三位，未动。
- **测量与渲染同源**：`LyricTrack` 传给 `measureLineWidths` 的 `timecode` 与 `LyricBlock` 渲染的标签都走 `formatTimecode`，块宽不会按旧两位估算而溢出。
- **导出解耦**：导出仍走 `settings.timestampPrecisionMs` + core `buildExportText`，与 UI 格式化完全无关（V 组「两位」断言保持 `.xx`，属正确预期）。
- **布局只读排查**（不改样式）：`TimeRuler` 刻度间距 `LABEL_MIN_GAP_PX=96px` 远大于 9 字符标签（10px mono ≈ 54px）；`LyricBlockPanel` 时间列 `w-20`=80px，9 字符 ≈ 59px 可容纳；`LogPanel` 描述行是 `truncate` 单行省略、展开区自然换行。三处均无需调样式。
