> **用途**：记录「字级视图重设计」大功能的背景、做法、验收与边界。配合主交接文档阅读。
> **状态**：R2a、R2b-1 已闭合；R2b-1a（几何内核修正）已落地但保留 6 条预期红字，R2 未闭合。
> **基线**：harness 444/444（R2b-1a 未重跑）；core vitest 120/126（6 条预期红字）；tsc -b --noEmit 退出码 0。
> **上游/依赖**：歌词卡片长度优化（textMeasure / 两行排版 / 末块封顶）已闭合；enhanced LRC 字级数据已在 core 层就绪。

## 轮次 1：R2a · 排版内核（零 UI 接线）

### 一、本轮范围

为放大态字级卡片建立纯内核排版能力：字级 chip 的合并、测量、内容宽计算与降级判定，不接 UI。

### 二、核心接口与契约变更

- **新增接口**：
  - `deriveDisplayChips(wordTimestamps, wordTimes)`：入参 `WordTimestamp[]` + `Array<number | null>`，出参 `DisplayChip[]`。用途：把同时间的相邻字合并为一个显示 chip，`null` 不合并且排最后。
  - `computeLineWidths(input, measureText)` / `measureLineWidths(input)`：`LineMeasureInput` 新增 `wordTexts?: readonly string[]`，输出新增 `wordRowWidthPx`。
  - `layoutBlock(input)`：`BlockLayoutInput` 新增 `mode?: BlockCardMode` / `wordRowWidthPx?: number | null` / `degradeEnabled?: boolean`，输出新增 `isDegraded`。
  - `layoutRows(items, ppms, durationMs, rowCount)`：`RowLayoutItem` 新增 `mode?` / `wordRowWidthPx?` / `degradeEnabled?`，`RowLayoutEntry` 新增必填 `isDegraded`。
- **修改接口**：
  - 无（R2a 只做增量，既有 line 口径不变）。
- **数据模型/类型变更**：
  - 新增 `BlockCardMode = 'line' | 'word'`、`DisplayChip { text, timeMs }`。
- **DOM 契约（供 harness 依赖）**：
  - 无（R2a 不接 UI）。

### 三、关键设计与做法

- word 内容宽 = `wordRowWidth + 12（把手）+ 4（间隔）`，再加 14 chrome；`minWidth = max(40, 12 + 4 + 22 + 14)`。
- chip 宽 = `max(measure(text, 'chip') + 8, 22)`，chip 间距 `CHIP_GAP_PX = 2`；探针样式为 `text-xs`。
- 降级判定：`mode === 'word' && degradeEnabled && cap < 52 && contentWidth > cap` → 宽度置 `14`、`isDegraded = true`。
- 两阶段排版保持：第一遍无 cap 定行号，第二遍按同行邻居压缩；降级只发生在第二遍。
- `deriveDisplayChips` 纯函数：按 `timeMs` 升序、`null` 排最后、严格相等才合并，不修改入参。

### 五、验收证据

- **tsc**：`npx tsc -b --noEmit` 退出码 0
- **vitest**：102 → **126/126**
- **harness**：维持 **444/444**
- **关键断言/实测**：word 宽 / 降级宽 / chip 合并顺序与最小宽均有单测覆盖。

### 六、已知取舍与未验证

- **取舍**：`WORD_CARD_DEGRADE_ENABLED` 默认 `false`，降级能力先具备、由后续轮次决定是否默认开启。
- **未验证**：真实浏览器字体下的 chip 累计宽与 Canvas 探针的偏差（仅单测注入测量函数）。

### 七、否决的备选方案

- 让 chip 行继续 `flexGrow` 按时间铺满：无法表达字级时间边界，否决。
- 在 UI 层临时测量：会破坏「测量单例 + 缓存」口径，否决。

## 轮次 2：R2b-1 · 放大态 UI 接线 + 拖动拦截 + 菱形降级

### 一、本轮范围

把 R2a 内核接到 `LyricTrack` / `LyricBlock`：`ppms >= 0.30` 且有字级的行切换为 word 卡片（左把手 + 字块），chip 区按下只选中不拖动，极窄块降级为菱形且整块即把手，辅助线锚定菱形中心。

### 二、核心接口与契约变更

- **新增接口**：
  - `calculateSnapAndOffset(rawPx, session)`（LyricTrack 内部）：出参 `{ offsetPx, snappedMs, anchorPx }`。用途：move 与 up 共用同一吸附口径，降级块统一加减 7px 菱心偏移。
- **修改接口**：
  - `showGuide(ms)` → `showGuide(ms, anchorPx = 0)`。修改原因：降级块辅助线需锚定菱形中心而非块左缘。
  - `LyricBlock` props：新增 `mode: BlockCardMode` / `chips: DisplayChip[]` / `isDegraded: boolean`。
- **数据模型/类型变更**：
  - `RowModel` 新增 `chips: DisplayChip[]`。
  - `LaidOutRow` 新增 `mode: BlockCardMode` / `isDegraded: boolean`。
  - `DragSession` 新增 `pressedIsDegraded: boolean`。
- **DOM 契约（供 harness 依赖）**：
  - word 模式新增 `[data-drag-handle]`（左侧 12px 把手）。
  - 降级块在根节点新增 `data-drag-handle=""`（整块即把手）。
  - line 模式 DOM、类名与尺寸完全不变。

### 三、关键设计与做法

- **模式判定**：`isExpanded = ppms >= WORD_CARD_PIXELS_PER_MS`；`wordMode = isExpanded && chips.length > 0`；测量时传 `wordTexts`，`RowLayoutItem` 填 `mode` / `wordRowWidthPx` / `degradeEnabled`。
- **拖动拦截**：pointerdown 时从 `laidOutRef` 读最新排版；word 模式下 `event.target.closest('[data-drag-handle]') === null` 即 chip 区，强制走 click 会话（保留 Ctrl/Shift 多选语义），仅把手可拖。
- **降级块**：14px 宽、整块即把手；内部只渲染 8px `rotate-45` 菱形（对角线 11.31px < 12px 内宽），不渲染信息行/正文/译文。
- **辅助线锚点**：菱形中心距块左缘 = 1（border）+ 6（padding）= 7px = `WORD_CARD_DEGRADED_WIDTH_PX / 2`。move 与 up 都走 `calculateSnapAndOffset`：`snapOffsetPx(raw + 7)`、`offset = snap.offsetPx - 7`；未命中时辅助线锚 `start + raw/ppms` 且 `anchor = 7`。
- **辅助线时机**：降级块 pointerdown 立即显示（`blocked` 模式除外），松手隐藏；非降级保持原「命中才显示」。
- **`laidOutRef`**：与 `rowsRef` 同为 render 期同步，避免为拖动状态机重绑事件。

### 四、改动文件清单

| 文件 | 改动内容 | 影响范围/关联模块 |
| :--- | :--- | :--- |
| `src/ui/timeline/LyricTrack.tsx` | imports / RowModel.chips / LaidOutRow.mode+isDegraded / rows 派生 chips / laidOut 派生 wordMode / laidOutRef / showGuide anchor / DragSession.pressedIsDegraded / calculateSnapAndOffset / pointerdown 拦截与显示 / pointermove / pointerup 复用 / 渲染透传 | 放大态渲染、拖动会话、辅助线 |
| `src/ui/timeline/LyricBlock.tsx` | props 三新增 / 根节点条件类与 `data-drag-handle` / 三分支内容渲染 / 降级菱形 | 卡片视觉与拖动命中区 |

### 五、验收证据

- **tsc**：`npx tsc -b --noEmit` 退出码 0
- **vitest**：通过数 **126/126**
- **harness**：**444/444，0 失败**；重点 `AZ` 9/9（`AZ.e` 在 `ppms=0.5` 仍可从 `left+10` 命中把手拖动）、`BA` 13/13（`ppms≈0.1537`，line 模式零回归）
- **关键断言/实测**：`git status --short` 恰 2 个业务文件；line 模式根节点 className 拼接结果与改动前字符串一致。

### 六、已知取舍与未验证

- **取舍**：降级态 move/up 两处都做 ±7px 的 `anchorPx` 偏移，保证菱心对齐目标时间。
- **取舍**：word 模式不渲染正文/信息行/译文，只保留把手与字块。
- **取舍**：降级态整块即把手（`data-drag-handle` 在根节点）。
- **取舍**：chip 区按下走 click 会话、不触发拖动，保留多选。
- **取舍**：辅助线在降级态 pointerdown 时立即出现，松手隐藏。
- **取舍**：8px 菱形旋转后对角线 11.31px，刚好塞进 12px 内宽。
- **取舍**：生产默认 `ppms = 0.02`，零视觉变化；仅在 `ppms >= 0.3` 时进入 word。
- **未验证**：降级块的真实构造（需极近相邻行）由用户人工目测；触屏长按与指针取消路径未专项复测。

### 七、否决的备选方案

- 在 chip 区按下也启动拖动：会与「点字块只选中」冲突，且破坏多选语义，否决。
- 降级块用伪元素/额外容器扩大命中盒：会增加 DOM 与层级复杂度，不如让根节点整块即把手，否决。
- 辅助线统一锚块左缘（不做 +7）：降级时辅助线会偏离菱形中心，视觉上误导吸附目标，否决。
- move 与 up 各写一份吸附算术：易漂移且难维护，改为抽 `calculateSnapAndOffset` 单一来源，否决复制粘贴方案。

## 轮次 3：R2b-1a · 几何内核修正（去左把手 + 降级阈值对齐）

### 一、本轮范围

把 word 模式的几何内核从「左把手 12 + 间隔 4 + chrome 14」改为「无左把手 + chrome 8」，并把降级阈值从 52 对齐到新的最小块宽 40；同时把「允许红字、禁止改测试凑绿」写入协作规则。

### 二、核心接口与契约变更

- **新增接口**：无。
- **修改接口**：
  - 无函数签名变更；`layoutBlock` 的 `mode: 'word'` 分支语义变更：`contentWidthPx = wordRowWidthPx + 8`，`minWidthPx = max(40, 22 + 8) = 40`。
- **数据模型/类型变更**：无。
- **DOM 契约（供 harness 依赖）**：本轮无 DOM 变更（UI 仍渲染旧 12px 左把手，属过渡态）。
- **常量契约**：
  - 删除 `WORD_CARD_HANDLE_WIDTH_PX`、`WORD_CARD_HANDLE_GAP_PX`。
  - `WORD_CARD_DEGRADE_CAP_PX`：52 → 40。

### 三、关键设计与做法

- chrome 新口径：左 border 1 + 左 padding 0 + 右 padding 6 + 右 border 1 = 8；line 模式仍用 `BLOCK_CHROME_X_PX = 14`，互不影响。
- 最小可用宽同步下调为 40（最小 chip 22 + chrome 8），保证 40~51 区间不再被错误降级。
- 降级判定公式不变，仅阈值变化：`mode === 'word' && degradeEnabled && cap < 40 && contentWidth > cap` → 宽 14。
- 测试红字按预期保留：旧断言仍引用已删除常量或旧公式，未修改任何 `tests/` 文件。
