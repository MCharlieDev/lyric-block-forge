# 字级视图重设计 · 交接文档

> **用途**：记录「字级视图重设计」大功能的背景、做法、验收与边界。配合主交接文档阅读。
> **状态**：R2a、R2b-1、R2b-1a、R2b-1b/1c、R3（R3a / R3b / R3c-1 / R3c-2 / R3c-3）均已闭合；6 条预期红字保留，R3 微型时间轴闭环。
> **基线**：harness 444/444；core vitest 143/149（6 条预期红字）；tsc -b --noEmit 退出码 0。
> **上游/依赖**：歌词卡片长度优化（textMeasure / 两行排版 / 末块封顶）已闭合；R2 提供 chip 合并、测量与降级内核；R3 在其上完成「时间 → 像素」绝对定位与字级拖拽。

## 轮次 1：R2a · 排版内核（零 UI 接线）

### 一、本轮范围

为放大态字级卡片建立纯内核排版能力：字级 chip 的合并、测量、内容宽计算与降级判定，不接 UI。

### 二、核心接口与契约变更

- **新增接口**：
  - `deriveDisplayChips(wordTimestamps, wordTimes)`：入参 `WordTimestamp[]` + `Array<number | null>`，出参 `DisplayChip[]`。用途：把同时间的相邻字合并为一个显示 chip，`null` 不合并且排最后。
  - `computeLineWidths(input, measureText)` / `measureLineWidths(input)`：`LineMeasureInput` 新增 `wordTexts?: readonly string[]`，输出新增 `wordRowWidthPx`。
  - `layoutBlock(input)`：`BlockLayoutInput` 新增 `mode?: BlockCardMode` / `wordRowWidthPx?: number | null` / `degradeEnabled?: boolean`，输出新增 `isDegraded`。
  - `layoutRows(items, ppms, durationMs, rowCount)`：`RowLayoutItem` 新增 `mode?` / `wordRowWidthPx?` / `degradeEnabled?`，`RowLayoutEntry` 新增必填 `isDegraded`。
- **修改接口**：
  - 无（R2a 只做增量，既有 line 口径不变）。
- **数据模型/类型变更**：
  - 新增 `BlockCardMode = 'line' | 'word'`、`DisplayChip { text, timeMs }`。
- **DOM 契约（供 harness 依赖）**：
  - 无（R2a 不接 UI）。

### 三、关键设计与做法

- word 内容宽 = `wordRowWidth + 12（把手）+ 4（间隔）`，再加 14 chrome；`minWidth = max(40, 12 + 4 + 22 + 14)`。
- chip 宽 = `max(measure(text, 'chip') + 8, 22)`，chip 间距 `CHIP_GAP_PX = 2`；探针样式为 `text-xs`。
- 降级判定：`mode === 'word' && degradeEnabled && cap < 52 && contentWidth > cap` → 宽度置 `14`、`isDegraded = true`。
- 两阶段排版保持：第一遍无 cap 定行号，第二遍按同行邻居压缩；降级只发生在第二遍。
- `deriveDisplayChips` 纯函数：按 `timeMs` 升序、`null` 排最后、严格相等才合并，不修改入参。

### 五、验收证据

- **tsc**：`npx tsc -b --noEmit` 退出码 0
- **vitest**：102 → **126/126**
- **harness**：维持 **444/444**
- **关键断言/实测**：word 宽 / 降级宽 / chip 合并顺序与最小宽均有单测覆盖。

### 六、已知取舍与未验证

- **取舍**：`WORD_CARD_DEGRADE_ENABLED` 默认 `false`，降级能力先具备、由后续轮次决定是否默认开启。
- **未验证**：真实浏览器字体下的 chip 累计宽与 Canvas 探针的偏差（仅单测注入测量函数）。

### 七、否决的备选方案

- 让 chip 行继续 `flexGrow` 按时间铺满：无法表达字级时间边界，否决。
- 在 UI 层临时测量：会破坏「测量单例 + 缓存」口径，否决。

## 轮次 2：R2b-1 · 放大态 UI 接线 + 拖动拦截 + 菱形降级

### 一、本轮范围

把 R2a 内核接到 `LyricTrack` / `LyricBlock`：`ppms >= 0.30` 且有字级的行切换为 word 卡片（左把手 + 字块），chip 区按下只选中不拖动，极窄块降级为菱形且整块即把手，辅助线锚定菱形中心。

### 二、核心接口与契约变更

- **新增接口**：
  - `calculateSnapAndOffset(rawPx, session)`（LyricTrack 内部）：出参 `{ offsetPx, snappedMs, anchorPx }`。用途：move 与 up 共用同一吸附口径，降级块统一加减 7px 菱心偏移。
- **修改接口**：
  - `showGuide(ms)` → `showGuide(ms, anchorPx = 0)`。修改原因：降级块辅助线需锚定菱形中心而非块左缘。
  - `LyricBlock` props：新增 `mode: BlockCardMode` / `chips: DisplayChip[]` / `isDegraded: boolean`。
- **数据模型/类型变更**：
  - `RowModel` 新增 `chips: DisplayChip[]`。
  - `LaidOutRow` 新增 `mode: BlockCardMode` / `isDegraded: boolean`。
  - `DragSession` 新增 `pressedIsDegraded: boolean`。
- **DOM 契约（供 harness 依赖）**：
  - word 模式新增 `[data-drag-handle]`（左侧 12px 把手）。
  - 降级块在根节点新增 `data-drag-handle=""`（整块即把手）。
  - line 模式 DOM、类名与尺寸完全不变。

### 三、关键设计与做法

- **模式判定**：`isExpanded = ppms >= WORD_CARD_PIXELS_PER_MS`；`wordMode = isExpanded && chips.length > 0`；测量时传 `wordTexts`，`RowLayoutItem` 填 `mode` / `wordRowWidthPx` / `degradeEnabled`。
- **拖动拦截**：pointerdown 时从 `laidOutRef` 读最新排版；word 模式下 `event.target.closest('[data-drag-handle]') === null` 即 chip 区，强制走 click 会话（保留 Ctrl/Shift 多选语义），仅把手可拖。
- **降级块**：14px 宽、整块即把手；内部只渲染 8px `rotate-45` 菱形（对角线 11.31px < 12px 内宽），不渲染信息行/正文/译文。
- **辅助线锚点**：菱形中心距块左缘 = 1（border）+ 6（padding）= 7px = `WORD_CARD_DEGRADED_WIDTH_PX / 2`。move 与 up 都走 `calculateSnapAndOffset`：`snapOffsetPx(raw + 7)`、`offset = snap.offsetPx - 7`；未命中时辅助线锚 `start + raw/ppms` 且 `anchor = 7`。
- **辅助线时机**：降级块 pointerdown 立即显示（`blocked` 模式除外），松手隐藏；非降级保持原「命中才显示」。
- **`laidOutRef`**：与 `rowsRef` 同为 render 期同步，避免为拖动状态机重绑事件。

### 四、改动文件清单

| 文件 | 改动内容 | 影响范围/关联模块 |
| :--- | :--- | :--- |
| `src/ui/timeline/LyricTrack.tsx` | imports / RowModel.chips / LaidOutRow.mode+isDegraded / rows 派生 chips / laidOut 派生 wordMode / laidOutRef / showGuide anchor / DragSession.pressedIsDegraded / calculateSnapAndOffset / pointerdown 拦截与显示 / pointermove / pointerup 复用 / 渲染透传 | 放大态渲染、拖动会话、辅助线 |
| `src/ui/timeline/LyricBlock.tsx` | props 三新增 / 根节点条件类与 `data-drag-handle` / 三分支内容渲染 / 降级菱形 | 卡片视觉与拖动命中区 |

### 五、验收证据

- **tsc**：`npx tsc -b --noEmit` 退出码 0
- **vitest**：通过数 **126/126**
- **harness**：**444/444，0 失败**；重点 `AZ` 9/9（`AZ.e` 在 `ppms=0.5` 仍可从 `left+10` 命中把手拖动）、`BA` 13/13（`ppms≈0.1537`，line 模式零回归）
- **关键断言/实测**：`git status --short` 恰 2 个业务文件；line 模式根节点 className 拼接结果与改动前字符串一致。

### 六、已知取舍与未验证

- **取舍**：降级态 move/up 两处都做 ±7px 的 `anchorPx` 偏移，保证菱心对齐目标时间。
- **取舍**：word 模式不渲染正文/信息行/译文，只保留把手与字块。
- **取舍**：降级态整块即把手（`data-drag-handle` 在根节点）。
- **取舍**：chip 区按下走 click 会话、不触发拖动，保留多选。
- **取舍**：辅助线在降级态 pointerdown 时立即出现，松手隐藏。
- **取舍**：8px 菱形旋转后对角线 11.31px，刚好塞进 12px 内宽。
- **取舍**：生产默认 `ppms = 0.02`，零视觉变化；仅在 `ppms >= 0.3` 时进入 word。
- **未验证**：降级块的真实构造（需极近相邻行）由用户人工目测；触屏长按与指针取消路径未专项复测。

### 七、否决的备选方案

- 在 chip 区按下也启动拖动：会与「点字块只选中」冲突，且破坏多选语义，否决。
- 降级块用伪元素/额外容器扩大命中盒：会增加 DOM 与层级复杂度，不如让根节点整块即把手，否决。
- 辅助线统一锚块左缘（不做 +7）：降级时辅助线会偏离菱形中心，视觉上误导吸附目标，否决。
- move 与 up 各写一份吸附算术：易漂移且难维护，改为抽 `calculateSnapAndOffset` 单一来源，否决复制粘贴方案。

## 轮次 4：R2b-1b + 1c（UI 重构与视觉微调）

> **用途**：记录字级卡片从「左侧 12px 把手 + 单行 chip」到「顶部把手 + 迷你卡（时间戳 + 歌词）」的视觉重构，以及 `anchorPx` / `forceClick` 的清理。
> **状态**：✅ 已闭合。
> **基线**：harness 444/444；core vitest 124/130（6 条预期红字）；tsc 退出码 0。
> **上游/依赖**：R2b-1a 几何内核（chrome=8、cap=40）已落地；本轮只接通 UI，不改底层公式。

### 一、本轮范围

接通放大态 UI 的最终视觉形态：顶部 `h-1` 把手 + 迷你卡（上排 `ss.xx` 时间戳、下排歌词），时间戳参与 chip 宽测量；删除降级块的 `anchorPx` 偏移与 word 模式 `forceClick` 拦截；1c 再对迷你卡做左上角对齐与 `ring-inset` 描边微调。

### 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `formatMiniTime(ms: number | null): string`：`null` 返回 `'--'`，否则返回 `ss.xx`（如 `12080 → '12.08'`）。用途：迷你卡上排时间戳。
- **修改接口**：
  - `LineMeasureInput`：新增可选 `wordTimeTexts?: readonly string[]`，与 `wordTexts` 按下标对应；缺项不计时间戳宽。
  - `calculateSnapAndOffset(rawPx, session)`：出参由 `{ offsetPx, snappedMs, anchorPx }` → `SnapResult`（`{ offsetPx, snappedMs }`）。修改原因：辅助线回归块左缘，删除降级半宽偏移。
  - `showGuide(snappedMs, anchorPx = 0)` → `showGuide(snappedMs)`。修改原因：同上。
- **数据模型/类型变更**：
  - `DragSession`：移除 `pressedIsDegraded`。
- **DOM 契约（供 harness 依赖）**：
  - word 模式的 `[data-drag-handle]` 由「左侧 12px 竖条」改为「顶部 `h-1` 绝对横条（`inset-x-0 top-0`）」。
  - word 模式 chip 结构由单行 `span` 改为迷你卡 `div`（上排时间戳 `span` + 下排歌词 `span`）。
  - 降级块仍为整块 `data-drag-handle`，DOM 不变；line 模式 DOM 不变。

### 三、关键设计与做法

- **测量**：chip 宽改为 `max(measure(text,'chip') + 8, measure(timeText,'badge') + 8, WORD_CHIP_MIN_WIDTH_PX)`；时间戳复用 `badge` 探针（`font-mono text-[9px]`），不新增 `TextStyleKey`。
- **顶部把手**：`absolute inset-x-0 top-0 z-[1] h-1 cursor-grab rounded-t bg-white/10`；内容容器加 `pt-1` 让出高度，块高仍锁死 52px。
- **左缘对齐**：根节点 word 模式改为 `pl-0 pr-1.5`，容器 `flex-row items-stretch`，使首张迷你卡与时间戳严格对齐。
- **迷你卡**：`flex min-w-0 flex-col items-start justify-center gap-0.5 overflow-hidden rounded-sm bg-white/5 px-1 ring-1 ring-inset ring-white/10 transition-colors hover:bg-white/10`；`minWidth: 22`、`flex: '0 1 auto'` 不变。
- **清理 `anchorPx`**：`pointerdown` / `pointermove` / `pointerup` 三处统一走块左缘口径；降级块按下即显示辅助线、松手隐藏的行为保留。
- **删除 `forceClick`**：word 模式任意位置按下均进入拖动会话，确保 harness `AZ.e`（固定取 `left+10, top+height/2`）仍可拖动；多选改由修饰键（Ctrl/Meta/Shift）触发。
- **1c 微调**：迷你卡改 `items-start` + `text-left`，时间戳 `text-neutral-500`、歌词 `text-neutral-200`，`gap-px → gap-0.5`，描边用 `ring-1 ring-inset` 而非 `border`。

> **用途**：记录字级卡片从「流式 chip 行」到「按字级时间绝对定位的微型时间轴」，以及拖拽、输入框单向联动、Toast 与视觉微调的完整落地过程。

### 一、本轮范围

把放大态字级卡片升级为「微型时间轴」：每个字卡按 `(timeMs − startMs) × ppms` 绝对定位，允许向左溢出、不做碰撞截断；接通字级拖拽；打通输入框的单向联动（只允许字拉行）与 Toast；最后统一视觉（迷你卡时间戳与歌词同色）。R3a / R3b 为纯内核与 UI 定位，R3c-1/2 为 store 联动与拖拽接线，R3c-3 为输入框联动、Toast、视觉微调与闭环归档。

### 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `layoutWordChips(widthsPx, timesMs, startMs, pixelsPerMs): WordChipBox[]`（`blockLayout.ts`）：把每个 chip 的宽度按时间戳映射为块内坐标。用途：微型时间轴的纯数学内核。
  - `WordChipBox { leftPx: number; widthPx: number }`：`leftPx` 可负（早于行起点、向左溢出）。
  - `nudgeWordsByOffset(lineId, wordIndices, deltaMs): void`（`editorStore`）：按位移平移若干字级时间戳，可撤销。用途：字级拖拽落盘 + 单向联动。
- **修改接口**：
  - `setWordTimestamps(lineId, values)`：返回 `void` → `number | null`。修改原因：首字早于行级时间时，store 在同一条记录内拉齐行级并返回新行时间，UI 无需重复推导联动条件（单一事实来源）。
  - `layoutBlock(input)`：`BlockLayoutInput` 新增 `wordChips?: readonly WordChipBox[] | null`；`BlockLayoutResult` 新增 `wordMinLeftPx` / `wordMaxRightPx`。
- **数据模型/类型变更**：
  - `LaidOutRow` 新增 `wordChips: WordChipBox[] | null`。
  - `DragMode` 新增 `'word'`。
  - `DragSession` 新增 `wordLineId?: string` / `wordIndices?: number[]` / `wordChipEl?: HTMLElement`。
- **DOM 契约（供 harness 依赖）**：
  - chip 新增 `data-word-chip`、`data-chip-indices`（逗号分隔的字下标）、`data-chip-time-ms`。
  - word 非降级根节点新增 `overflow-visible`、`px-0`；line 模式 DOM 不变。

### 三、关键设计与做法

- **废弃 Flex 的根本原因**：流式布局导致空间与时间脱节，拖拽松手会弹回，无法满足“所见即所得”的打轴直觉。
- **R3a 纯数学内核**：`leftPx = round((timeMs − startMs) × ppms)`，允许负值；无时间戳 chip 紧贴当前最大右缘 + `CHIP_GAP_PX`；不做任何碰撞截断，字与字允许重叠。
- **R3a 块宽口径**：word 绝对定位分支 `contentWidthPx = max(0, wordMaxRightPx) + 2 × border`，`minWidth = max(MIN_BLOCK_WIDTH_PX, WORD_CHIP_MIN_WIDTH_PX + wordPad)`；**不 cap 压缩、不降级**（允许越过下一行起点）。负向左溢不参与宽度计算。
- **R3b UI 绝对定位**：`LyricTrack.laidOut` 调 `layoutWordChips` 生成 `wordChipsByIndex`，随 `LaidOutRow` 透传到 `LyricBlock`；chip 改 `absolute` + inline `left` / `width`，容器改 `relative`。`overflow-visible` 让负偏移字卡可见。
- **尾部留白微调**：绝对定位改造后，`wordPad` 从 8 改为 2，UI 去掉 `pr-1.5`，消除最后一张字卡与右侧边框间多余的 7px 空隙。
- **R3c-1 单向联动**：普通平移落 `offset`，`lineIds: []`，行级与其余字级不动；首字越界前移（`targetFirstTime < currentLineTime`）改落 `absolute`，同一条记录写入行级、首字与**同批被拖的其它字**，修复「首字拉齐后其余被拖字留在原地」的多字撕裂。
- **行级绝对赋值的 `null` 契约（否决了先前设想的 -1）**：首字越界拉齐时，代表行级的 `wordIndex` 必须是 `null`，不能用 `-1`，否则底层回放会将数据写入脏键，导致行时间不生效。
- **R3c-2 UI 事件分派**：pointerdown 用 `closest('[data-word-chip]')` 建 `word` 会话并 `setPointerCapture`；超过阈值后 `zIndex=10`、`cursor=grabbing`、命令式 `translate3d(rawPx, 0, 0)`（拖动中零 store 写入）；松手 `deltaMs = Math.round(rawPx / snapshot.pixelsPerMs)` 调 `nudgeWordsByOffset`；未拖动视为点击选中。`clearSessionStyles` 统一清理 transform / zIndex / cursor，pointerup 与 pointercancel 共用。
- **R3c-3 输入框联动**：`LineEditForm.save()` 先 `applyLineTimeChange()` 落行级、再 `setWordTimestamps()` 落字级；后者发现首字早于当前行级时间时，把 `{ wordIndex: null }` 的行级值追加进**同一条** `absolute` 记录，返回新行时间。`save()` 依返回值弹 Toast「首字时间早于行级时间，行级时间已自动拉齐至 mm:ss.mmm」。拖拽路径（`nudgeWordsByOffset`）不经过此处，因此天然不弹 Toast。行级未打轴（`currentLineTime === null`）时不联动。
- **R3c-3 视觉微调**：迷你卡时间戳 `text-neutral-500` → `text-neutral-200`，与歌词同色。
- **R3c-2 的 AZ.e 实测未变红**：`left+10` 虽在视觉上靠近首字卡，但 demo 的 `global-offset +120ms` 只作用于行级（line0 行起点 12120、首字仍 12000）；`ppms=0.5` 时首字卡左缘在 `-60px`，`left+10` 仍落在空白 word 层，`closest('[data-word-chip]')` 为 `null`，继续走行级拖动。按红字原则未修改任何测试。
