## 一、本轮范围

新增歌词块宽度纯函数内核 `layoutBlock`，把「内容自然宽 + 到下一行间距压缩 + 保底宽」的算术从渲染层剥离出来，并用 vitest 锁死契约；本轮不接线任何 UI。

## 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `layoutBlock(input: BlockLayoutInput): BlockLayoutResult`：入参为已测量好的像素宽度与时间信息，出参为 `contentWidthPx / minWidthPx / widthPx / isCompressed / overlapsNext`。用途：决定单个歌词块的最终宽度。
  - `BLOCK_PADDING_X_PX = 12`：单侧内边距（CSS px），总内边距按 ×2 计入块宽。
  - `BLOCK_BORDER_PX = 2`：单侧边框（CSS px），总边框按 ×2 计入块宽。
- **修改接口**：无。
- **数据模型/类型变更**：
  - `BlockLayoutInput`：新增类型。字段 `bodyWidthPx` / `infoRowWidthPx` / `translationWidthPx` / `wordRowWidthPx` / `startMs` / `nextStartMs` / `pixelsPerMs`。
  - `BlockLayoutResult`：新增类型。字段 `contentWidthPx` / `minWidthPx` / `widthPx` / `isCompressed` / `overlapsNext`。
- **DOM 契约（供 harness 依赖）**：无变更（本轮零接线）。

## 三、关键设计与做法

- **宽度规则**：`pad = 12×2 + 2×2 = 28`；`contentWidthPx = max(body, info, translation ?? 0) + pad`；`minWidthPx = max(info + pad, MIN_BLOCK_WIDTH_PX)`。
- **无下一行**：`widthPx = max(contentWidthPx, minWidthPx)`，不压缩、不重叠。
- **有下一行**：`timeGapPx = (nextStartMs − startMs) × pixelsPerMs`，`cap = timeGapPx − BLOCK_GAP_PX`，`widthPx = max(minWidthPx, min(contentWidthPx, cap))`。
- **两个标记**：`isCompressed = widthPx < contentWidthPx`；`overlapsNext = widthPx > cap`（保底宽越过下一块起点，即真实重叠）。
- **边界**：`timeGapPx` 允许为负（同起点或乱序），此时必然退到 `minWidthPx` 且 `overlapsNext = true`。
- **位置不变式**：本模块只决定宽度，块左边缘仍由 `startMs × pixelsPerMs` 决定，绝不推挤。
- **测量输入化**：本轮所有宽度由调用方测好后传入；Canvas / DOM 字体测量留到子轮 2，保持纯函数可在 node 环境测试。

### 三、关键设计与做法

- **pad 修正**：Tailwind Preflight 全局 `border-box`，`width` 已包含 padding/border；真实左右装饰为 `(6 + 1) × 2 = 14`。旧常量按「总量 ×2」计算得 28，重复计了一次。
- **两层测量**：`computeLineWidths` 不含 DOM，node 可直接测；`measureLineWidths` 首次调用才创建离屏容器与 canvas，顶层无任何 DOM 访问。
- **字体探针**：五种样式各建一个 span（`text-xs` / `font-mono text-[10px]` / `font-mono text-[9px]` / `text-[10px]` / `text-[10px]`），读 `getComputedStyle` 拼 canvas `font`。
- **首帧校准**：固定样本 `时间码 00:00.000 Lyric`，`ratio = domWidth / canvasWidth`，clamp `[0.9, 1.1]`；偏差 > 2% 打警告但仍应用。
- **缓存**：key 为 `${style}\u0000${text}`，上限 4096，超限整体清空；缩放变化不失效。
- **字体加载**：`document.fonts.ready` 与 `loadingdone` 触发 `resetTextMeasureCache()`，下次调用重新校准。
- **node 边界**：`typeof document === 'undefined'` 时单例抛明确错误；纯函数不受影响。

### 二、核心接口与契约变更

- **新增接口**：
  - `LyricBlockProps.widthPx: number`：由轨道算好后传入块宽；块自身不再做任何宽度换算。
- **修改接口**：
  - `LyricBlock`：新增必填 prop `widthPx`；其余 props 不变。

- **数据模型/类型变更**：
  - 删除导出函数 `lyricBlockWidthPx(spanMs, pixelsPerMs)`。
  - 删除常量 `ROW_ASSIGN_GAP_PX = 8`。
- **DOM 契约（供 harness 依赖）**：无变更。块的 `data-lyric-block` / `data-line-id`、class、内部结构与渲染顺序均未改；仅 inline `width` 数值来源变化。

### 三、关键设计与做法

- **单向数据流**：`LyricTrack` 是唯一的宽度计算处；`LyricBlock` 只消费 `widthPx`，消除「轨道算一次、块再算一次」的双口径。
- **下一不同起点映射**：`ordered` 按 `startMs` 升序、同起点按文档序稳定排序；从尾部反向扫描，维护 `nextLarger`，遇到更小起点时写入映射并更新，复杂度 O(n)；同起点的所有行共享同一个 `nextStartMs`。
- **每行只算一次**：循环内 `measureLineWidths` → `layoutBlock`，`widthPx` 暂存到 `widthOf[index]`；`endPx = startPx + widthPx` 就地参与贪心，最终 map 复用暂存值，不再二次调用。
- **测量入参**：`timecode` 与块内展示同源（`row.times.length > 0 ? formatTimecode(row.times[0]) : '--:--.--'`）；`extraCount = max(0, times.length - 1)`；`hasWords` 看 `wordTimestamps.length > 0`；`hasTranslation` 用 `Boolean(line.translation)`，与译文真值一致，避免徽标与宽度错位。
- **避让语义**：`lastEndPx <= startPx` 即允许同排（贴边即可），块间隙已由 `layoutBlock` 在 `cap` 里扣掉 `BLOCK_GAP_PX`；两行都占用时仍选结束更早的行。
- **虚拟化**：条件保持 `endPx > windowStartPx && startPx < windowEndPx`，未加余量。
- **本轮不消费**：`isCompressed` / `overlapsNext` 不进入 props，不新增 overlaps 字段；压缩后的重叠视觉留子轮 3。

### 七、否决的备选方案

## 补充修正：视口跳动（暂停拖块松手补 playing 守卫）

> **状态**：✅ 已闭合。
> **基线**：harness 444/444（AP 组 5/5）；vitest 93/93；tsc 退出码 0。
> **上游/依赖**：子轮 2b / 2c 的宽度接线与「重叠视觉」补充修正闭合后，用户实测反馈：暂停状态下拖块松手，视口被强行按 20% 比例拉回播放头。A 段核实定位到 `LyricTrack.restoreFollowAfterDrag` 缺播放态守卫。

### 一、本轮范围

只修一个点：`restoreFollowAfterDrag` 增加播放状态守卫，使 A 模式（snap）在暂停时只清挂起、视口原地不动；不改行分配、宽度计算、`setDuration` 等其他逻辑。

### 二、核心接口与契约变更

- **新增接口**：无。
- **修改接口**：无（`restoreFollowAfterDrag(session: DragSession): void` 签名不变，仅分支语义变化）。
- **数据模型/类型变更**：无。
- **DOM 契约（供 harness 依赖）**：无变更。

### 三、关键设计与做法

- **根因**：原实现真拖动后无条件 `kernel.resumeFollow(settings.followResumeMode, adapters.audio.getCurrentTimeMs())`。默认 `followResumeMode === 'snap'`，暂停时 `getCurrentTimeMs()` 返回暂停位置；若播放头在视口 `x > 0.8W` 或屏外，`resumeFollow` 会 `applyView(timeMs - W × 0.2 / ppms)`（或 160ms 动画到同一目标），播放头精确落到 20% 处（`FOLLOW_TARGET_RATIO`）。
- **修法**：保留前两行（`!session.followSuspended` 早退、置 `followSuspended = false`）与 `!session.dragging` 分支（仅 `clearFollowSuspension()`），其后改为三分支：
  - `followResumeMode === 'pause'` → `resumeFollow('pause', audio.getCurrentTimeMs())`，维持 B 模式「进入跟随暂停」原语义，不移动视口；
  - 否则若 `playback.isPlaying` → `resumeFollow('snap', audio.getCurrentTimeMs())`，播放中行为不变；
  - 否则（snap + 暂停）→ `clearFollowSuspension()`，视口原地不动。
- **同口径对齐**：滚轮收敛（`TimelineStrip`）与滚动条松手（`Scrollbar`）本就是「仅 `snap && playing` 才拉回，否则只解除挂起」，本轮让拖块路径与之一致。
- **连带路径**：`stampLine`（未打轴块提交）、多选确认弹窗、`handlePointerCancel` 均复用同一函数，一并修复。
- **JSDoc 同步**：注明 A 模式仅播放中 snap 拉回、暂停只清挂起；B 模式保持原语义。
