# 字级空格打轴（文本流游标）· 交接文档

> **用途**：记录本轮的背景、做法、验收与边界。配合主交接文档阅读。
> **状态**：✅ 已闭合。
> **基线**：harness 546/546；core vitest 207/207；tsc -b --noEmit 退出码 0。
> **上游/依赖**：切割轮 R4a 的 `word-segments` 回放（提供 `wordTimestamps`）、R4b-1 的字级数据接线；行首拖动的「一条 absolute 批量落值、一步撤销」口径。

## 一、本轮范围

让空格键在「已切分行」上按**字**打轴、在「未切分行」上按**行**打轴，并用同一份文本流游标（`wordCursor`）驱动上下键按字跳转与字卡 / 行内字条蓝光。用户最终拍板：**不存在「缩小态」和「放大态」两套逻辑**，底层统一为文本流游标。

## 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `EditorState.wordCursor: { lineId: string; wordIndex: number } | null`：文本流游标，默认 `null`。`wordIndex` 是 `wordTimestamps` 数组下标（文本顺序），不是 chip 的视觉顺序。
  - `EditorState.setWordCursor(lineId: string | null, wordIndex?: number): void`：`lineId === null` 清空；`wordIndex` 非非负整数时退化为 0。
  - `EditorState.stampWordAt(lineId: string, wordIndex: number, timeMs: number): void`：落一条 `kind: 'word-timestamp'`、`mode: 'absolute'` 操作日志。
  - `stampAtCursor(adapters: AdapterContext): void`（`editorCommands.ts`）：空格分发入口，替换原先直接调用 `stampActiveLine`。
- **修改接口**：
  - `moveSelection(direction, options?)`：签名不变，内部新增「同一行内按字步进」；只有字走到本行边界才换行。`Ctrl+↑/↓` 的 `keepSelection` 路径同样生效。
- **数据模型 / Operation 契约**：
  - `stampWordAt` 的单条日志 `values` 至少含 `{ lineId, wordIndex, timeMs }`；当 `wordIndex === 0` 且该行行级时间为空时，同一 `values` 里追加 `{ lineId, wordIndex: null, timeMs }`，因此「行级 + 首字」是同一条 `absolute`，撤销一步回退。
  - 写入后游标自动 `+1`；到达本行末字后置 `null`，由命令层决定「换到下一可见行首字」还是「下一行整行打轴」。
  - `importDocument` 重建 selection 时同步把 `wordCursor` 置 `null`（换文档游标失效）。
- **组件 Props 契约**：
  - `LyricBlock` 新增 `cursorWordIndex: number | null`（`null` = 本行不是游标行）。
- **DOM 契约（供 harness 依赖）**：
  - 字卡（`word` 模式）新增 `data-word-cursor`（游标所在时存在）；行模式文字条 `span` 新增 `data-word-strip=""` 与 `data-word-cursor`。
  - harness 新增探针 `__lrc.wordCursor()`、`__lrc.chipRect(lineId, wordIndex)`（按 `data-chip-indices` 找覆盖该下标的字卡，返回视口坐标矩形）。

## 三、关键设计与做法

- **游标归属**：`wordCursor` 放在 `editorStore`，与 `selection` 平级；`activeLineId` 是「选中的行」，`wordCursor` 是「行内第几个字」。命令层移动游标时同步 `selectLine` / `setActiveLine`，保证视口跟随与选中态一致。
- **空格分派（`stampAtCursor`）**：
  - 选中行 `wordTimestamps.length === 0` → 原样走 `stampActiveLine`（行级 + 跳下一行）。
  - 有字级：游标为空或不属当前行 → 初始化为 `{ activeLineId, wordIndex: 0 }`；取 `resolvePlayheadMs(adapters)`；调 `stampWordAt`。
  - 打完本行末字（`stampWordAt` 把游标置 `null`）→ 找下一可见行：有字级则 `selectLine + setWordCursor(next, 0)`；无字级则只 `selectLine`（游标保持 `null`，下次空格按行打）。
- **上下键统一逻辑（`moveSelection`）**：只看「当前行是否有字级 + 游标是否属于当前行」，**完全不读 ppms / 卡片形态**。
  - 往下：游标不在本行末字 → `wordIndex + 1`；在末字 → 换下一行，有字级落首字，无字级清游标。
  - 往上：游标不在本行首字 → `wordIndex - 1`；在首字 → 换上一行，有字级落末字（`length - 1`），无字级清游标。
  - 无选中进入文档：落第一可见行，有字级落首字。
- **视觉联动**：
  - `LyricTrack` 订阅 `wordCursor`，按 `wordCursor.lineId === item.row.line.id` 计算 `cursorWordIndex` 传给 `LyricBlock`；不做放大 / 缩小条件渲染。
  - `LyricBlock` 的 chip 用 `chip.indices.includes(cursorWordIndex)` 判定（同时间合并卡会整卡高亮），样式 `bg-blue-500/20 ring-2 ring-blue-500`；行模式文字条按 `index === cursorWordIndex` 高亮，同一套蓝光。
- **鼠标联动**：
  - `pointerdown` 命中 `[data-word-chip]` 时按 `data-chip-indices` 取首下标 `setWordCursor(pressedLineId, chipIndices[0])`；未命中字卡（含缩小态整块 / 空白）一律 `setWordCursor(null)`。
  - 点轨道空白额外清游标。点击字卡仍沿用原「word 拖动」分支，未拖动时松手走 `selectLine`，游标不被覆盖。
- **一步撤销**：`stampWordAt` 把行级与首字并入同一条日志，`undoLastAction` 一次即同时回退两者（BI.a 实测）。
- **失败断言修正（测试口径，不改业务代码）**：
  - BI.a 原期望「撤销后首字回到 12000」有误：测试前置调用了 `clearLineTime(l0)`，该操作按契约会同时清空行级与全部字级，故撤销后正确状态是 `[null, null]` + `times []`。据此修正断言。
  - BI.d 原视口 `setView(11500, 2200)` 的右边界只到 13700ms，而第二字在 14000ms，字卡被裁到轨道外、点击坐标落空。按「视口必须完整含住 13000 / 14000 两字」改为 `setView(12800, 2600)`，仍为放大态（ppms ≥ 0.3）。

## 五、验收证据

- **tsc**：`npx tsc -b --noEmit` 退出码 0。
- **vitest**：207/207 通过。
- **harness**：546 断言 / 546 过 / 0 失败；其中 BI 组 23/23。
- **关键断言**：
  - BI.a：选中带字级行按空格 → 同一条 `word-timestamp` 同时写 `word 0` 与行级，游标变 1；一次撤销后行级与首字一起回退。
  - BI.b：再按空格 → `word 1`，本行打完后游标清空、选区顺延下一可见行。
  - BI.c：↑/↓ 在本行字间顺序步进，到边界后跨行落首字 / 末字。
  - BI.d：放大态点第二个字卡游标落到该字并高亮；切回缩小态同一游标仍在文字条上生效、上下键仍按字跳、空格仍按游标写字。
  - BI.e：未切分行按空格落 `manual-timestamp`，切分行落 `word-timestamp`。

## 六、已知取舍与未验证

- **取舍**：
  - 游标按文本流下标走，与「字卡按时间排序」的视觉顺序可能不同；点击同时间合并字卡只落到组内首字。
  - `stampAtCursor` 保留「无字级回退行级」的两条数据路径（由数据形态区分，不是缩放两套逻辑）。
  - 上下键的跨行判定只看游标是否在本行首 / 末字，不看可视位置。
- **未验证**：
  - 真机视觉目测（蓝光在深色轨道上的对比度、与选中态叠加的观感）。
  - 播放中连续按空格的听感 / 手感；触屏上点击字卡设游标。
  - 极窄缩放下行模式文字条被压缩 / 截断时游标字是否仍可辨认。

## 七、否决的备选方案

- **按 ppms 分两套逻辑（缩小态整行、放大态按字）**：用户明确否决；改为单一文本流游标，缩放只影响渲染形态。
- **`wordCursor` 存在本地组件 state**：热键层与两个渲染组件都要读它，且需在换行时被命令层改写；放 store 才能单源。
- **首字时间与行级时间分两条日志**：撤销要按两次、且中途可能行级有值而首字无值；改为同一条 `absolute` 批量落值。
- **点击字卡时另走一套 click 处理（绕过拖动状态机）**：会与既有的 word 拖动 / 阈值判定冲突；改为在 pointerdown 分派点顺带设游标，拖动路径完全复用。
- **为保绿改 `clearLineTime` 让字级不清空**：破坏既有契约（清行级连带清字级），且会让 BI.a 的「一步撤销」变成掩盖问题；改为修正测试期望。
