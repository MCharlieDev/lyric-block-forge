### 第零步核实结论（B 段前置）

1. **时间轴对未打轴行的占位**：`src/ui/components/timeline/LyricTrack.tsx:270-278`，写在组件 `useMemo` 内，**不是纯函数**；按 `untimedIndex * DEFAULT_BLOCK_MS`（2500ms）顺序累加，连续多行不会堆在 0ms。无现成可复用函数 → R4a 只在 `resolveCutAnchor` 接收调用方传入的 `placementStartMs`，占位算法不在 core 重算。

## 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `wordTimes.WORD_CUT_DEFAULT_GAP_MS`：常量 `200`（毫秒），切分初始字级时间的默认步长。
  - `wordTimes.charsFromText(text: string): string[]`：`Array.from` 按码点拆字，空格与标点保留为元素。
  - `wordTimes.cutsToSegments(text, chars, cuts: ReadonlySet<number>): WordSegment[]`：`cuts` 为 UTF-16 码元偏移，输出首尾相接、全覆盖、无 gap 的块。
  - `wordTimes.segmentsToCuts(segments): Set<number>`：反向取块起点（跳过第 0 块），与 `cutsToSegments` 互逆。
  - `wordTimes.deriveInitialWordTimes(anchorMs, count, stepMs = 200): number[]`：首块 = 锚点，后续逐块 +`stepMs`；`count <= 0` 返回空数组。
  - `wordTimes.resolveCutAnchor(lineTimeMs, firstWordTimeMs, placementStartMs): CutAnchor | null`：三层回退（行级 → 首字 → 占位），全空返回 `null`；`CutAnchor = { anchorMs: number; source: 'line' | 'word' | 'placement' }`。
  - `editorStore.commitWordSegments(lineId, segments, opts?: { placementStartMs?: number }): { ok: boolean; reason?: 'no-anchor' | 'line-not-found' }`：写一条 `word-segments` 日志；三层锚点全空时 no-op 不写日志。
- **修改接口**：
  - 无。`setWordTimestamps` / `clearLineTime` / `editLineText` / `setLineTime` / `stampLine` 的行为与签名均未改。
- **数据模型/类型变更**：
  - `OperationKind` 新增 `'word-segments'`。
  - 新增 `WordSegment`：`{ start: number; end: number; text: string }`（`start` / `end` 为 UTF-16 码元偏移，左闭右开）。
  - `OperationDelta` 新增 `{ mode: 'word-segments'; segments: WordSegment[]; times: number[]; lineTimeMs?: number }`。
  - `ReplayState` 新增 `wordSegments: Record<string, WordSegment[]>`（覆盖表，不来自基线）。
- **DOM 契约（供 harness 依赖）**：无新增/移除。R4a 零 UI 接线。

## 三、关键设计与做法

- **落盘只存结果，不存 cuts**：`segments` 自带 `range + text`，cuts 仅是 R4b 弹窗内部态；`segmentsToCuts` 供弹窗二次编辑时反推。
- **一条日志管三件事**：补行级（可选 `lineTimeMs`）+ 新切分（`segments`）+ 字级时间序列（`times`），撤销一次全退；不再拆成三条记录。
- **直接写绝对值**：`commitWordSegments` 不用 `setLineTime` 的 offset 平移路径，避免「补锚点」被当成整体位移、避免首字拉齐逻辑二次改写。
- **锚点三层回退**：行级 → 首字 → 调用方传入的时间轴占位起点；只有后两层才写 `lineTimeMs`，行级本来有值时不重写。
- **回放覆盖表整体替换**：`applyEntry` 的 `word-segments` 分支先 `clearLineWords` 再按下标写 `times`，防止块数变少时旧下标残留成幽灵时间；随后覆盖 `wordSegments[lineId]`，并 `delete` 该行在 `clearedWordLines` / `clearedLineLines` 的标记，避免新切分被旧「已清空」标记二次抹掉。
- **`deriveVisibleLines` 命中覆盖表**：整体替换该行 `wordTimestamps` 的 `range` / `text`，`timeMs` 取回放表同下标值，`precisionMs` / `source` 沿用旧下标值；覆盖分支放在 `clearedWordLines` 判断之前，保持「文本改动清空切分」语义。
- **覆盖表每次回放从空重建**：因为回放是全量重放，undo 后覆盖表自然消失，无需逆操作；也不写入 baseline。
- **切分粒度按 UTF-16 码点**：`charsFromText` 用 `Array.from`，emoji 占 2 个码元但只算一个字符；块边界只落在码点之间，`start` / `end` 按码元长度累加。
- **二次切割天然覆盖**：同一行再 commit 只是又一条 `word-segments`，回放顺序后者覆盖前者；撤销一次回到第一次结果，再撤销回到原始。

## 六、已知取舍与未验证

- **取舍（本轮零视觉变化）**：切割入口、弹窗、灰显、提示、设置项全部在 R4b，用户看不到任何新功能。
- **取舍（占位锚点不在 core 计算）**：本轮只接收调用方传入的 `placementStartMs`；占位算法在 `LyricTrack.tsx` 的 `useMemo` 内且非纯函数，R4b 需自行推导并与渲染共用同一函数。
- **取舍（内存）**：切分覆盖表常驻内存，规模 = 行数 × 段落数；本轮不做内存优化。
- **取舍（cuts 无多级）**：cuts 值退化为布尔，不支持 L1/L2；未来扩展只改 R4b 弹窗态，不影响本轮落盘格式。
- **取舍（撤销粒度）**：一条日志管三件事（补行级 / 切分 / 字级时间），撤销是整笔，用户无法只撤销其中一项。
- **取舍（无跨 entry 语义重映射）**：撤销切割后，若之后又按 index 改过字级时间，这些时间会落到恢复后旧切分的对应槽位；本轮不做重映射。
- **取舍（源头未治理）**：不修「行级空 + 字级有值」的产生源（`setWordTimestamps` 无行级校验）；本轮只保证切割入口能用三层锚点自愈。
- **取舍（导出无脏状态兜底）**：`clearedLineLines` 命中即丢字标签，挂账。
- **取舍（日志展示简版）**：新增 kind 只保证不显示「未知操作」；范围、块数等详细展示留后续。
- **未验证**：R4a 无 UI，全部交互（弹窗、灰显、提示）未接线、未目测；非纯函数的占位算法仍需 R4b 与渲染共用，本轮无法机器验证一致性。

## 七、否决的备选方案

- **否决「落盘存 cuts」**：cuts 只是弹窗内部态，存 cuts 需在回放时重算 range/text，且文本未来变动会与 cuts 失配；改存 `segments`（range + text）更稳。
- **否决「复用 `setLineTime` / `setWordTimestamps` 补锚点」**：前者走 offset 平移会二次位移，后者带首字拉齐与校验，均与「直接写绝对值」冲突；改为 action 内直接构造一条日志。
- **否决「覆盖表写入 baseline」**：baseline 只反映文档初始态，切分是日志产物；写 baseline 会让撤销无法恢复，且每次导入需额外重建。
- **否决「`deriveVisibleLines` 里按 `wordTimestamps` 原数组就地改 range」**：块数可能变少，就地改会残留旧块；必须按 `segments` 整体重建。

## R4a 交付契约补充

> R4b-1 接线时补记的两条硬约束，R4a 的接口与行为不变。

- **cuts 的坐标系是 UTF-16 码元偏移，不是字符下标**：`cutsToSegments` / `segmentsToCuts` 里的值都是 `WordSegment.start` 同系的码元偏移。UI 用 `Array.from(text)` 得到的是**码点**数组，emoji 等代理对占 2 个码元但只算一个字符；累加每个 `char.length` 得到码元偏移后再传入 `/ 取出`，不能直接拿 `chars` 的下标当 cuts。
- **`commitWordSegments` 不校验 `segments` 与当前文本是否一致**：action 只按传入的 `start` / `end` / `text` 原样落盘，不比对 `lineText`，也不校验块边界是否落在码点之间。调用方必须保证 `segments` 是对**保存后的文本**算出来的；文本一变，之前算好的草案必须作废，否则回放后会出现越界切片或错位文本。

### 三、关键设计与做法

- **Esc 分层**：外层 `LineActionSheet` 在 window **冒泡**阶段监听（`LineActionSheet.tsx:88-98`），同节点无法互阻；`WordCutDialog` 在 window **capture** 阶段拦截 + `stopPropagation()`，因此只关二级、一级保留。**故本轮未改 `LineActionSheet.tsx`**。
- **坐标换算**：`charsFromText` 给码点数组，逐字符累加 `char.length` 得每个字符的起始码元偏移，第 i 条缝的位置是 `charOffsets[i + 1]`；`segmentsToCuts` / `cutsToSegments` 两端都用码元偏移，emoji 代理对不会错位。
- **缝宽**：`(可用宽 − 标尺文字宽) / 缝数`，clamp `[8, 48]`；`可用宽` 由容器 `clientWidth` 减左右内边距得到，文字宽用同字体同字号的隐藏标尺量；`ResizeObserver` 跟随尺寸变化。到下限时文字行 `w-max` + 容器 `overflow-x-auto` 横向滚动，弹窗不撑破。
- **草案暂存**：二级弹窗「确定」只 `setCutDraft(segments)`，不写 store；正文 `onChange` 直接把草案置空（range 全部失效，本轮无语义提示）。
- **保存时序**（`LineEditForm.tsx:232-259`）：正文未变时先 `applyLineTimeChange()` 落行级，再 `commitWordSegments(line.id, cutDraft)`。原因：action 内部用「回放后的行级时间」当锚点，行级必须先落；草案非空时**跳过** `setWordTimestamps`，新切分整笔接管字级时间，旧槽位手改值没有意义，也避免旧下标污染新块。正文已变时草案已在 `onChange` 作废，不调 action。
- **只读预览**：草案非空时字级列表按 `cutDraft` 渲染（块数 = `segments.length`），时间用 `deriveInitialWordTimes(cutAnchorMs, cutDraft.length)` 预览（锚点为空显示空），整列表 `opacity-50` + 输入框 `disabled`，不显示旧槽位。
- **脏保护**：`dirty` 纳入 `cutDraft !== null`，Esc / 点遮罩不会静默丢弃草案。

### 三、关键设计与做法

- **两条路径的「不写入」手段不同**：非 IME 路径在 `onChange` 里不 `setDrafts`，靠 React 受控输入在事件结束后把 DOM 值回写成 `drafts.text`；IME 路径在组合期间必须放行（否则打断输入法），`compositionend` 再判定，取消时显式 `applyTextDrafts(composingStartTextRef.current)` 回滚。
