## 一、本轮范围

把元数据前缀识别器的硬编码前缀表提取为可导出的默认表，并允许调用方通过 `ParseOptions.metadataPrefix.rules` 整表替换；同时给每条规则增加 `action: 'meta' | 'line'`，支持「命中后保留为歌词行、绝不转元数据」。本轮只做内核，不接 UI、不碰序列化。

## 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `MetadataPrefixRule`：`{ prefix: string; tag: string; action?: 'meta' | 'line' }`。用途：描述一条前缀规则，`tag` 为写入 `applyMetaTag` 的标签名；`action` 缺省 `'meta'`。
  - `DEFAULT_METADATA_PREFIX_RULES: MetadataPrefixRule[]`：原硬编码 9 条默认前缀，`action` 全缺省。
  - `matchMetadataPrefix(line: string, rules: readonly MetadataPrefixRule[])`：返回 `{ tag, value, action } | null`，首个命中即返回。
- **修改接口**：
  - `ParseOptions.metadataPrefix`：原 `{ enabled?: boolean; keepLyricLine?: boolean }` → 现新增 `rules?: MetadataPrefixRule[]`。
  - `matchMetadataPrefix`：原签名为 `(line: string)` 且读模块内硬编码表 → 现签名为 `(line, rules)`，由调用方决定规则表。
- **数据模型/类型变更**：
  - `MetadataPrefixRule`：新增 `action?` 字段（`'meta' | 'line'`）。
- **DOM 契约（供 harness 依赖）**：
  - 无。本轮为纯 core 内核，不改 DOM、不改 `data-*`、不改 class。

## 三、关键设计与做法

1. **整表替换语义**：主循环用 `options.metadataPrefix?.rules ?? DEFAULT_METADATA_PREFIX_RULES` 取表。用 `??` 而非 `||`，保证显式传入空数组时不会回退默认表（空数组 = 全部不识别）。
2. **非法规则静默跳过**：新增 `isValidMetadataPrefixRule`，空 `prefix`、空 `tag`、`prefix` 含 `：: \t` 任一分隔符即判非法；循环内 `continue`，不抛错、不阻断后续规则。
3. **重复 prefix 先到先得**：`matchMetadataPrefix` 顺序遍历规则，命中第一条合法规则立即 `return`，后续同前缀规则不再参与。
4. **action 分流**：命中结果带 `action`；主循环只在 `matched.action === 'meta'` 时走原有「写 `metadataTags` + `applyMetaTag` + 可选 `keepLyricLine` 保留行」逻辑。`action === 'line'` 与未命中一样自然落到 `placeLine`，因此：
   - 绝不写元数据；
   - 不注入 `00:00.000`；
   - 全局 `keepLyricLine` 对它无效（保留为歌词行是最高优先级）。
5. **沿用既有触发窗口**：规则仍只在 `recognizeMetadataPrefix && withinPrefixWindow && !sawTimestamp` 时匹配，即前 10 条内容行、首条带时间戳行之前、总闸门与 `enabled` 均开启；窗口逻辑本轮未改。
6. **`rule.tag` 直传 `applyMetaTag`**：标准标签名进对应字段，非标准标签名继续走既有 default 分支 → `meta.custom[tag]` + `unknownTags`，前缀路径与 `[tag:value]` 路径共用同一份映射。

## 六、已知取舍与未验证

- **取舍**：

  - 本轮未将冲突（如同前缀多值）录入建议层。

- **未验证**：

## 七、否决的备选方案

- **把 `rules` 与默认表合并（增量语义）**：调用方只写差异、默认表兜底。否决原因：用户/决策 AI 明确要求「传入即完全替换」，合并会让「删除默认前缀」无法表达；后续 UI 需要完全控制权。
- **在 `matchMetadataPrefix` 内按 `action` 直接返回不同结构，或给 `action:'line'` 单独写一条保留分支**：否决原因：会让「保留为歌词行」重复 `placeLine` 逻辑，且容易误带 `keepLyricLine`；当前「不命中 meta 分支即自然落 `placeLine`」更少代码、语义更硬。
- **对非法规则抛错或整体拒绝解析**：否决原因：规则来自未来用户配置，单条脏数据不应让整次导入失败；静默跳过 + 首条合法命中优先更稳。

## 一、本轮范围

把可配置前缀表接入设置持久化，并新增独立的「前缀规则」编辑弹窗：用户在设置面板点击「配置前缀规则…」后，可在弹窗内即时增删改规则；规则表随设置写入 localStorage，刷新后保持。

## 二、核心接口与契约变更（极其重要）

- **新增接口**：
  - `MetadataPrefixDialog`：Props `{ rules: MetadataPrefixRule[]; onChange: (rules: MetadataPrefixRule[]) => void; closeOnBackdropClick: boolean; onClose: () => void }`。用途：前缀规则内联编辑弹窗；遮罩关闭由 `closeOnBackdropClick` 控制。

  - `ControlCtx.openPrefixDialog: () => void`（`SettingsMenu` 内部）：设置项控件打开弹窗的入口。
- **修改接口**：
  - `AppSettings`：新增 `metadataPrefixRules: MetadataPrefixRule[]` 字段；新增 `closeMetadataPrefixDialogOnBackdropClick: boolean`（默认 `false`，与 `closeDialogOnBackdropClick` 相互独立）。
  - `toMetadataPrefixOptions(settings)`：返回值新增 `rules: settings.metadataPrefixRules`（三个模式分支均透传）。
  - `SettingsMenu` 的 `metadataPrefixMode` 控件：外层 `<label>` → `<div>`，内部保留 `<label>` 包文字与 `<select>`；下方新增按钮。

  - `AppSettings` 新增 `metadataPrefixRules`（`MetadataPrefixRule[]`；空数组语义 = 不识别任何前缀，不回退默认表）与 `closeMetadataPrefixDialogOnBackdropClick`（`boolean`，非 boolean 回退默认 `false`）。

## 三、关键设计与做法

1. **即时保存、无草稿**：弹窗每次 `input` / `select` / 增删 / 恢复默认都直接 `onChange(nextRules)` → `settingsStore.update({ metadataPrefixRules })` → `App.tsx` 的变更即写 effect 落 localStorage。关闭弹窗不会提交任何额外变更。
2. **默认表 clone 三处**：`DEFAULT_SETTINGS.metadataPrefixRules`、`createDefaultSettings()`、`reset()` 都走 `cloneDefaultMetadataPrefixRules()`；弹窗内「恢复默认规则」也独立 clone。避免任何一处修改污染内核默认表或其他实例。
3. **白名单校验与内核同口径**：`normalizeMetadataPrefixRules` 对数组逐条校验——`prefix` / `tag` 必须为字符串且 trim 后非空；`tag` 必须匹配 `^[a-zA-Z]+$`；`prefix` trim 后不得含 `：: \t`；`action` 仅 `'line'` 保留，其余一律降级 `'meta'`。非法条目静默丢弃。非数组回退默认表 clone；**空数组保持 `[]`**。
4. **输入即过滤**：prefix 输入时过滤 `：: \t`（含空格），`onBlur` 再 trim；tag 输入时只保留 `[a-zA-Z]`。因此弹窗内很难产出必然非法的条目，红框只用于「用户清空」这类瞬时状态。
5. **行内反馈分级**：空前缀 / 空标签 → 红框 + `text-red-400` 错误文案；与上方规则重复 prefix → `text-amber-400` 警告，不阻断、不在 normalize 去重（与内核「先到先得」一致）。
6. **关闭与焦点**：遮罩点击仅在开关开启且 `event.target === event.currentTarget` 时关闭；Esc 走 `window` keydown 并 `stopPropagation()`，避免触发编辑器全局快捷键；打开时记录 `document.activeElement`，初始焦点给首条规则 prefix 输入（空表给「+ 添加规则」），卸载时还原。
7. **Focus trap**：弹窗根 `onKeyDown` 捕获 `Tab`，查询 `button / input / select / [tabindex]` 中可见元素，Shift+Tab 在首元素回环到末尾、Tab 在末元素回环到开头；焦点意外落在弹窗外时也拉回。
8. **遮罩关闭独立开关**：本弹窗读取 `closeMetadataPrefixDialogOnBackdropClick`（默认 `false`），不复用 `closeDialogOnBackdropClick`，两者互不影响；开关与行操作弹窗开关并列在「界面」段同一设置项内，因此不改变 harness 依赖的设置项 ID 集合。Esc 关闭始终可用。

## 二、核心接口与契约变更（极其重要）

- **修改接口**：
  - `MetadataPrefixRule.action`：原类型 `'meta' | 'line' | undefined` → 现类型 `'off' | 'meta' | 'meta+line' | undefined`（缺省仍按 `'meta'` 处理）。修改原因：`'line'` 与「不命中规则」在结果上等价，三态后语义更清晰且与设置项对齐。
- **数据模型/类型变更**：
  - `MetadataPrefixRule`：`action` 字段的可选值集合变更，无新增字段。
- **DOM 契约（供 harness 依赖）**：
  - `MetadataPrefixDialog` 内动作下拉框仍为原生 `<select>`，`aria-label` 不变；option 由 2 个变为 3 个，值为 `off` / `meta` / `meta+line`。未新增 `data-*`，设置项集合仍为 15 项。

## 三、关键设计与做法

- `matchMetadataPrefix` 在命中时归一 action：仅 `'off'` 与 `'meta+line'` 原样透传，其余（含缺省与非法值）一律按 `'meta'`。
- 主循环分流：
  - `off`：不进入元数据分支，直接落到统一 `placeLine`，原文与行角色沿用普通歌词行逻辑。
  - `meta`：写元数据标签（`metadataTags` 占源顺序位），再按全局 `keepLyricLine` 决定是否额外 `placeLine` 一条 `00:00.000` 的保留行。
  - `meta+line`：写元数据标签，并强制 `placeLine` 保留行；条件写作 `matched.action === 'meta+line' || keepLyricLine`，因此两者同开也只保留一条，不重复。
- `settingsStore.normalizeMetadataPrefixRules` 白名单同步收紧：只接受三态，`'line'` 等旧值/脏值降级为 `'meta'`，避免持久化层把已废弃值继续写回。
- 弹窗动作下拉直接映射三 option；`handleAdd` 新建规则仍默认 `action: 'meta'`。

## 五、验收证据

- **tsc**：`npx tsc -b --noEmit` 退出码 0。
- **vitest**：`npx vitest run` 通过 74/74（3 个文件）。
- **harness**：`npm run harness` 断言总数 444，通过 444，失败 0。
- **关键断言/实测**：
  - `off`：`meta.lyricist` 为 `undefined`，`lines` 含原文行且无时间戳，导出逐字节等于源文本。
  - `meta+line`：`meta.lyricist === '张三'`，`lines` 含原文行且时间戳为 `00:00.000`，导出为 `[lyricist:张三]\n[00:00.000]作词：张三\n[00:01.00]x\n`。
  - 三态与全局 `keepLyricLine` 同开：保留行数量为 1，不重复。

## 六、已知取舍与未验证

- **取舍**：彻底移除 `'line'`，不做兼容别名；旧持久化数据中的 `'line'` 会被清洗为 `'meta'`（用户需在弹窗中重新选择「关闭规则」）。这是有意为之，避免两套等价语义长期并存。
- **未验证**：未做真实浏览器人工目测；harness 仅覆盖设置读盘与既有交互，三 option 的视觉排布与长文案截断未截图验证。

## 七、否决的备选方案

- **保留 `'line'` 作为 `'off'` 的别名**：可兼容旧持久化数据，但会让三态下拉与内核类型继续存在第四种输入，违背本轮「去掉冗余、逻辑清晰」的目标，故否决。
- **在 `matchMetadataPrefix` 外层做 action 归一**：会让归一逻辑分散到主循环与设置层，容易出现两处口径不一致；统一放在匹配返回处更收敛。
