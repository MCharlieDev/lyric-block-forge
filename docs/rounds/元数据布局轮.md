## 压缩监控（操作规则）

**阈值**：约 70%（已用）。达到即自动压缩。

**手动压缩与自动压缩无机制差异**——压的是同一个上下文、丢的是同一批残影，
区别只在"谁按的按钮"。因此：

- "手动压缩"**不改变损失量**，只能把压缩提前，不能让压缩变便宜。
- 文档里不再区分手动/自动，统称"压缩"。

**真正的成本驱动是"轮次类型"，不是"压缩时机"**：

| 轮次类型                  | 单轮攀升          |
| :-------------------- | :------------ |
| 普通轮（改代码 + 交付）         | \~17–22 点     |
| **核实轮**（读多文件 + 产核实报告） | **\~40–50 点** |

> 数据来源：元数据布局轮闭合后，紧随的核实轮把上下文从 5% 拉到 51%（+46 点）。

**结论**：控制成本要控的是「这轮读多少代码」，不是「什么时候压缩」。
压缩早压晚压都一样。

**操作**（按顺序）：

1. 一轮闭合、AI 判过
2. **文档补丁贴进 Trae**（唯一持久真相）
3. 确认它收到
4. 压缩（手动或自动皆可）

**铁律**：**任何压缩之前，文档必须已落到外部。**
压缩有损，只有文档能穿越。
（此条不绑定"手动压缩"——手动/自动都适用。）

**信号判据**（不变）：

- 行为信号（可靠）：压后重复劳动 / 问已答过的问题 → **换对话**
- 数字信号（辅助）：连续几次压后值趋势性抬升 → 残影累积 → **换对话**

**压缩 ≠ 换对话**：压缩省短期成本，换对话清累计残渣，不可互替。
